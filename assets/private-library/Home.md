# 私人知识库

这里保存只属于当前用户、会跨任务继续使用的知识、来源、项目和成果。它与 100x-learning 的可发布 Skill 源码分开；任何能够读取本地文件的 Agent 都可以按本页约定使用，不依赖某个客户端的专属目录。

## 目录边界

| 目录 | 放什么 |
| --- | --- |
| `00-Inbox` | 暂时无法判断归属、仍待复核的材料 |
| `10-Knowledge` | 已经消化、可以反复使用的概念、结论、机制和方法 |
| `20-Sources` | 外部文章、书籍、课程、字幕、访谈、原帖和其它原始材料 |
| `30-Projects` | 有明确目标、交付物和结束条件的进行中工作 |
| `40-Outputs` | 已经确认完成的研究、实践和其它成果 |
| `50-Areas` | 没有固定结束日期、需要长期维护的领域 |
| `60-Systems` | 可重复使用的流程、模板和工作规则 |
| `90-Archive` | 已结束或停用但仍需保留的内容 |

原始材料进入 `20-Sources`，从材料形成的稳定认识进入 `10-Knowledge`。知识文档链接来源，项目与成果链接它们实际使用的知识和材料。

## 面向人和 Agent 的知识文档约定

新建或实质更新 `10-Knowledge` 中的主题文档时使用：

```yaml
---
type: knowledge-note
status: active
created: YYYY-MM-DD
updated: YYYY-MM-DD
topic: 稳定且唯一的主题标识
aliases:
  - 真实存在的别名、缩写或英文术语
---
```

文件名和唯一的一级标题直接说明主题。标题后先说明文档回答什么问题、当前结论和适用范围，再保存机制、证据关系、限制、冲突和开放问题。重要来源链接放在它支持、限制或反驳的主张附近。

写入前先搜索主题、别名和来源。处理同一个问题时更新现有文档；新材料只是证据、案例或限制时合并到对应位置；只有能够独立回答另一个长期问题时才新建主题。

## 写入与归档

普通理解、研究和实践结果只在当前回复中交付。用户明确要求保存、沉淀或更新时才写入。写入后重新读取实际文件，告诉用户更新了哪些真源。

旧知识库中可能保留写作案例、钩子、写作输出或写作系统。它们是用户既有资料，不属于 100x-learning 当前活动结构；本 Skill 不删除、移动、初始化或验证这些目录。

活动内容有新结论时更新原文件。已经停用的内容移入 `90-Archive`；归档不是删除，也不在活动目录保留兼容副本。
