# 完整内容案例库

用于在写作前查找真实完整成品，也用于用户明确要求时保存或更新案例。它不管理钩子；钩子由独立的钩子库、脚本和索引维护。

## 案例的正式原文

完整案例保存一条真实成品从第一句到最后一句的原文和必要定位字段，不附加来源。完整短内容位于 `<私人知识库>/20-Sources/Social Posts/Content Cases/完整短内容/`，活动文章案例位于 `<私人知识库>/20-Sources/Articles/Content Cases/`。正式文章要作为案例时复制一份到文章案例目录：正式文章保留自己的发布入口，案例副本不保存来源，两者不能共用同一文件。两类案例共享索引，但按当前内容形式读取：短内容只查完整短内容，文章与 Newsletter 才查文章案例；用户明确要求跨形式参考时除外。

```text
<私人知识库>/20-Sources/Content Cases/内容案例索引.md
```

完整案例的隐藏索引只保留查找原文和区分使用条件所需的字段，例如写作任务、主题、推进动作、内容形式、宣发角色、利益领取者，以及能否作为用户写作风格样本。案例不得保存钩子 id、钩子分析、读者效果或钩子来源引用。

两类索引回答不同问题：内容案例先按完整成品承担的写作任务定位，钩子先按开头手法定位。不能把案例主题复制成钩子分类，也不能用钩子手法重组完整案例库。

## 查找与读取

先浏览案例索引，再只搜索当前成品对应的目录。短内容使用：

```powershell
rg -n -i "当前任务或对象" "<私人知识库>/20-Sources/Social Posts/Content Cases/完整短内容"
```

文章或 Newsletter 使用：

```powershell
rg -n -i "当前任务或对象" "<私人知识库>/20-Sources/Articles/Content Cases"
```

索引只负责定位。网络搜索得到的新闻、评测、博客和其它文章是当前对象的外部材料，不因此成为文章案例，也不改变短内容的案例目录。先按当前内容形式确定目录，再把本次公开动作归到介绍机会、介绍对象、解释机制、分享经历、给出教程、比较选择、表达观点、整理清单或讲述事件中的实际一种。案例的 `index_task` 先与这个公开动作对应，随后再比较信息关系、读者处境和推进方式，题材放在最后用于缩小范围。同题材但写作任务不同的原文不进入本次成文上下文；当前题材没有合适案例时，跨题材寻找公开动作和推进关系一致的原文。

正面介绍、推荐和活动发布先浏览“项目与产品介绍”以及其它由利益、参与动作和结果推进的案例；当前成品本身是分析或判断时，才使用“行业与投资分析”。介绍机会、福利或新变化时，选择能让主要利益出现、让参与动作推进并落到结果的案例；解释机制、分享经历或比较选择时，使用与相应传播任务一致的案例。打开多份准备阅读全文并用于本次写作的完整案例；同类候选的宣传语气、抽象程度或结尾方式趋同时，继续跨题材寻找由具体动作、结果或真实问题推动的案例。

入库只说明这是一份可读的完整原文，不表示其中每一种语气、修辞和收束都适合当前成品。阅读全文时分别判断它怎样选择事实、组织关系和继续推进，以及哪些表面习惯只属于原文；即使原文的语气夸张或结构生硬，其中真实有用的动作关系仍可参与写作。组合多份案例时让它们提供不同的内容推进和表达距离，不选择唯一模仿对象，不按案例拼装模板，不把共同句式当成当前成品的模板，也不让多份原文共享的定义、夸张、分析姿态或统一升华获得额外权重。进入成文前逐份确认它会改变哪一个信息选择或推进关系；没有带来具体改变的候选退出本次参考。最终“本次创作参考”只列仍实际参与成文的案例。

索引不存在、校验失败、对应目录为空，或浏览索引并搜索正文后仍没有返回可读原文时，把准确状态交回主流程并停止成文，直接说明用户需要修复或补充的私人库状态。本文件不授权写作者跳过案例输入继续成文。

完整案例还可以让写作者看见当前内容是否缺少必要场景、证据或上下文；这个缺口确实影响本篇成立时，返回当前对象的来源补材料。当前作品的事实、人物、身份、经历和结果仍由对象材料与用户要求提供。主流程可以同时提供独立钩子库中的原文，两类资源共同参与写作，但彼此不引用、不转换身份。

写作按当前成品的任务、对象、读者和可迁移的推进方式查看相关案例。当前内容含福利、时限或行动入口时，可以用 `index_roles` 和 `benefit_recipients` 帮助找到机制相近的案例，但不能因此排除普通案例，也不能把这些索引字段交给写作者。案例中的利益、身份、时间和行动入口不能改写当前任务材料已经确定的事实。

## 创建和更新

只有用户明确要求保存或更新案例时才写入。保存时保留未经改写的全文，不附加来源；完整短内容使用 `short`，文章使用 `article`。文章输入来自正式文章时仍创建独立案例副本，不在正式文章上附加案例元数据：

```powershell
python scripts/content_case_library.py add-case --kind short --input "完整原文.md" --title "案例标题" --content-type "项目与产品介绍" --index-task "介绍项目" --topic "主题" --move "输入变成结果"
python scripts/content_case_library.py build-index
python scripts/content_case_library.py validate
```

新建宣发案例时通过 `--index-role`、`--promotion-stage`、`--audience-action` 和 `--benefit-recipient` 写入同一资源；案例需要进入写作记忆时，通过 `--writing-format`、`--writing-origin` 和 `--voice-eligible` 明确其写作用途，不根据账号或链接推断。更新已有资源时直接修改唯一案例文件并重建索引。

## 通过标准

- 案例脚本、目录、数据类型和索引只认识完整短内容与完整文章。
- 完整案例只显示原文，隐藏索引不规定唯一学法，也不保存来源。
- 案例文件不存在钩子字段，也不能通过案例路径生成钩子。
- 写作可以同时读取多个完整案例与多个独立钩子，但管理和索引边界保持分开。
