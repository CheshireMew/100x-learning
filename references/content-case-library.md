# 内容案例库

用于在写作前查找真实成品与开头技巧，也用于用户明确要求时维护案例。索引只负责找到参考；真正参与写作的是原文。

## 两种资源，两个管理边界

### 完整内容案例

完整案例保留一条真实成品从第一句到最后一句的全文。它让写作者直接感受进入方式、句子节奏、段落推进、具体动作、情绪变化和收束。题材、类型和标签只帮助定位，不限定这篇案例只能教哪一种写法。

完整社交案例的可见部分是：

```markdown
# 案例标题

## 原帖全文

完整原文

原帖链接：可核对来源
```

末尾隐藏索引只保留来源状态与定位所需的最少信息，例如 `index_task`、`index_topics`、`index_moves`、`writing_format`、`index_roles`、宣发阶段与利益领取者，以及声音资格。完整案例不保存钩子字段，也不保存“这篇只能怎样借鉴”的结论。

### 钩子技巧

钩子技巧只位于 `钩子与开头`，以独立 `HookPattern` 保存。它是一种可迁移的开头动作，例如直接展示结果、从一次接触动作进入、用具体问题拉近距离，或先让读者看见前后变化。每项技巧保留：

- 稳定的 `hook_pattern_id`；
- 一到数项 `hook_techniques`；
- 希望带来的 `reader_effects`；
- 来源示例的开头和紧接内容，或通过 `source_case_file` 引用完整案例。

钩子不是内容案例的别名。钩子只存在于 `钩子与开头` 中，并以 `HookPattern` 管理；完整短内容与文章只能成为来源示例，不能直接混入钩子资源。

来源示例用了“我刷到”“我试了”“我把东西丢进去”等第一人称时，不因此淘汰技巧。写作者可以借鉴接触动作、假设场景和节奏，再按当前作者与材料自然改写，不在起草前证明叙事动作逐字发生过；具体亲历、测试结果或感受最终承担可信度时，再由成稿核查处理。

## 管理上分开，写作时合在一起

完整案例与钩子技巧分开存放、分别定位，是为了保证资源边界清楚。找到参考后，把多个相关完整案例的全文、多个钩子来源的开头与紧接内容，以及上层已经净化的可写材料一起放入写作上下文。模型可以同时学习几篇的不同长处，也可以从多个参考中形成一个新的讲法。

不要求只选择一个案例或一个钩子，不要求逐篇声明“采用/未采用”，也不要求证明某个句子来自哪份参考。参考数量不预先固定；写作说明可以自然说明哪些原文共同影响了方向，但这不是成品的通过条件。

## 怎样找到参考

先浏览 `<私人知识库>/20-Sources/Content Cases/内容案例索引.md`，从成品形态和内容类型中看有哪些真实原文。需要缩小范围时，用普通文本搜索直接查标题、正文和隐藏索引；完整内容与钩子分别在自己的目录里找。例如：

```powershell
rg -n -i "项目|结果|痛点" "<私人知识库>/20-Sources/Social Posts/Content Cases/完整短内容"
rg -n -i "结果|痛点|问题|反常识" "<私人知识库>/20-Sources/Social Posts/Content Cases/钩子与开头"
```

搜索只负责定位文件，不给创作价值打分，也不替模型决定哪些参考有资格进入上下文。打开原文后，由模型结合当前任务判断相关性、差异和可借鉴之处。参考太相似或明显不合适时继续找；已经出现几种足以启发成文的方向时停止。没有找到更合适的案例，也可以依靠当前可写材料、外部语境和作者判断继续写，不为凑数量强行加入无关材料。

普通写作可以跨题材学习写法。内容型宣发只查看 `index_roles` 包含 `promotion` 的案例；存在具体利益时，再确认 `benefit_recipients` 是 `reader`、`publisher` 还是 `partner`，防止把发布者返佣写成读者优惠。同形态宣发案例不足时，可以在相同宣发角色和领取者条件下查看文章案例；案例不能改写用户已经确定的利益领取者和行动入口。

## 怎样把参考放进上下文

不要先把每篇案例压缩成一句标签。把全文放在当前材料旁边，让模型直接观察：

- 开头为什么会让人停下来；
- 下一句怎样兑现，而不是另起话题；
- 事实和项目说明在什么时机出现；
- 长短句、换行、列点和留白怎样形成节奏；
- 哪些具体动作、数字或名词让内容变得有力；
- 结尾为什么停在这里。

多篇案例可以共同影响同一个位置，也可以分别影响开头、推进或收束。不要把它们拼成新的固定模板；让当前材料和作者声音决定最终形状。只有用户明确要求仿写或续写某篇时，才近距离对应句段职责。

钩子同样以来源示例进入上下文。模型结合几种入口动作自由试写，不需要先完成“必须关系映射”。钩子可以提供假设场景、接触动作、轻微泛化和表达力度；精确数字、核心能力和明确承诺如果进入成稿，再由统一成稿核查处理。

## 创建和更新

用户明确要求保存或更新案例时：

1. 先判断它是完整内容还是独立钩子技巧。
2. 完整短内容进入 `完整短内容`，文章进入文章案例；保留未经改写的全文和可核对来源。
3. 钩子技巧进入 `钩子与开头`，保存 `hook_pattern_id`、技巧、读者反应和来源示例。
4. 来源示例来自现有完整案例时，用 `source_case_file` 引用，不复制第二份全文。
5. 经过本人账号验证的社交内容按实际情况记录 `writing_format`、`writing_origin` 和 `voice_eligible`；发布过不等于能够代表作者声音。
6. 新建完整案例时，模型先判断内容类型、任务、主题和可检索写法，再把完整原文保存到临时 UTF-8 文件并运行 `python scripts/content_case_library.py add-case ...`；新建钩子时运行 `add-hook` 并引用已经存在的完整案例。脚本负责确定路径、写出资源和更新索引，模型继续负责内容判断。
7. 直接更新现有真源后运行 `python scripts/content_case_library.py build-index` 和 `python scripts/content_case_library.py validate`。

```powershell
python scripts/content_case_library.py add-case --kind short --input "完整原文.md" --title "案例标题" --content-type "项目与产品介绍" --source "来源链接或本地来源" --index-task "介绍项目" --topic "主题" --move "输入变成结果"
python scripts/content_case_library.py add-hook --title "钩子标题" --pattern-id "stable-pattern-id" --content-type "结果钩子" --source-case "20-Sources/Social Posts/Content Cases/完整短内容/项目与产品介绍/案例标题.md" --index-task "从结果进入" --topic "主题" --move "结果前置" --technique "直接展示可见结果" --reader-effect "迅速理解变化"
```

重复的 `--topic`、`--move`、`--technique` 和 `--reader-effect` 可以表达多个真实维度。新建宣发案例时通过 `--index-role`、`--promotion-stage`、`--audience-action` 和 `--benefit-recipient` 写入同一资源；新建本人发布案例时通过 `--writing-format`、`--writing-origin` 和 `--voice-eligible` 明确声音资格。更新已有资源时直接修改唯一案例文件并重建索引，不为方便命令行创建第二份正文。

## 通过标准

- 完整案例与钩子技巧位于各自目录，钩子用独立 `hook_pattern_id`、技巧、读者反应和来源示例表示。
- 完整案例先显示全文和来源，索引没有替原文规定唯一学法。
- 钩子目录没有混入完整内容，来源示例的尾部 CTA 不会污染开头材料。
- 实际写作打开了多份有差异的相关原文；没有固定数量和单一参考限制，确实无合适参考时也不会强行凑数。
- 案例与钩子没有替换当前对象的核心能力和明确承诺；表达性改写由成稿核查按实际影响处理。
