# 内容案例库

用于在实际写作前查找并学习真实成品，也用于用户明确要求时维护案例。案例的原文是主要写作输入；索引只负责把原文找出来，不能替作者总结这篇案例唯一值得学什么，更不能规定它只能用于哪个题材。

## 一、案例承担两种角色

### 完整内容案例

完整案例展示一条真实成品从第一句到最后一句怎样成立。写作技巧可以跨题材迁移，目录、成品类型、任务和主题只是检索线索。项目介绍可以学习故事的悬念推进，教程可以学习观点文的句子节奏，投资内容也可以学习产品帖怎样快速兑现结果。

选中完整案例后阅读全文，至少观察：

- 每句话具体用了什么说法，为什么不是另一种说法；
- 每句和每段承担什么职责，上一句怎样把读者带到下一句；
- 长短句、换行、列表、标点和留白怎样形成节奏；
- 具体名词、动作、数字、反差、强调和省略怎样增加力度；
- 情绪从哪里出现、怎样加强、在哪里得到兑现；
- 结尾为什么停在这里，以及它与开头怎样呼应。

这些观察来自本次阅读全文，不提前压缩成案例文件中的一句标准答案。

### 开头案例

开头案例只保存足以展示入口技巧的真实原文，但同样先读原句，再判断它怎样调动感受、制造信息缺口并把读者送入正文。技巧类别、读者感受和所需材料只帮助检索；原案例的题材、人物、产品和行业不限制它可以迁移到哪里。

## 二、案例文件先呈现原文

社交内容案例的可见部分固定为：

```markdown
# 案例标题

## 原帖全文

完整原文

原帖链接：可核对来源
```

机器检索信息放在文件末尾的隐藏注释中：

```markdown
<!-- content-case-index
index_task: 这篇原文可能帮助查找的写作任务
index_topics: [只用于检索的主题词]
index_moves: [只用于检索的内容动作]
-->
```

文章保留自身发布所需的 frontmatter，案例专用索引同样放到正文末尾的 `content-case-index`。案例文件不保存预先写好的借用结论和狭窄使用范围；这两类说明会抢走原文的解释权，使写作者只模仿整理者看见的一层。

索引字段全部是召回线索：

- `index_task` 帮助找到可能相关的写作任务；
- `index_topics` 帮助按对象和题材浏览；
- `index_moves` 帮助按内容动作和推进关系查找；
- `hook_family`、`hook_techniques`、`reader_effects` 和 `required_material` 帮助查找开头。

字段没有列出的表达技巧仍然可以从原文中学习。字段匹配不上当前题材，也不代表原文的写法不能迁移。

## 三、一个来源可以承担多个角色

完整案例的开头本身值得单独检索时，在同一份隐藏索引中补充完整的开头字段，让同一原文同时进入完整案例和开头检索。原文和来源只保存一份，不为角色或题材复制正文。

调查信息分别报告实际使用结果：

- 作为完整案例时，说明真正沿用了哪些句段职责、表达技巧、节奏、格式、情绪推进和收束；
- 作为开头参考时，说明第一句采用了什么入口技巧，以及希望带动什么感受。

报告来自最终成稿与原文的真实对应，不照抄索引字段。

## 四、检索只负责找候选

### 完整案例

查询包含本次要实现的读者变化、内容关系和希望采用的表达特征。成品类型可以提高同类案例的排序，但不能排除其它类型；主题词可以提高相关案例的召回，但不能成为写作边界。

例如：

```text
让不懂技术的人迅速感到项目的变化；用短句直接推进，随后用紧凑的并列内容增加力度
```

### 开头案例

先从当前材料确定：

```text
第一句希望带动什么感受：
准备使用什么入口技巧：
当前材料具备什么事实关系：
开头之后需要兑现什么：
```

开头检索比较技巧、感受、所需材料和推进动作，不使用题材词决定结果。相同技巧换一个行业仍应找到承担相同作用的案例；相同题材需要另一种技巧时，结果应随技巧变化。

检索结果必须先显示原文全文，最后才显示本地路径和匹配角色。写作阶段不显示主题、内容类型、结构标签或人工摘要，避免索引字段变成写作上限。

## 五、怎样从完整案例写出新内容

选定案例后，先在当前任务中建立逐句对应：

```text
案例这一句怎样说、承担什么作用
→ 本次材料中什么真实内容承担同一作用
→ 哪些句式、节奏、格式和情绪动作可以直接沿用
```

默认尽量保留整套有效写法，包括段落顺序、句段职责、信息密度、长短节奏、列表作用和收束位置。先区分案例为什么有效，以及它在这一次恰好用了几个段落、几项内容和哪些数字。推进关系、表达作用与节奏优先迁移；条目数、段落数和具体数值由当前材料自然产生。只有以下情况才改变对应部分：

- 案例依赖的事实关系在当前材料中不存在；
- 照搬会产生错误事实、身份、经历、立场或精确引语；
- 用户明确要求的格式、声音或固定文字与案例冲突；
- 某个表达只属于原作者的独特身份或不可移植语境。

案例使用并列内容加强前文时，学习的是“在这里用紧凑的并列内容增加力度”。当前材料只有一项真正有力的内容就写一项，有三项同样重要就写三项，不为了复现原案例的数量增删事实；材料根本不形成并列关系时，用能承担同一作用的场景、动作或结果继续推进。局部无法迁移时只调整局部，不把完整案例降级成一句抽象灵感，也不把表面数量变成固定模板。

作者声音负责让新稿像当前作者在说话，不能把已经有依据的案例节奏和表达技巧清洗成普通说明文。事实仍只来自当前材料，案例不提供新任务的数字、身份、经历和结论。

## 六、创建和更新

用户明确要求保存或更新案例时：

1. 保留未经改写的完整原文和可核对来源。
2. 先按完整内容、开头或两个角色确定目录和索引字段。
3. 主题、类型和任务只写入隐藏索引，不写成使用限制。
4. 不为案例添加唯一借用结论，不替未来写作者决定只能学习哪一层。
5. 同一来源增加新角色时补充索引，不复制原文。
6. 完成后运行 `build-index` 和 `validate`。

新增目录或技巧类别只服务查找。只是换了人物、行业或项目时不增加题材限制；发现一篇案例还有新的表达价值时，未来写作直接从原文读取，不需要先修改案例说明才能使用。

## 七、通过标准

- 打开社交案例时先看到标题、原文和来源，看不到占据正文上方的机器属性。
- 活动案例中不存在替原文下结论的固定摘要栏目和狭窄使用范围栏目。
- 检索输出先给完整原文，索引字段不进入写作输入。
- 成品类型只影响排序，不会拦截表达上更合适的跨类型案例。
- 写作结果能够指出并实际复现多层表达技巧，而不是只复述一个索引标签。
- 高度沿用已选案例的结构和节奏不被自然度清理误判为 AI 模板。
- 案例中的条目数、段落数和具体数值没有成为固定要求；改变这些参数后仍能保留案例真正有效的推进、节奏和表达作用。
- 本次事实、身份、经历、立场和精确引语仍然来自当前材料。
