# 完整内容案例库

用于在写作前查找真实完整成品，也用于用户明确要求时保存或更新案例。它不管理钩子；钩子由独立的钩子库、脚本和索引维护。

## 案例真源

完整案例保存一条真实成品从第一句到最后一句的原文和可核对来源。完整短内容位于 `<私人知识库>/20-Sources/Social Posts/Content Cases/完整短内容/`，活动文章案例位于 `<私人知识库>/20-Sources/Articles/`。两类文件可以共享索引，但按当前成品形态读取：短内容只查完整短内容，文章与 Newsletter 才查文章；用户明确要求跨形态参考时除外。

```text
<私人知识库>/20-Sources/Content Cases/内容案例索引.md
```

完整案例的隐藏索引只保留定位和既有业务边界所需的字段，例如写作任务、主题、推进动作、成品形态、宣发角色、利益领取者和声音资格。案例不得保存钩子 id、钩子分析、读者效果或钩子来源引用。

两类索引回答不同问题：内容案例先按完整成品承担的写作任务定位，钩子先按开头手法定位。不能把案例主题复制成钩子分类，也不能用钩子手法重组完整案例库。

## 查找与读取

先浏览案例索引，再只搜索当前成品对应的目录。短内容使用：

```powershell
rg -n -i "当前任务或对象" "<私人知识库>/20-Sources/Social Posts/Content Cases/完整短内容"
```

文章或 Newsletter 使用：

```powershell
rg -n -i "当前任务或对象" "<私人知识库>/20-Sources/Articles"
```

索引只负责定位。网络搜索得到的新闻、评测、博客和其它文章是当前对象的外部材料，不因此成为文章案例，也不改变短内容的案例目录。先根据当前成品、对象和读者缩小范围，再打开少量真正准备阅读全文并用于本次写作的完整案例。模型直接从全文感受信息选择、关系组织、推进、节奏和表达，不选择唯一模仿对象，不把每篇压缩成规定学法，也不按案例拼装模板。本次实际使用的案例在最终“本次创作参考”中列出。

完整案例还可以让写作者看见当前内容是否缺少必要场景、证据或上下文；这个缺口确实影响本篇成立时，返回当前对象的来源补材料。当前作品的事实、人物、身份、经历和结果仍由对象材料与用户要求提供。上层可以同时提供独立钩子库中的原文，两类资源共同参与写作，但彼此不引用、不转换身份。

写作按当前成品的任务、对象、读者和可迁移的推进方式查看相关案例。当前内容含福利、时限或行动入口时，可以用 `index_roles` 和 `benefit_recipients` 帮助找到机制相近的案例，但不能因此排除普通案例，也不能把这些索引字段交给写作者。案例中的利益、身份、时间和行动入口不能改写当前任务材料已经确定的事实。

## 创建和更新

只有用户明确要求保存或更新案例时才写入。保存时保留未经改写的全文和可核对来源；完整短内容使用 `short`，文章使用 `article`：

```powershell
python scripts/content_case_library.py add-case --kind short --input "完整原文.md" --title "案例标题" --content-type "项目与产品介绍" --source "来源链接或本地来源" --index-task "介绍项目" --topic "主题" --move "输入变成结果"
python scripts/content_case_library.py build-index
python scripts/content_case_library.py validate
```

新建宣发案例时通过 `--index-role`、`--promotion-stage`、`--audience-action` 和 `--benefit-recipient` 写入同一资源；新建本人发布案例时通过 `--writing-format`、`--writing-origin` 和 `--voice-eligible` 明确声音资格。更新已有资源时直接修改唯一案例文件并重建索引。

## 通过标准

- 案例脚本、目录、数据类型和索引只认识完整短内容与完整文章。
- 完整案例先显示原文和来源，隐藏索引不规定唯一学法。
- 案例文件不存在钩子字段，也不能通过案例路径生成钩子。
- 写作可以同时读取多个完整案例与多个独立钩子，但管理和索引边界保持分开。
