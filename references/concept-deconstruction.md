# 概念拆解方法

用于根据用户当前用途，把概念讲到刚好能够理解、判断、使用或写作的程度。概念拆解不是把所有相关知识展开，也不要求每次展示同一套标题。

## 一、先选解释深度

### 快速理解

回答四个问题通常已经足够：

- 它为什么会出现，或试图解决什么问题。
- 它到底是什么。
- 原因怎样一步步产生结果。
- 一个具体情境中会发生什么。

只补充会直接造成误解的一项边界。来源谱系、学术争论、全部变体和低概率例外默认省略。

### 为写作或判断服务

在快速理解之上，补充当前文章或判断真正会用到的内容，例如：

- 概念由谁在什么背景下提出，以及后来发生了什么关键变化。
- 能承载文章主线的人物转折、现实矛盾或典型误解。
- 支撑核心机制的证据、案例或直观数据。
- 会改变文章结论或实际选择的限制与反方。

### 深入研究

用户明确要深究，或概念本身存在重大定义冲突时，才系统展开原始定义、演变版本、证据质量、争议、替代理论和细分边界。

## 二、建立最低充分解释

优先组织成一条自然的解释链：

```text
现实问题或来源故事 → 核心含义 → 机制链 → 具体场景 → 当前用途需要的限制或用法
```

这是一条内部检查线，不是固定的正文目录。可以从人物故事、读者疑问、反常现象或定义进入，只要后续因果能够接上。

### 核心含义

用普通语言说清它指什么。只有相近概念确实会干扰当前理解时，才说明关键差异；不为了显得严谨而罗列所有排除项。

### 机制链

把原因和结果连接起来：

```text
条件或变化 → 中间过程 → 结果 → 可能的反馈
```

只写资料能够支持的因果。资料只说明相关性时，不自行补成确定机制。

### 具体场景

例子应展示事情怎么发生，而不是只报一个人名或案例名。说明起点、变化和结果即可；教学例子要与真实事件分开。

### 限制或用法

只保留会改变当前理解、文章或行动的内容。用户只是询问来源时，不顺带展开全部风险；用户要实施或比较方案时，再补必要条件和差异。

## 三、按概念性质选择工具

概念类型只用于内部选择讲法，不必展示分类过程：

- **定义型**：说明必要特征；只有混淆真实存在时才做对比。
- **机制型**：突出参与因素、因果顺序、反馈和中断条件。
- **框架型**：说明组成部分怎样共同解决一个问题，以及怎样用于当前案例。
- **程序型**：说明输入、关键动作、反馈、纠错和完成标准。
- **争议型**：先找出各方究竟在哪个事实、定义或价值前提上不同，再按当前用途选择展开程度。

一个词有多种常见含义时，只拆开会影响当前结论的词义。

## 四、处理抽象内容

在“概念—机制—情境”之间移动。某一层已经说清时不要重复换词解释。

- **对比**：相近概念按同一关键维度比较，维度数量以消除当前混淆为止。
- **类比**：用于建立直觉；只有类比容易导致错误行动时才指出失效点。
- **概念关系**：只连接当前主线需要的前置、因果、依赖或对比关系。
- **知识地图**：三个以上概念之间的关系难以用短段落说明时才画图；简单关系用句子或列表。

## 五、与实践和写作连接

只有用户需要使用知识时，才继续选择相应产物：

- 用概念判断一个真实案例。
- 改变一个变量，观察机制会怎样变化。
- 把框架用于模拟、方案或决策。
- 提取可用于文章的来源故事、解释链、例子和关键证据。

实践可以由 Agent 演示或共同完成，不要求用户先背诵、答题或证明自己学会。

## 六、何时停止

满足以下条件即可结束当前层次：

- 用户当前问的问题已经得到直接回答。
- 用户能够沿着原因和结果理解概念，而不是只记住术语。
- 已有一个足以建立直觉的具体情境。
- 所有会实质改变当前判断的限制已经说明。

不是每次都必须有反例、完整概念地图、实践任务或学术争议。是否补充取决于它们对当前用途有没有作用。
