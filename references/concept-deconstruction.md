# 概念拆解方法

用于根据用户当前用途，把概念讲到刚好能够理解、判断、使用或写作的程度。解释范围和结构随当前用途变化。

## 一、先选解释深度

### 快速理解

回答四个问题通常已经足够：

- 它为什么会出现，或试图解决什么问题。
- 它到底是什么。
- 原因怎样一步步产生结果。
- 一个具体情境中会发生什么。

只补充会直接造成误解的一项边界。来源谱系、学术争论、全部变体和低概率例外默认省略。

### 为写作或判断服务

在快速理解之上，补充当前文章或判断真正会用到的内容，例如：

- 概念由谁在什么背景下提出，以及后来发生了什么关键变化。
- 能承载文章主线的人物转折、现实矛盾或典型误解。
- 支撑核心机制的证据、案例或直观数据。
- 会改变文章结论或实际选择的限制与反方。

### 深入研究

用户明确要深究，或概念本身存在重大定义冲突时，才系统展开原始定义、演变版本、证据质量、争议、替代理论和细分边界。

### 技术概念默认保留两个层次

抽象、技术或公式密集的概念默认按以下顺序交付：

1. **可理解层**：从现实问题、具体对象或一个能完整走通的例子进入，用普通语言说明概念做了什么、为什么需要它、条件变化后会发生什么。
2. **正式层**：保留精确定义、符号含义、核心公式或结构、成立条件、与相邻概念的关系以及会改变使用方式的边界，提供以后继续学习的入口。

每个正式元素都指回可理解层：公式中的对象分别对应例子里的什么，条件限制了哪个结论，计算结果能回答哪个问题。对应关系缺失时，修正例子并收拢到当前主线需要的公式。

正式层保证当前主题的主干完整；全部证明、其它变体和整套先修课由深入研究触发。快速理解时说明正式层可以留作后续入口。

两层要求作用于整份技术交付。面向普通人的行动总结、最终清单或“实际怎么用”部分使用可观察对象、判断条件和动作表达；精确定义、公式与高阶关系放在后续独立正式层。

### 先建立概念身份

解释一个被点名的核心概念时，先让可理解层独立完成以下工作：

1. 用“满足什么条件，就把它叫作什么”的方式给出最小定义，并区分符合与相邻情况。
2. 说明它具体在处理什么输入、使用哪些已知信息，并回答、计算或约束什么问题，说出它让人能够判断什么。
3. 让概念在一个完整情境中运行一次，说明起点、规则、发生的变化和得到的结果。
4. 再把正式术语、符号和公式逐项对应回这个情境，指出每个条件限制了哪一步。

两个相近概念同时出现时，先分别完成“是什么”和“做什么”，再让它们经过同一个情境并按同一维度比较。至少给出一个只满足其中一个概念的例子。

## 二、建立最低充分解释

优先组织成一条自然的解释链：

```text
现实问题或来源故事 → 核心含义 → 机制链 → 具体场景 → 当前用途需要的限制或用法
```

这是一条内部检查线。正文可以从人物故事、读者疑问、反常现象或定义进入，并让后续因果自然接续。

### 核心含义

用普通语言说清它指什么。相近概念确实会干扰当前理解时，说明会改变判断的关键差异。

### 机制链

把原因和结果连接起来：

```text
条件或变化 → 中间过程 → 结果 → 可能的反馈
```

因果强度与资料支持程度一致；相关性材料按相关关系表达。

### 具体场景

例子展示事情怎么发生，说明起点、变化和结果；教学例子与真实事件分别标明。

### 限制或用法

限制与用法围绕会改变当前理解、文章或行动的内容。询问来源时交付来源；实施或比较方案时补充必要条件和差异。

## 三、按概念性质选择工具

概念类型用于内部选择讲法，输出直接采用对应结构：

- **定义型**：说明必要特征；只有混淆真实存在时才做对比。
- **机制型**：突出参与因素、因果顺序、反馈和中断条件。
- **框架型**：说明组成部分怎样共同解决一个问题，以及怎样用于当前案例。
- **程序型**：说明输入、关键动作、反馈、纠错和完成标准。
- **争议型**：先找出各方究竟在哪个事实、定义或价值前提上不同，再按当前用途选择展开程度。

一个词有多种常见含义时，拆开会影响当前结论的词义。

## 四、处理抽象内容

在“概念—机制—情境”之间移动，每一层承担独立作用。

- **对比**：相近概念按同一关键维度比较，维度数量以消除当前混淆为止。
- **类比**：用于建立直觉；只有类比容易导致错误行动时才指出失效点。
- **概念关系**：只连接当前主线需要的前置、因果、依赖或对比关系。
- **知识地图**：三个以上概念之间的关系难以用短段落说明时才画图；简单关系用句子或列表。

### 用户反馈看不懂时

“看不懂”“太数学”“太抽象”说明可理解层需要重建。此时：

1. 回到概念试图解决的现实问题，换一个完整具体情境重新解释。
2. 减少同一段中的新术语和符号，先让用户知道谁对什么做了什么、得到了什么。
3. 重新连接正式层，说明每个定义或公式对应情境中的哪一步。
4. 保留与当前主题相关的精确定义、核心公式和成立条件。

从现实问题和完整情境重建解释，再连接正式锚点。用户只指出普通人总结太专业时，重写该总结并把公式移到正式层，整份内容继续保留必要的正式层。

### 用概念判断现实对象

用户问“现实中的某个东西是不是这种数学对象”时，按下面的顺序判断：

1. 先写出概念真正要求的性质，再判断现实对象。
2. 固定观察变量、时间尺度、当前可用信息和“状态”包含的内容。同一个现实系统在不同状态定义下，可能得到不同结论。
3. 构造一个反事实检查：如果当前状态相同、历史不同，下一步的条件分布是否仍应相同？如果历史还能改变预测，说明当前状态没有压缩完有用信息。
4. 分别说明模型假设与现实证据；模型中的可计算假设按假设报告。
5. 区分正在判断的分布部分，分别检查方向、条件均值、波动、尾部、持续时间或状态切换。
6. 结论写到证据能够支持的程度，例如“在这个模型和状态定义下成立”“单独用当前价格证据不足”或“加入波动状态后可以建成马尔可夫模型”。

## 五、与实践和写作连接

只有用户需要使用知识时，才继续选择相应产物：

- 用概念判断一个真实案例。
- 改变一个变量，观察机制会怎样变化。
- 把框架用于模拟、方案或决策。
- 提取可用于文章的来源故事、解释链、例子和关键证据。

实践可以由 Agent 演示或共同完成，用户决定参与方式。

## 六、何时停止

满足以下条件即可结束当前层次：

- 用户当前问的问题已经得到直接回答。
- 用户能够沿着原因和结果理解概念，并能说明术语的实际含义。
- 已有一个足以建立直觉的具体情境。
- 技术概念已经保留可供以后继续学习的正式定义、核心公式或结构及其成立条件。
- 所有会实质改变当前判断的限制已经说明。

反例、完整概念地图、实践任务和学术争议在它们服务当前用途时补充。
