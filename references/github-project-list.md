# GitHub 项目清单

用于盘点、推荐、排名或比较多个 GitHub 项目。本文件只维护“多个对象需要在同一篇里形成可理解的集合”这一成品职责，不把每个项目写成独立长介绍。

## 必要输入

上层提供用户指定的项目数量、清单用途、格式，以及每个候选项目取舍后仍保留完整事实关系和必要上下文的材料。用户要求排名、评测或锐评时，需要有能够支撑比较的共同尺度；只是资源合集时不必制造排序。star 数、价格、维护状态、许可证、平台和技术栈只在用户要求或它们确实影响当前选择时加入。

## 共同成文

模型根据清单用途决定入选、排序、每项篇幅、开头、字段、句式、入口和收束。不同项目可以用不同角度说明，只要读者仍能理解它们为什么被放在一起；不要为视觉整齐把所有项目压进同一句型，也不要预设每项只能一句。

多个完整案例与多个独立钩子原文一起作为创作参考，不要求唯一样本、固定数量或采用记录。案例里的项目评价和实时数据不自动成为本轮材料。

用户给出参考格式时沿用字段顺序、换行、链接位置和 Markdown 包装。没有指定格式时由模型按信息量自然组织，不使用固定清单骨架。每项需要项目页面、安装入口或其它行动信息时分别保留；共享提示词只有在用户要求或整份清单本来就服务同一个 AI 任务时加入。

草稿完成后统一交回上层检查比较结果、实时字段和行动入口中会造成实质误解的部分，并做自然润色。本模板不重复逐项核查清单。
