# 学习过程与方法选择

用于围绕具体材料、主题或真实任务判断“现在卡在哪里、下一步用什么方法”。流程直接服务当前学习对象和用途。

## 一、什么时候使用

满足以下任一情况时使用：

- 用户面对具体材料或任务，不知道怎样开始或继续。
- 用户能读懂文字，却无法建立结构、判断真假或实际使用。
- 同一种方法反复无效，需要定位问题出在哪个环节。
- 解释或实践方式必须根据材料性质和用户已有知识调整。

用户只要求日程或打卡表时，进入相应计划流程；出现具体学习对象、用途或卡点时进入本流程。

## 二、先做四项判断

### 1. 当前用途与产物

先确定知识最后要帮助用户完成什么：看懂材料、形成判断、通过考试、执行程序、制作工具、解决问题还是准备文章。方法是否有效，要由这个产物判断。

把“学会”展开为真实使用环境中的可观察结果：

| 目标表现 | 检查方式 |
| --- | --- |
| 识别 | 在相似干扰项中辨认 |
| 回忆 | 延迟后在适当提示下调用 |
| 理解和解释 | 说明关系、条件、推导和反例 |
| 程序执行 | 在真实或模拟环境完成步骤和产物 |
| 辨别与策略选择 | 在混合案例中选对方法并说明线索 |
| 迁移与泛化 | 在未练过、表面变化的新案例中使用 |
| 保持 | 经过目标时间后仍达到所需表现 |

同一任务可以需要多个结果，但应指出当前最影响产物的一项。记忆、理解和迁移不是互斥活动；具体案例、抽象规则和程序都可能共同支持新任务。

### 2. 已有知识

判断用户是否已有能够调用的概念、案例、程序或经验：

- **陌生**：术语和关系都需要建立，先给主干和示例。
- **部分熟悉**：已有零散知识，重点补关系、差异和缺口。
- **能够使用**：减少基础解释，直接进入原始资料、争议、变体和迁移。

根据当前任务中可观察的表现调整帮助，能力判断保持在本次任务范围内。

### 3. 信息性质

以下分类只用于选方法，同一材料可以同时包含多种性质：

- **事实信息**：名称、日期、规则、符号或其它需要准确调用的内容。
- **主张信息**：带有立场、证据和适用条件的判断。
- **程序信息**：指导行动的一组步骤、判断点和反馈。
- **具体信息**：可以观察、感知或放进现实场景的材料。
- **抽象关系**：机制、模型、公式、因果或概念之间的关系。

只判断当前最影响方法选择的材料性质，分类数量随实际内容调整。

### 4. 当前卡点

按最先阻塞后续结果的环节定位：

| 环节 | 常见表现 | 当前目标 |
| --- | --- | --- |
| 获取 | 材料缺失、噪音太多、来源不合适 | 得到足够且相关的输入 |
| 字面理解 | 术语、句子、符号或上下文不清 | 准确说出材料在表达什么 |
| 建立联系 | 知识孤立，无法解释原因或差异 | 形成最小关系结构 |
| 纠错 | 来源冲突、类比失真、结论过度 | 找到错误位置和适用边界 |
| 应用 | 会复述但不会判断、执行或制作 | 产生真实用途需要的结果 |
| 反馈 | 不知道结果是否可靠、能否迁移 | 用结果定位下一轮改进 |
| 行动启动 | 知道要做什么，却迟迟不能开始 | 找到具体阻力并形成最小起步动作 |
| 持续投入 | 能开始，但很快中断或切换活动 | 调整相关性、难度、反馈和环境 |

先处理最影响后续的一项。问题解决后再判断是否需要进入下一环节。

## 三、学习是可往返的循环

初次接触材料时，通常会经历：

```text
获取 → 字面理解 → 建立联系 → 纠错 → 应用 → 反馈
```

这条顺序用于定位条件，各阶段可以按反馈往返：

- 建立联系困难时，回到术语和上下文。
- 核查发现来源质量不足时，回到获取阶段换材料。
- 应用失败时，判断是程序、机制、假设还是环境有问题。
- 一个低风险的早期尝试能够暴露缺口时，可以先尝试，再带着问题学习。

理论理解、来源核查、逻辑检查和实践按当前问题交替推进。

## 四、先搭最小模型，再逐步展开

解释陌生或复杂内容时：

1. 先确定当前问题不可缺少的少量要素。
2. 说明这些要素之间最关键的关系。
3. 给一个能展示关系如何运行的具体例子。
4. 用户已经能够跟上主线后，再加入证据、变体、反例和边界。
5. 新内容加入后破坏理解时，重新分段或换一个更贴近已有知识的入口。

### 结构服务于当前关系

选择树、图、表格或流程时，先说明当前要表达的关系，再让结构服务这种关系：

| 当前要回答的问题 | 优先结构 |
| --- | --- |
| 对象主要属于哪里、整体怎样逐层分解 | 树或层级目录 |
| 多个对象怎样相互连接、存在多父节点 | 图或双向链接 |
| 多个对象在相同维度上怎样比较 | 表格或矩阵 |
| 事件或状态怎样依次变化 | 时间线、流程图或状态图 |
| 既要稳定入口，又要表达多重关系 | 树作为主要入口，链接和属性补充 |

使用树时，检查父子边表达的关系、兄弟节点是否采用同一划分标准，以及多父节点和交叉关系怎样呈现。需要复制节点或加入交叉引用时明确保留这些关系，并说明转换覆盖程度。

从零散内容建立结构时：

1. 先外化候选主张、事实、案例、方法和疑问，保留来源、条件和置信度。
2. 用直觉或相似性生成临时聚类和候选连线，并标记为待验证关系。
3. 给重要关系标明种类、组成、依赖、因果、时序、逻辑支持、证据、冲突、类比或使用触发等具体类型。
4. 检查两端定义和范围、关系方向、证据、反例以及它会改变的结果。
5. 待确认关系保留为开放问题；条件不同的竞争主张按各自成立条件并存。
6. 最后根据关系选择树、图、表格或流程，并用查询、解释、判断或实践检查结构。

熟悉领域的直觉适合提出候选关系；陌生领域增加示例、明确比较和来源核查，由证据决定关系强度。

工作记忆负担取决于用户已有知识、当前材料和同时需要处理的陌生关系。按这些因素决定每组信息量。

可以使用熟悉结构和类比建立入口，并检查它是否保留当前要解释的关系。能够帮助解释、预测或行动的联系进入正式结构。

## 五、评价方法先限定作用范围

吸收、比较或推荐学习方法前，先还原五件事：

1. 它处理什么信息或任务。
2. 它解决哪个具体卡点。
3. 它需要哪些前提和使用环境。
4. 它承诺产生什么可观察结果。
5. 它在哪些情况下会失效或增加成本。

方法冲突时，比较作用范围重叠的部分。两个相反建议可能分别服务不同信息、熟练程度或使用环境。方法的局部效果按相应结果检查，讲者的完整理论框架另行判断。

### 控制方法采用队列

方法较多或用户想同时改变多个习惯时：

1. 记录当前做法、卡点和最低限度的结果基线。
2. 按卡点匹配、近期使用频率、可能收益、可信度和实施成本排序。
3. 优先采用一个主要改动，或者一组无法拆开的互补动作。
4. 为方法定义触发情境、最小动作、可观察结果、观察窗口和停止条件。
5. 使用足够次数后，明确保留、修改、降低频率或停止，再引入下一项。

一次改变少量因素用于降低执行负担并看清结果。检索与纠错反馈等配套动作可以作为一个方法包；紧急问题按实际优先级处理。旧方法和新方法都按当前个人数据与结果选择。

## 六、按信息与用途选择方法

| 主要信息 | 优先方法 | 结果检查 |
| --- | --- | --- |
| 事实信息 | 按自然关系组织；保留可查询外部记录；确实需要随时调用时做可选检索练习 | 能在需要的情境准确找到或调用 |
| 主张信息 | 追溯来源；分开事实、推断和价值前提；寻找反方与适用条件 | 能说明证据、信任范围和改变判断的条件 |
| 程序信息 | 新手先看完整示例和关键判断点，再做有反馈的尝试；熟悉后减少提示并增加变体 | 能完成产物，并能定位步骤错误 |
| 具体信息 | 观察、比较多个实例、标出决定性特征并改变条件 | 能从新案例中识别相关特征 |
| 抽象关系 | 最小模型、因果链、具体实例、对比和迁移 | 能用关系解释新情境，而不只复述定义 |

混合任务按局部问题选择方法。例如一份投资文章可以同时使用记忆规则、主张判断、机制理解和个人情景应用。

## 七、决定内部掌握还是外部查询

先看知识在真实环境中怎样被调用，再决定记忆与外部检索的分工。

优先内部掌握：

- 必须立即反应，现场没有查询时间。
- 高频使用，反复查询的总成本更高。
- 是理解、提问、检索和评价其它信息的基础。
- 需要形成流畅判断、程序或动作。
- 查询失败会造成明显损失。

优先外部保存：

- 精确但低频的数字、参数、日期、命令和长列表。
- 经常变化的规则、版本、价格和状态。
- 需要保留原文、来源和上下文的证据。
- 已有稳定概念结构后能够快速定位的参考细节。

默认采用两层结构：内部保留概念、索引、检索线索和判断标准，外部保存精确细节、来源和版本。结果检查关注在真实时间内找到、判断并正确使用信息的能力。

## 八、用自我解释定位理解缺口

自我解释适合概念、机制、程序和“读懂但不会用”的内容，其它信息按调用方式选择方法。

1. 先定义本次要达到的用途和检查标准。
2. 获得最小必要输入后，暂时离开材料，用口述、书写、图示、推导或操作重建理解。
3. 把“卡住了”进一步定位为调用、术语、关系、条件、例证或应用缺口。
4. 定向返回材料补当前缺口，同时核对原解释中的错误。
5. 再次独立重建，并用新案例、反例、实际程序或产物检查。

理解标准同时包含语言可懂、必要术语、成立条件和实际使用。Agent 可以负责追问、核对材料、提供反例和应用情境；用户选择开卷方式时，用对照、新案例或实际产物检查理解。

## 九、具体学习任务中的行动问题

用户学不下去时，先区分是行动问题还是知识问题：

- **迟迟不能开始**：检查任务是否含糊、准备是否繁琐、是否害怕失败或容易被环境打断。先明确第一个具体动作，减少准备，并降低第一次尝试的代价。
- **开始后难以持续**：检查内容与现实用途的关系、难度、反馈速度、单次长度和切换诱因。可以增加个人相关性、可见反馈和适度变化，并继续用学习结果判断效果。
- **一直在做却没有结果**：回到信息性质、方法和反馈，重新选择有效动作。

兴趣、用途、反馈、环境和任务设计共同影响投入，奖励间隔按具体学习任务调整。本节聚焦当前学习任务。

## 十、根据已有知识调整帮助

### 用户对主题陌生

- 先给主线、必要术语和完整示例。
- 一次只改变少量关键关系。
- Agent 可以演示检索、分析、计算和第一次应用。

### 用户已有部分经验

- 从已有理解出发，指出缺少的联系和错误边界。
- 用比较、反例和变体代替重复基础定义。
- 让用户选择参与程度，用可观察结果判断学习效果。

### 用户已经能够使用

- 减少解释性脚手架，直接提供原始资料、冲突证据和复杂案例。
- 检查迁移、边界和判断质量，据此选择后续步骤。

帮助程度随当前表现变化，不按固定阶段长期绑定用户。

## 十一、反馈、检索与低压力测验

根据用途选择最低压力的反馈：

- 查证关键事实或重做推导。
- 用新案例检查机制能否解释。
- 运行模拟、代码或实际流程观察结果。
- 比较方案与约束是否一致。
- 用户愿意时使用检索练习检查需要随时调用的内容。

只有知识将来需要独立调用，或当前需要暴露理解和应用缺口时，才优先安排检索练习。低频、可可靠查询的精确细节可以保留在外部资料中。

安排检索时：

1. 先明确最终要回忆事实、解释机制、选择方法还是完成操作。
2. 提供最低必要输入，让完全陌生的用户有依据地作答。
3. 可以在刚学完后检查是否跟上，也可以延迟一段时间检查保持；时间点按目标选择。
4. 让检索需要一定努力，但能够成功，或能在尝试后立即获得可靠答案和纠错。
5. 修正后隔一段时间重新调用，并逐步改变线索、案例或使用情境。
6. 根据正确率、错误类型和最终用途调整次数与间隔。

检索练习可以采用开卷对照、新案例、模拟、实际产物或由 Agent 完成的查证。用户选择闭卷形式时再使用闭卷；反馈用于定位理解和使用上的缺口。

## 十二、根据目标安排练习、休息与孵化

先区分练习目标：

| 当前目标 | 优先安排 |
| --- | --- |
| 新手建立基本概念、动作或步骤 | 完整示例、少量集中练习和及时反馈 |
| 延迟后仍能调用 | 间隔练习与检索 |
| 判断该使用哪种策略 | 在掌握基本方法后穿插相近问题 |
| 适应案例、参数和环境变化 | 逐步增加变化和迁移任务 |
| 在真实约束下完成任务 | 接近最终用途的综合练习和结果反馈 |

集中练习帮助初次获得，穿插练习帮助识别问题并选择策略。用户正在建立各方法的基本过程时，先用示例和适量集中练习；间隔根据目标保持时间、当前表现和重学成本调整。真实练习保留关键约束和反馈。

需要迁移或泛化时：

1. 明确新情境允许改变哪些表面特征、条件和约束。
2. 选择表面不同但深层关系相同的正例，以及表面相似但机制或结果不同的反例和边界案例。
3. 并排比较案例，提出多个候选规则、相似性结构或策略，再用新情境检验。
4. 用没有参与形成候选规律的新案例检查，并记录失败是调用、辨别、范围、遗漏变量还是偶然细节造成。
5. 区分欠拟合、过拟合、过度泛化和泛化不足；用旧案例与新案例共同判断规律质量。
6. 语言说明用于引导注意，案例用于展示含义和边界，两者配合使用。

增加案例只有在带来新的区分、范围或反例时才改善归纳。形成规则后仍保留关键案例，用于解释来源、例外和环境变化。

休息和问题孵化解决的是另一类问题：

- 持续注意明显下降时，可以安排短暂、低干扰的休息，再返回任务。
- 生成解释、方案、证明或创意已经经过一轮专注处理，却反复卡在同一路径时，可以暂时进行低负荷活动，回来后检验出现的新想法。
- 卡点是缺少事实、术语未懂、基本步骤不会或没有反馈时，优先补输入和指导。
- 初次编码和关键推理期间保持专注；心流和发散按实际任务需要切换。

## 十三、完成标准

满足以下条件即可停止当前层次：

- 当前卡点已经解除，或已明确缺少什么外部条件。
- 用户需要的产物和目标表现已经形成，知识确实参与了结果。
- 会改变结果的错误、假设和边界已经记录。
- 当前方法已经足以支持理解或行动，新增方法的边际价值低于负担。

如果方法没有产生预期结果，先重新判断卡点和信息性质，再选择替换、调整或补充方法。
