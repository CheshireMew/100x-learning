# 研究驱动学习

用于用户只给出一个主题、问题或陌生概念，需要主动寻找资料，并把资料变成当前用途真正需要的知识或写作材料。

## 一、先确定研究要交付什么

根据用户请求选择最低充分研究：

- **快速理解**：找到原貌、核心机制和一个可靠例子，回答当前问题后停止。
- **写作材料**：补齐文章主张需要的来源故事、解释链、可用案例或数据、读者最可能提出的质疑。
- **判断或实践**：查清会改变选择的规则、条件、成本、风险和替代方案。
- **深入研究**：用户明确要求时，再完整处理演变、方法、冲突证据和争议。

用户已经说明用途时直接研究，不重复盘问。用途不清时，从请求强度推断最浅但有用的一层；不要自动把定义、机制、证据、争议、应用全部做成五章。

## 二、只建立必要问题

按用途选问题，而不是每次全部回答：

- 它原本由谁在什么背景下提出，今天讨论的是哪个版本？
- 它为什么可能有效，原因怎样导向结果？
- 哪项证据最能支持或削弱当前主张？
- 用户真正要写、判断或操作时，哪项差异会改变结果？
- 普通读者最容易在哪一步产生疑问？

研究问题应直接对应交付物。只问来源时不扩张成完整可行性研究；要写文章时，不只收集定义和术语。

## 三、按角色组织来源

来源没有固定高低顺序。先判断它要完成什么工作：

| 来源角色 | 用途 | 通过标准 |
| --- | --- | --- |
| 定义源 | 还原创始主张、术语和规则 | 能追溯原文，不改变概念边界 |
| 证据源 | 支持或反驳可验证主张 | 方法、数据、样本和时间范围透明 |
| 解释源 | 用通俗语言讲清机制 | 简化但不扭曲，有完整例子和边界 |
| 案例源 | 展示真实使用和执行摩擦 | 背景充分，不用个案冒充普遍结论 |
| 反方源 | 揭示失败条件和隐藏假设 | 回应真正主张，不制造稻草人 |
| 实践经验 | 提供操作细节、踩坑和变体 | 明确个人环境、选择和结果 |
| 问题源 | 暴露普通人最常见的疑问 | 只用于发现问题，不直接作为结论依据 |

论文、官方文件、书籍、博客、播客、论坛和个人记录都可以进入来源组合。高质量博客常是更好的解释源或案例源；涉及金额、健康、法律权利、实时规则等高影响事实时，再用官方文件、原始数据或可靠研究核查。

## 四、按主张和用途判断质量

不要给整篇文章贴一个总分。对准备采用的关键主张分别检查：

- **可追溯性**：能否找到原始定义、数据或事件。
- **方法透明度**：数据区间、样本、算法或推导是否交代。
- **机制完整性**：是否解释原因怎样导向结果。
- **边界意识**：是否说明会改变当前结论的反例、失效条件和适用环境。
- **利益关系**：作者是否销售相关产品、服务或立场。
- **时效与地域**：结论是否依赖特定时间、国家、货币或制度。
- **教学价值**：是否使用准确、具体、能迁移的语言和案例。

同一来源可以在解释上优秀、在事实证明上不足。保留它擅长的部分，对超出能力且影响当前结论的主张另找证据。博客和视频可以因为更通俗、有真实使用感或案例完整而成为主要解释材料，不需要为其“二手”身份道歉。

### 核查强度

- 会改变概念原貌、文章核心结论、数据可信度、现实决策或被理解为承诺的主张，追溯可靠来源。
- 只帮助理解但不承担证明作用的故事、类比和经验，标清其角色即可。
- 与当前用途无关的术语精度、极少数例外和完整争论不进入交付。

高风险领域需要核实关键主张，但不把全部核查过程和免责信息塞给用户。只输出核查后真正影响理解或行动的结果。

## 五、研究工作流

1. 从交付物倒推少量研究问题和搜索词。
2. 先确认当前讨论的概念版本，避免资料彼此错位。
3. 只为所需的机制、证据、故事、案例或反方寻找合适来源。
4. 对会改变结论的主张建立证据卡并按影响核查。
5. 来源冲突影响结论时，判断它来自定义、数据区间、评价目标还是事实错误；不影响时不展开。
6. 把资料重组成解释链、判断依据或写作内容，不按搜索顺序逐篇摘要。
7. 已经能够支持当前交付物时停止。

### X/Twitter 与 Grok CLI 路由

先判断任务是否满足任一条件：

- 研究对象本身是 X/Twitter 的帖子、账号、回复链、平台讨论、传播过程或舆情。
- 完成任务必须取得 X 原帖或平台内上下文，而当前通用检索工具无法可靠取得。
- 用户明确要求使用 Grok CLI。

满足条件时，优先用本机 Grok CLI 获取候选材料；不满足时继续使用当前通用检索工具。某个主题在 X 上流行、搜索结果可能包含 X 链接，或 Grok 已安装，都不构成调用理由。查证产品规则、法律条文、论文结论和公司公告时，优先使用相应官方或一手来源；除非任务还要求分析 X 上的讨论，否则不额外调用 Grok。

调用时使用单次无界面模式，限制任务边界和轮次。例如：

```powershell
grok --single "搜索 X/Twitter 上与该研究问题直接相关的内容。返回原帖链接、作者、发布时间、核心内容、必要上下文和检索限制；区分直接读取的原帖与搜索摘要，不要把摘要冒充原文。" --output-format json --no-subagents --max-turns 4
```

根据任务替换提示词，至少要求返回：

- 原帖或回复链的直接链接。
- 作者或账号。
- 发布时间；无法确认时明确为空。
- 与研究问题相关的核心内容和必要上下文。
- 内容是直接读取、搜索摘要还是模型推断。
- 删除、受限、未登录、索引不全等检索限制。

处理结果时：

1. 把 Grok 返回内容视为候选来源，不因来自 Grok 自动提高可信度。
2. 有原帖链接时回到原帖核对作者、时间、上下文和实际表述；只能取得摘要时标为“未核对原帖”。
3. 帖子可以承担观点、案例、实践经验、问题源或传播证据；可验证事实仍按风险追溯官方文件、原始数据或可靠研究。
4. Grok CLI 不存在、未登录、超时或无法读取目标内容时，改用当前可用检索工具继续研究，并在交付中说明未能验证的 X 内容。
5. 不为完成一次检索自动安装、更新、登录 Grok，也不自动放宽其工具权限；这些操作需要用户另行授权。

## 六、证据卡

只为影响理解或行动的主张建立证据卡：

```text
主张：
来源及角色：
它实际提供了什么：
适用条件：
反方或缺口：
当前可信度：
在教学或实践中怎样使用：
```

资料不足时保留未知，不用更多低质量链接制造确定感。简单问题不必把内部证据卡完整展示给用户。

## 七、为文章准备材料

文章研究不是把资料分成“定义、机制、风险、适用人群”四堆。应交付一条能继续写下去的内容链：

1. **文章要回答的核心问题**：读者为什么会关心。
2. **可作为入口的材料**：人物转折、来源故事、现实场景或反常结果。
3. **核心解释链**：每一步原因怎样导向下一步结果。
4. **正文可用内容**：事实、场景、案例、数据和通俗解释分别放在哪里。
5. **怀疑出现的位置**：读者会在哪一段不相信，此时用哪项证据回答。
6. **必要限制**：只保留会改变主张或读者行动的限制。

用户只要写作材料时，不顺带写全文，也不把抽象写作原则当成材料。

## 八、交付与停止

交付形式由请求决定：可以是一段直接解释、知识模型、来源判断、证据包、具体内容路线或实践依据。来源链接放在支撑相应主张的位置；链接清单不能代替解释。

满足以下条件即可停止：

- 当前问题得到回答，或当前文章主张已有足够支撑。
- 机制能被清楚说明，并有至少一个合适的具体材料。
- 会改变结论的事实已经核实。
- 新资料只是在重复、增加边缘例外或扩展到用户未问的方向。
