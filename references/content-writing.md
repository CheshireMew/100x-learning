# 内容成文

用于执行所有文字成品共有的成文步骤。上层已经选定写作动作、成品形态、表达任务和格式，从搜索结果中剔除了无关信息、官方套话、通用免责声明和保守提醒，并把净化后的内容材料、作者声音、专项模板、多个完整案例与多个钩子示例放在一起。本文件直接写出成品，不再选择路线、核查资料或建立写作执行记录。

## 进入条件

用户明确要求起草、改写、扩写、压缩、重组或审查后修改时进入。用户只要研究、分享候选或审查报告时，完成对应结果后停止。

短帖、清单、Thread、项目介绍和文章都在本次任务完成，由上层按用户的使用方式选择直接回复、代码块或临时 Markdown。长期保存由用户明确要求触发。

## 成品身份

上层已经选定下面一种形态，本节只保持它的基本职责：

- **独立帖**：脱离上下文也能成立，围绕一个完整判断。
- **引用帖**：让读者知道引用内容与当前判断的关系，再增加原因、机制或影响。
- **资源分享**：说明资源解决什么问题、为什么值得用以及真实入口。
- **产品帖**：让结果或使用场景可见，再用必要细节把它写具体。
- **Thread**：每一条推进同一个问题，顺序清楚。
- **通用短帖**：用户要短内容但没有指定更具体形态。
- **单项目介绍、项目清单或文章**：遵守上层已经读取的专项模板。

用户给出的长度、数量、Thread 拆分、链接位置、Markdown、换行和固定排版优先。

## 接收写作输入

开始前应当已经具备：

1. 当前对象、读者、作者位置和已经净化的可写材料；
2. 真正改变本篇选材和讲法的媒体、KOL、创作者、用户或社区内容；
3. 已选写作动作、成品形态、表达任务、数量与格式；
4. 本篇最值得讲的变化、用户必须写入的内容和停止位置；
5. 需要时的作者声音证据；
6. 专项模板；
7. 多个相关完整案例全文、多个钩子来源的开头与紧接内容，以及这些文件的实际路径；
8. 正文需要引导行动时，上层已经核实的项目主页、仓库、安装指南、原样候选命令及其完成范围和前置步骤，以及已经选定提示词作为主要下一步时所需的材料。

这些参考共同作为创作上下文，不要求先选出唯一案例或钩子，也不要求逐项登记采用状态。缺少会决定正文内容的行动入口，或宣发利益的领取者与时间时，把具体缺口交回上层；参考数量不足不会阻止成文。

## 直接成文

先让净化后的内容材料、外部真实声音和作者位置决定这篇真正要讲什么，再从所有参考中吸收适合的进入方式、推进、节奏、句式、格式与收束。模型可以把媒体或创作者看到的传播点、用户自己的说法和几篇案例的不同启发融成一个自然版本，但不能把它们拼成固定模板，也不能为了像案例而增加段落、CTA、结论或成品数量。

“根据、基于或结合材料写”表示新稿从材料取得事实与场景，不表示正文要沿用材料的措辞、顺序和结论。先守住直接引语、数字、人物身份、具体事件和关键关系，再根据当前读者与成品职责重新组织；材料能够支持的现场观感、情绪判断、比喻、过渡和读者启发可以直接成文，即使材料没有逐字写出。只有上层已经选择忠实摘要、逐句改写或不得超出原意时，才收窄这种创作空间。

面对字幕、访谈或会议记录，先把分散话语恢复成完整互动：谁反复发问，谁回避或改变问题，哪句话形成反差，后续内容真正回答了什么。直接引语本身承担冲突或悬念时，可以单独成段，让前一句建立场景、后一句解释价值；这是一种随材料决定的节奏，不是固定排版模板。

开头可以来自作者反应、项目本身、结果、场景、问题、动作或判断。钩子库提供的是可借鉴的开头技巧与来源示例，不是必须逐项满足的合同。来源用了“我刷到”“我试了”“把东西丢进去”等接触动作时，可以根据当前作者和场景自然改写，不要求先证明这个叙事动作逐字发生过；具体测试、效果和亲历如果最终承担可信度，再留给成稿核查。

面向普通读者时，前两句优先让一项可感受的变化成立，正文继续围绕熟悉的问题、能看到的结果和下一步行动推进。能力列表、文件格式、完整工作流和内部结构只有在读者必须理解它们才能判断或行动时才出现，必要术语第一次出现时立即用日常语言解释。读者还不认识对象时，在自然需要的位置用最短说明交代它是什么、直接做什么以及与当前内容的关系，不固定成“项目名＋类别”的身份句。

提示词不是正文的固定部分。只有用户明确要求，或者正文的主要下一步本来就是把一个明确任务交给具备目标环境操作能力的 AI，而且这段提示词比项目入口更直接地帮助读者完成任务时，才写出一至三句可以直接复制的提示词，包含目标、必要上下文或边界和完成后的验证结果。只是介绍、推荐、制造兴趣或提供项目入口时不加；需要读者自己完成时再写真正必要的手动步骤。

行动入口的唯一选择规则是先看正文目的和读者真正要完成的下一步，再看候选入口，不按命令能否排成一行判断。普通介绍、推荐、分享或制造兴趣时，默认使用项目主页、仓库或最有用的介绍页面；一段候选命令不会仅凭外形替代项目入口。用户明确要安装、运行或操作教程时，只有官方命令使用稳定的命令或包标识、不包含完整的 HTTP(S) URL，并且能在没有隐藏前置步骤的情况下完成正文承诺的主要动作，才把它作为直接指令。`npx package-name`、`npm install package-name` 和 `pipx install package-name` 属于这种指令的典型形式；`curl`、`wget` 或 `iwr` 携带完整网址的 Shell 管道属于链接式安装路线，不算直接指令，也不能仅凭单行形式替代项目入口。多步安装、只完成其中一层或仍需先安装其它组件时，改用官方安装指南或项目主页。

最终正文默认只保留一个最有用的主要入口，用户明确要求同时提供项目页和安装方式时除外。选择直接指令时，先用自然语言说明这条指令会完成什么，再给代码块；不把没有上下文的裸命令单独扔在结尾。已经选定的提示词包含同一指令时不重复。单对象正文使用页面入口时，让真实链接成为正文最后一行；项目清单按每项保留已经选定的入口，不要求多个链接同时位于整篇最后。只有整份清单共同服务一个明确任务时才提供一段共享提示词。用户指定的格式和链接位置优先。

多项功能、步骤或结果只有真实并列时才列点。关系已经清楚时直接列出；读者会混淆这些项目在回答什么时，才增加一句说明。段落数量、长短、项目名位置和收束由当前内容决定。

短内容围绕一条最值得复述的关系压缩场景和判断；长内容可以继续展开机制、例子、反面情况、现实意义和行动框架。篇幅改变展开深度，不改变材料只是事实基础而非表达上限的共同边界。

结尾落在正文已经建立的判断、后果、余味、读者收获或下一步，不因为材料以免责声明、范围限制或保守结论结束就机械复述。面向可访问对象的单对象内容执行上面的指令或链接规则；其它没有可访问对象或行动需要的完整观点可以自然结束。

## 表达自由与作者声音

正文从上层净化后的材料出发，不在动笔时重新展开来源核查。允许口语概括、假设场景、轻微泛化、情绪判断、比喻和有力度的绝对化表达，只要它们服务当前内容。案例可以改变写法和叙事动作；核心能力、精确数字、明确承诺和会改变读者行动的说法由成稿核查决定是否修正。

使用用户在当前任务中的原话、亲自提供或修改的样稿，以及明确可用的长期声音证据。没有声音证据时保持普通直接，不临时编造会改变事实可信度的人设。

第一人称分两类处理：

- “我打开看看”“我把一段素材丢进去”“刷到这个项目时”这类轻量接触动作，可以直接作为叙事进入方式；
- “我连续用了两周”“我测出速度快了三倍”“我亲眼看到某结果”这类具体亲历或证据，可以先完成草稿，成稿核查再判断它是否改变可信度并需要修正。

不要因为第一人称来源于案例就机械弃用整个钩子，也不要用空泛的“我认为”“我最看重”假装作者在场。

## 内容型宣发

本节只在上层已经确认方案或取得直接成文授权时生效。成品数量、主要读者、核心信息、利益领取者、触发动作、有效时间和入口继续有效，案例与钩子不能覆盖。

单篇只生成一个完整正文，多个卖点和角度按主次组织，不自动拆成多条。正文只使用公开成文材料造句；合作来源、发布要求、发布者收入、审核、结算和选材理由只负责内部核对，除非方案明确要求披露。

发布者因发布或邀请得到的返佣不能写成读者优惠，读者利益也不能写成作者收入。CTA 只能要求实际领取者完成对应动作，并让入口、利益、时间和资格一致。只提升认知时可以自然结束。

## 病毒式传播

这是效果目标，不是模板。传播力优先来自“读者一眼能看懂、转述时不用重新解释”的关系：清楚的输入到结果、熟悉阻力被移除、意外演示、现实比较、当前争议、创作者反应或用户自己的说法。写作前搜索用来发现这些关系，完整案例和钩子帮助模型把它们说得更有力度。

允许明确态度、好奇、兴奋、反差、短促节奏和不影响核心理解的表达性误差，不把“客观中立”当作自然写作的默认语气。力度落在具体动作、结果或判断上；第一句可以更锋利，但要由下一句和正文兑现。精确数字、性能、热度、普遍共识和明确承诺如果进入成品，再由成稿核查处理，不在起草时压低全部表达。

## 修改已有正文

只执行已经选定的改写、扩写、压缩、重组或审查后修改。用户明确删除的内容不恢复；只改措辞时不重建整篇结构；对象、角度、核心判断或受众改变时才重组相应部分。保留已经自然、有力和有作者特征的句子。

## 交付

把纯正文交回上层，由上层按照用户的使用方式选择代码块、直接回复或 Markdown 文件。上层先交付成品；除非用户明确只要正文，再用自然语言说明目标与取舍、真正改变讲法的外部材料、多个案例与钩子共同带来的方向，以及没有进入正文的重要技术信息、限制或保守说法，最后列出本次实际阅读的完整案例与钩子文件路径。说明不登记逐项采用或未采用，不建立候选映射、分数、JSON 或检查记录，也不暴露隐藏推理。

## 完成检查

- 成品数量、形态和格式与上层合同一致。
- 第一段具体、有推进，让读者知道这篇在讲什么并愿意继续读。
- 当前材料、多个完整案例与多个钩子示例共同参与写作，没有单一模仿对象。
- 材料中的事实锚点得到保真，正文的场景、判断、组织和结尾又真正服务当前读者，没有退化成逐句释义。
- 创作上下文只包含本篇可能使用的材料，没有混入只供备查的限制和免责声明。
- 普通读者不需要先理解技术实现也能说清问题、结果和下一步行动。
- 提示词只在用户明确要求，或它本来就是正文的主要下一步且比项目入口更能帮助读者完成任务时出现；没有因为 AI 可以代办而机械加入，手动步骤也只在需要时出现。
- 行动入口按正文目的和读者下一步选择：普通介绍、推荐或分享使用项目页面；安装、运行或教程中的直接指令不含完整 HTTP(S) URL，能够独立完成主要动作，并在代码块前说明用途；多步或部分安装使用官方指南或项目页面。项目清单仍保留每项入口。
- 陌生对象出现时关系清楚，同一事实没有换一种说法重复。
- 宣发利益、领取者、动作、时间和入口保持对应。
- 全文离开研究过程也能独立阅读。
- 纯正文已经交回上层；除非用户明确只要正文，上层会附自然语言写作说明和实际阅读路径，但不把它们变成采用证明或内部过程记录。
