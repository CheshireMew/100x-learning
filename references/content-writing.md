# 内容成文

用于把当前材料写成用户要的成品。模型先从完整材料中决定最值得展开的具体角度，再选择分开存放的组件约束实际用到的钩子、承接、正文推进、连接和结尾；组件不替代选题判断，也不提供成品句。相关的真实例子可以帮助表达，没有相关例子时直接不用。

## 写作输入

主流程把真实成文输入按下面顺序放在同一上下文中。专项说明、维护规则、检索过程、覆盖账本和与当前对象无关的旧稿不进入；本次任务的事实来源、用户明确交付的待改正文和来源消化对象仍作为材料使用。模仿例子单独标明职责，不与本轮事实混放。

```text
【用户要求】
<只放用户要生成的成品，以及明确提出的数量、语言、平台、格式、受众、篇幅和必须或禁止出现的内容；能直接摘录时保持原话>

【材料】
<先放用户随请求给出的事实、关系、判断、猜测、问题、角度和内容主次，再按原有边界排列准备后的来源原文与必要上下文>

【当前角度】
<读完全部材料后，写出本篇选择的一个具体细节及其选择理由；只服务内部成文，不作为正文提纲或固定句式>

【结构组件】
钩子：<Hxx 名称，或 USER-H；附该组件的适用条件、必须事实和写法>
承接：<Cxx 名称或 USER-C，并附适用条件、必须事实和职责；没有独立承接时写“未使用”>
正文：<Pxx 名称，或 USER-P；附该组件的适用条件、必须事实和推进关系>
连接：<Bxx 名称或 USER-B，并附真实关系；没有连接句段时写“未使用”>
章节：<文章或 Newsletter 为实际章节逐章写 Sxx 名称或 USER-S，并附推进关系；其它形式写“未使用”>
结尾：<Exx 名称，或 USER-E；附该组件的适用条件、必须事实和停止位置>

用户结构要求：<只列用户明确规定的部分；没有则省略>

【模仿例子】
<只加入经过标题与当前角度语义比较后确实相关的例子；没有相关例子则省略整个区块>
钩子 Hxx：<最多一份完整真实例子；只影响开头怎样进入>
正文 Pxx：<最多一份完整真实例子；只影响正文怎样取舍、推进和控制密度>
结尾 Exx：<最多一份完整真实例子；只影响怎样停笔>
章节 Sxx：<文章或 Newsletter 才加入；每种实际使用的 S 最多一份完整真实例子>

【作者声音】
<只放用户在当前请求中直接提供的声音样稿，或用户明确要求从私人库取得的声音结果；普通写作不自行检索，否则整个区块省略>

按组件分工和模仿例子写成一个可直接使用的成品。模仿例子可以影响句子长短、信息密度、推进速度和停笔方式，但其中的人物、对象、数字、观点、情绪和行动入口不能进入本轮成品。
```

先完整阅读材料并比较可用的具体角度，再确定当前角度和组件。输入中必须有一个 `H`、一个 `P` 和一个 `E`；`C` 与 `B` 只有成品确实写出对应承接或连接句段时才使用，不能为了结构完整而补句。文章与 Newsletter 的每个实际章节使用一个 `S`。组件独立选择，不使用整篇模板、固定套餐、项目类型默认路线或推荐组合。项目介绍与操作演示都可以使用命令、自然语言输入、可见结果或其它受材料支持的开头，由最强具体角度决定。用户明确规定某一部分时只替换对应组件，其余部分仍按实际写法决定是否使用。用户要求多个候选时，为每个候选分别从材料选角度并建立一份输入，不在同一份输入里混放多个钩子、正文或结尾。

私人库可用且模仿可能有帮助时，组件选定后先运行 `python scripts/select_writing_examples.py candidates --form <short|thread|article|newsletter> <Hxx> <Pxx> <Exx> [实际使用的 Sxx...]`，只查看覆盖账本中全部活动候选的标题和来源类型。根据当前角度、对象和目标形态逐项判断相关性；只有某个候选确实能帮助对应部分时，才运行 `python scripts/select_writing_examples.py render --form <形态> <Hxx=source-id> [Pxx=source-id] [Exx=source-id] [Sxx=source-id...]` 读取完整原文。每个组件最多选一份，也可以不选；禁止按列表第一项、篇幅、来源类型或避免重复等固定规则自动决定。承接 `C` 和连接 `B` 不加载模仿例子。实际读取的每份原文完整进入对应模仿区块，候选清单、覆盖账本、选择过程和文件路径不进入成文输入。私人库不可用或没有相关例子时省略相应模仿区块，组件仍只作为职责和推进关系使用。

## 输入边界

用户要求生成、改写或续写什么成品的直接动作和明确硬约束进入用户要求；同一条消息里的对象事实、关系、观点、疑问、猜测、内容主次和角度说明进入材料。用户给出的文字默认是来源材料，不是用户本人写的现稿；其中的第一人称、经历、立场和口吻属于来源作者。只有用户明确说明是本人现稿或声音样稿时，才改变这个默认。

材料中的精确引语、数字、日期、链接、命令和明确归因按来源准确使用。可讨论信息、推断和猜测保持原有确定程度。模仿例子只提供表达和推进感觉，不提供本轮事实、主张、第一人称经历或可复制句子。

组件的“必须事实”只用于判断当前材料是否足以使用这个组件，不转成填空字段。材料仍然完整保留在输入中，由模型按用户目标和所选正文推进方式取舍。第一人称、亲历、测试、时间、数字、引语、因果、比较和最高级必须由当前材料直接支持。

## 模仿成文

先围绕当前角度自然成文，再用 `H → C（可选）→ P → B（可选）→ E` 检查实际职责；长文在 `P` 的全文推进中为实际章节使用 `S`。组件文件不提供可以填空的成品句；模型结合完整材料和确实相关的例子，自行决定句子、段落长度、信息取舍和自然结束位置。同一句或同一段可以承担相邻职责：若 `C` 或 `B` 实际决定了它怎样承接或表达关系，仍列为已使用；若只是直接执行 `P`，没有采用额外承接或连接写法，则写“未使用”。

钩子例子只影响开头，不把它的悬念或夸张带到正文；正文例子只影响信息怎样推进，不把它的题材事实带进来；结尾例子只影响怎样停笔，不强迫当前内容使用 CTA。文章与 Newsletter 的章节例子只影响对应 `S` 的章节内部。不同例子不混成统一口吻，也不要求每个例子留下可辨认痕迹。

用户明确要求多个候选时按要求完整生成；没有指定数量时只生成一个。只改错字、格式和等义措辞时保留现有结构，不重新选组件。`H`、`P` 或 `E` 没有合格组件时不成文，只返回当前缺少的事实；缺少 `C` 或 `B` 不影响成文。

## 成稿核对

完整读一遍成稿，先单独遮住正文检查开头：它是否使用了当前材料中足够具体、值得继续读的细节，而不是只有项目定义、泛泛利益或空悬念。再看钩子承诺是否兑现、正文是否自然推进、实际连接句是否表达真实关系、结尾是否已经停住。随后从最终文字重新确认使用模板：正文每句话都必须符合已选 `P` 的推进关系；如果某段实际采用了另一种 `P` 才定义的推进，删除或重写该段，不能保留混用内容却仍只标原来的 `P`，也不能加第二个 `P`。删除为了凑齐组件而出现的身份句、解释句和过渡句，再删除重复事实、抽象总结、无关条件和从模仿例子带入的题材内容。若一句话能明显还原成“对象 + 动作 + 结果”之类的填空句，保留事实关系，按当前材料重新自然表达。

最后只核对正文实际使用的名称、数字、日期、功能、合作关系、第一人称经历、使用体验、资格、时限和行动入口。来源不支持时修正或移开对应主张，不重写其它句子，不补入成稿没有使用的背景。

## 返回主流程

已经成文时把完整成品和“使用模板”清单一起交回主流程；清单根据核对后的最终文字生成，必须列出 `H`、`C`、`P`、`B`、`S` 和 `E`，实际使用的写 ID 与名称，没有使用的写“未使用”。`H`、`P` 或 `E` 没有合格组件时只交回当前缺少的事实。组件选择、模仿例子、覆盖账本和检查过程默认不展示；用户明确要求查看写作依据或过程时才在正文之后简要说明。
