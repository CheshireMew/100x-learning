# 写作模板目录

这是普通写作唯一使用的结构真源。案例库、钩子库、外部写作范例和与当前对象无关的旧稿都不能代替这里的模板，也不能作为语言参考进入成文输入。本次任务的事实来源、用户明确交付的待改正文和来源消化对象仍然作为材料使用。每篇只选择一个完整模板；钩子、承接、推进、连接和收尾必须来自同一个模板，禁止跨模板拼装。

## 先选模板，再写句子

1. 先按用户要求确定短帖、Thread、文章或 Newsletter。只有用户同时规定了开头或进入方式、紧接开头怎样承接、正文推进顺序、段落怎样连接或明确不加连接，以及停止位置，长文还规定了章节内部写法时，才能把用户结构视为本次唯一完整模板。用户只给出“三段式、先讲功能、结尾放链接”等局部约束时，仍从目录选择一个完整模板，把局部约束记入对应槽位，不能使用 `USER` 绕过其余结构。
2. 只保留满足“适用条件”且“必须事实”齐全的模板。第一人称、亲历、测试、时间、数字、引语、因果、比较和最高级都必须由当前材料支持。
3. 多个模板同时合格时，选择能用最少槽位呈现最强具体事实的一个。工具存在真实输入、处理和输出链时，优先工作流演示；明确发布或更新时优先事实更新；其它情况才使用对象介绍。
4. 选定后先建立槽位绑定。每个必填槽写出对应的材料事实或来源位置；缺少必填槽就换模板，不补故事、痛点、情绪、使用体验、读者心理或价值判断。
5. 正文每句话只能完成模板中的一个槽位。句子无法指回槽位和材料时删除。可选槽没有材料就省略，不用过渡句填空。
6. 一篇只保留一个组织主线，并选一个最值得记住的具体事实作为主证据；其它事实只能支撑同一主线。数字、功能和卖点不为齐全而堆叠。

所有模板共同遵守以下硬边界：

- 钩子只预告正文必定兑现的事实。疑问句必须在正文回答；数量承诺必须逐项兑现。
- 承接句要说清对象、结果或本文问题，不能只宣布重要性。
- 解释之后必须跟具体机制、动作、数字、例子或限制；不能连续两句只谈价值、效率、体验或趋势。
- 连接句只能表达真实存在的因果、时间、条件、分类或范围关系。没有关系就直接进入下一事实。
- 默认在最强事实、可见结果或明确边界处停笔。只有材料含有真实下一步且用户需要宣发、报名、安装或讨论时才使用 CTA。
- 不得用先否定一个宽泛说法、再抬高另一个抽象说法的反转句制造深刻感。只有实验结果确实推翻原判断，或材料本身要求事实分类时，才能写对应的窄范围纠正。
- 不得把项目案例、模板示例或来源作者的经历变成本轮事实或用户经历。

## 短帖与 Thread 模板

Thread 仍只选一个模板。下列每个编号槽在独立短帖中最多两句；在 Thread 中最多展开为两条连续帖文，不得在中途切换模板。

### T01 新近动作

- 适用条件：材料有可识别行动者、新近完成的动作和明确结果。
- 必须事实：`行动者`、`时间状态`、`动作`、`结果`、`一个证明结果的事实`。
- 禁用条件：静态 README、没有时间信息，或只能靠夸张意义才能成立。
- 钩子：`[有人/这个人/行动者]刚刚[完成动作][！/。]`
- 承接：`得到的结果是[可观察结果]。`
- 推进：`他/她/团队先[关键动作一]，再[关键动作二]；[证据]证明结果已经发生。`
- 连接：只有动作之间存在顺序或因果时写 `因为[具体机制]，[前一步]才会得到[后一步]。`
- 收尾：停在 `现在[真实状态或后果]。`；来源链接确实帮助读者核对时放在末尾。
- 删除项：没有证据的最高级痛点、行业级影响、人物心理、读者应当如何理解。

### T02 工作流演示

- 适用条件：材料有真实命令、自然语言输入、输入到输出的操作链，或可以观察的演示。
- 必须事实：`用户输入或动作`、`可见输出`、`二至四个自动步骤`、`一个能力证据`。
- 禁用条件：只有功能清单，没有真实输入和输出关系。
- 钩子：直接写输入，格式为 `你只要说/输入：[原始输入]。`
- 承接：`它会返回/生成[可见输出]。`
- 推进：`中间自动完成[动作一]、[动作二]和[动作三]。` 接着只写一个最能证明能力的数字、格式、模型或结果事实。
- 连接：需要解释时只写 `这一步通过[机制]把[输入]变成[输出]。`
- 收尾：有安装要求时写 `运行需要[条件]：[真实入口]`；否则停在输出或证据。
- 删除项：凭空补用户痛点、效率升华、泛化适用人群、无关功能清单。

### T03 发布或更新

- 适用条件：核心材料是发布、版本更新、数据变化或明确的新事实。
- 必须事实：`谁`、`发布或更新了什么`、`最重要变化`、`直接影响`、`二至三个证据`。
- 禁用条件：没有新变化，或事件时间无法确认。
- 钩子：`[主体]发布/更新了[对象]：[最重要变化]。`
- 承接：`这会直接影响[明确对象]的[具体动作或结果]。`
- 推进：按重要性写二至三个事实，每句一个；不按原文目录顺序复述。
- 连接：限制或条件会改变理解时写 `目前它只在[条件]下成立。`
- 收尾：以使用条件、发布日期或来源结束；不强加讨论问题。
- 删除项：悬念故事、未经证实的未来影响、把普通更新拔高成行业转折。

### T04 对象亮相

- 适用条件：读者需要先知道一个项目、工具、作品或概念是什么，且材料有清楚定位和真实能力。
- 必须事实：`对象名`、`一句定位`、`核心动作`、`可见结果`、`一个区别性事实`。
- 禁用条件：材料主要是更新、实测、争议或教程；这些应选相应模板。
- 钩子：`[对象名]是一个能[核心动作]的[准确类别]。`
- 承接：`给它[输入或条件]，会得到[结果]。`
- 推进：先写工作方式，再写一个区别性事实；最多补一个适用场景。
- 连接：只有定位可能被单项功能误解时写 `它还包括[决定对象身份的能力范围]。`
- 收尾：普通介绍停在最具体的结果；需要访问时只留一个真实入口。
- 删除项：口号替代能力、虚构体验、把单项演示改写成全部产品定位。

### T05 问题到机制

- 适用条件：材料有一个可回答的问题，以及足以回答它的机制或证据链。
- 必须事实：`具体问题`、`窄答案`、`二至四步机制`、`一个证据或例子`、`成立条件`。
- 禁用条件：答案只是观点，或因果链缺证据。
- 钩子：`[具体问题]？`
- 承接：`答案是[窄答案]。`
- 推进：按 `条件 → 动作或变化 → 中间结果 → 最终结果` 写机制，再放一个例子或数字。
- 连接：`只有在[条件]下，这条链才成立。`
- 收尾：回到开头问题，写比开头更精确的一句答案。
- 删除项：另造第二个问题、用类比代替机制、把相关性写成因果。

### T06 同维度比较

- 适用条件：材料同时提供 A、B 和至少一个共同评价维度。
- 必须事实：`A`、`B`、`共同维度`、`双方事实`、`选择条件`。
- 禁用条件：只有单方资料，或双方数据口径不同且无法校正。
- 钩子：`在[共同任务]上，[A]和[B]的差别集中在[维度]。`
- 承接：直接给双方在该维度上的事实，不先造共识或稻草人。
- 推进：每段只比较一个维度，顺序固定为 `标准 → A → B → 本维度结论`；最多三个维度。
- 连接：维度切换时写明 `换到[新维度]，[事实关系]。`
- 收尾：`需要[条件一]选[A]；更看重[条件二]选[B]。`
- 删除项：跨维度下总排名、无证据输赢、为了反转制造旧认知。

### T07 有证据的问题—解决

- 适用条件：材料明确记录真实用户场景、具体问题、一个可核实后果和解决机制。
- 必须事实：`场景`、`问题`、`后果`、`解决动作`、`机制证据`。
- 禁用条件：问题来自模型猜测，或只有产品功能没有用户问题证据。
- 钩子：`在[具体场景]里，[角色]会遇到[可观察问题]。`
- 承接：`它会导致[一个可核实后果]。`
- 推进：`[产品或方法]通过[机制]处理这个问题；[证据]显示该机制已经工作。`
- 连接：只有限制会改变适用范围时写 `它目前不能处理[明确边界]。`
- 收尾：宣发任务才给真实行动入口；普通分享停在机制证据。
- 删除项：情绪加剧、泛化痛点、替读者编造焦虑或犹豫。

### T08 实测纠正

- 适用条件：材料有原判断、真实测试方法、结果，以及结果造成的判断修正。
- 必须事实：`异常或原判断`、`测试方法`、`测试结果`、`修正后的判断`、`下一动作或边界`。
- 禁用条件：没有实际测试，或多个变量无法区分却声称找到唯一原因。
- 钩子：`我注意到[异常]，原先以为原因是[原判断]。`
- 承接：`我用[方法]测了[对象]，结果是[结果]。`
- 推进：写清改动变量、观察值和原判断为何被推翻；一次只处理一个主要变量。
- 连接：`这个结果把问题缩小到[新变量或范围]。`
- 收尾：`下一次我会[具体动作]；目前还不能确认[未知]。`
- 删除项：把单次结果推广成普遍规律、虚构测试、抽象经验升华。

### T09 清单或资源

- 适用条件：材料有同一任务下的多个对象和明确选择标准。
- 必须事实：`读者任务`、`数量`、`共同标准`、`每项的用途和区别`。
- 禁用条件：对象只是凑数，或无法用同一标准说明。
- 钩子：`做[任务]，这[N]个[对象类别]分别解决[共同问题]。`
- 承接：一句写选择标准。
- 推进：严格重复 `名称 → 用途 → 一项具体特点 → 一项限制或适用条件`；承诺几项就写几项。
- 连接：条目之间不用总结性过渡。
- 收尾：只给一个最小选择建议或资源入口，不重抄清单。
- 删除项：每项使用不同广告句、无依据排名、在末尾追加泛化价值。

### T10 真实事件或微叙事

- 适用条件：材料有真实人物或主体、时间顺序、阻碍、关键动作和结果。
- 必须事实：`具体时刻或场合`、`动作`、`阻碍或变化`、`关键决定`、`结果`。
- 禁用条件：静态项目介绍，或需要模型补人物心理、对话、天气和现场细节。
- 钩子：`[时间或场合]，[人物/主体][具体动作]。`
- 承接：`随后发生了[阻碍或变化]。`
- 推进：按时间只写关键动作和状态变化，最多两个转折。
- 连接：`到[时间点]，[前一状态]变成[新状态]。`
- 收尾：回扣开头对象的最终状态，或停在事件后果。
- 删除项：旁观者反应、心理描写、英雄化意义，除非来源明确提供。

## 文章与 Newsletter 模板

长文也只选一个模板。开头到第一个正文标题最多三个普通段落；每个章节只选择模板规定的一种章节块，每个段落只承担主张、证据、解释、例子、边界或动作中的一种功能。小标题直接写本节对象，禁止装饰性标题。逻辑结尾完成后，Newsletter 才能按模板允许情况追加一个 CTA 页脚。

### A01 长教程

- 适用条件：作者或来源已经完成一条可复现操作链。
- 必须事实：`完成结果`、`适用环境`、`前提`、`有顺序的步骤`、`每步可见结果`、`最终验收`。
- 钩子：`已经完成[可见结果]。下面按[环境]讲清楚怎样从[起点]做到[终点]。`
- 承接：写适用对象、前提和不覆盖的范围。
- 全文推进：`结果与环境 → 前提 → 三至八个步骤章节 → 完整链路验收 → 已知失败与恢复 → 下一步`。
- 章节块：每节固定写 `本步目标 → 准确动作或命令 → 预期可见结果 → 已知失败 → 已验证恢复办法`；后两项没有材料就省略。
- 章节连接：只有前一步结果是下一步前提时写 `确认[阶段结果]后，再处理[下一问题]。`
- 收尾：用三项以内的执行前检查，或写当前已完成状态和真实下一步。
- 禁止：没有验收结果的步骤、未经核验的命令、把未完成产品写成完整教程。

### A02 主张论证

- 适用条件：材料有明确主张、机制、证据或例子，并有反方、例外或适用边界。
- 必须事实：`主张`、`关键概念`、`形成机制`、`证据或例子`、`反方或边界`。
- 钩子：直接给主张，或提出正文能够回答的窄问题。
- 承接：在两段内说明本文讨论什么、为什么值得读，以及会用什么证据回答。
- 全文推进：`主张 → 定义 → 机制 → 例子或证据 → 反方或例外 → 收窄边界 → 回到主张`。
- 章节块：每节固定写 `本节窄结论 → 理由 → 一个证据或例子 → 一个限制 → 比开头更窄的结论`。
- 章节连接：只用解题顺序、证据修正或适用条件连接；下一节必须回答上一节留下的必要问题。
- 收尾：`在[条件]下，结论是[开头主张的窄版本]；超出该条件，不能推出[过度结论]。`
- 禁止：只摆正方材料、每节换词重复主张、结尾升级成更大的命题。

### A03 项目或实验复盘

- 适用条件：材料来自真实实施过程，并记录选择、问题、改动和结果。
- 必须事实：`原目标`、`初始选择及原因`、`实际实施`、`至少一个问题`、`改动`、`当前结果`、`重做选择`。
- 钩子：`这次[实验或项目]原本要[目标]，最终[失败或部分结果]。`
- 承接：写仍值得复盘的具体发现，不把失败当人格表演。
- 全文推进：`原目标 → 初始选择 → 实施 → 问题 → 修改 → 新问题或结果 → 当前状态 → 重做选择`。
- 章节块：每轮固定写 `本轮假设 → 改了什么 → 测到什么 → 保留或推翻什么 → 下一轮改什么`。
- 章节连接：只有结果确实改变判断时写 `这个结果把下一轮范围缩小到[变量]。`
- 收尾：`如果再做一次，我会[具体改变]，因为这次已经证明[证据]。`
- 禁止：虚构失败、多个变量混在一起却声称找到原因、抽象经验教训。

### A04 分层机制解释

- 适用条件：需要解释一个概念、系统或现象如何工作，材料能支持逐层机制。
- 必须事实：`核心问题`、`基础概念`、`机制层`、`例子或数量级`、`应用或后果`、`失效条件`。
- 钩子：提出核心问题；有可靠事件现场时也可用 `时间/场合 → 动作 → 结果` 开场。
- 承接：直接给窄答案，并列出回答必须先弄清的下位问题。
- 全文推进：`问题 → 起点或定义 → 逐层机制 → 例子或数量级 → 现实应用 → 失效条件或风险`。
- 章节块：机制节写 `本层作用 → 输入 → 变化过程 → 输出 → 限制`；比较节写 `标准 → A → B → 本标准结论`。
- 章节连接：`要回答[总问题]，先要弄清[必要的下位问题]。`
- 收尾：回到开头问题，给带条件的答案；不把类比当结论。
- 禁止：同一概念重复解释、类比代替证据、无来源因果。

### A05 长时间线叙事

- 适用条件：材料有按时间排序的事件、至少两个转折和明确结果。
- 必须事实：`现场起点`、`背景`、`转折一`、`转折二`、`决定性动作`、`结果`、`后续影响`。
- 钩子：`[日期或年份]，在[地点或场合]，[人物或双方][关键动作]。`
- 承接：写现场结果以及它与全文问题的关系。
- 全文推进：`现场 → 必要背景 → 第一次转折 → 冲突升级 → 决定性动作 → 结果 → 后续影响 → 当前回望`。
- 章节块：每节固定写 `时间或地点 → 动作 → 障碍 → 决定 → 新状态`，只承载一个主要转折。
- 章节连接：用真实时间点或状态变化连接。
- 收尾：回扣开头人物、物件或场景的最终状态，再写有来源的长期后果。
- 禁止：补人物内心、虚构对话或场景细节、另开无关技术主线。

### A06 来源消化型文章或 Newsletter

- 适用条件：材料来自明确文章、访谈、播客、视频或一组来源，作者有真实筛选判断。
- 必须事实：`来源`、`为何选择`、`主题化分组`、`来源观点和证据`、`作者接受或质疑的部分`、`读者可用结果`。
- 钩子：`我读/听/看了[来源]，其中最值得留下的是[具体问题或发现]。`
- 承接：说明来源原主题和作者真正关注点。
- 全文推进：`来源与选择理由 → 按主题而非原顺序展开三至七节 → 每节来源观点、证据、作者判断 → 可执行提取`。
- 章节块：每节固定写 `来源提出什么 → 用什么证明 → 作者接受或质疑哪一部分 → 对读者的具体用途`。
- 章节连接：只有主题存在依赖时说明；否则直接换到明确的小标题。
- 收尾：留下三项以内会改变行动的提取；Newsletter 可在逻辑结尾后追加一个订阅或合集入口。
- 禁止：把来源观点写成作者亲历、沿原文顺序逐段摘要、用长引语代替处理、同时放多个 CTA。

### A07 带判断的工具目录

- 适用条件：同一任务下至少有两个工具，材料支持统一选择标准、具体优点和限制。
- 必须事实：`读者任务`、`选择标准`、`每项用途`、`每项优点`、`每项限制`、`适用对象`。
- 钩子：`做[任务]，我按[标准]筛了这[N]个工具。`
- 承接：说明选择标准和是否来自亲测；没亲测就明确是资料筛选。
- 全文推进：`任务 → 标准 → 重复工具章节 → 同维度比较 → 最小建议`。
- 章节块：每项固定写 `工具名 → 用途 → 一项具体优点 → 一项具体限制 → 适合谁或链接`。
- 章节连接：条目之间不用修辞过渡；比较时只在同一维度内连接。
- 收尾：留下按条件选择的建议和一个资源入口。
- 禁止：把官方文档写成亲测、忽略限制、实时功能不核验、为了整齐使用空洞广告句。

### A08 周期复盘

- 适用条件：材料有明确时间范围、多个领域的行动与结果，以及下一周期目标。
- 必须事实：`周期`、`总判断`、`各领域行动`、`结果或数字`、`失误`、`留下的东西`、`下一周期目标`。
- 钩子：`[周期]结束了。最准确的总结是[有事实支撑的总判断]。`
- 承接：说明复盘覆盖哪些领域，不提前宣布成长或意义。
- 全文推进：每个领域固定重复 `做了什么 → 结果或数字 → 哪里失误 → 留下什么`。
- 章节块：一节只写一个领域，事实和判断分开。
- 章节连接：领域之间直接用对象小标题，不写统一升华。
- 收尾：`下一周期只做[N]件事：[目标]。` 目标必须由正文推出。
- 禁止：把所有事件包装成成长、目标不断扩张、用祝福替代结果。

### A09 事实说明

- 适用条件：用户明确需要文章或 Newsletter，但材料主要是对象事实、能力范围或当前状态，不足以支持教程、论证、复盘、叙事或来源消化。
- 必须事实：`对象`、`准确定位`、`三至五组不同事实`、`每组事实的证据或可见结果`、`至少一个适用条件或限制`。
- 钩子：`[对象]是[准确定位]，当前可以[最具体的能力或状态]。`
- 承接：在两段内说明本文覆盖哪些事实，以及不讨论什么。
- 全文推进：按读者理解对象所需的顺序展开三至五节，每节只处理一组事实；不把规格目录原样搬进正文。
- 章节块：每节固定写 `本节对象 → 事实 → 证据、机制或可见结果 → 适用条件或限制`。
- 章节连接：只有后一组事实依赖前一组时说明关系；否则直接使用对象小标题进入下一节。
- 收尾：停在当前状态、最重要限制或一个真实使用入口，不总结对象的宏大价值。
- 禁止：用材料数量硬撑篇幅、把官方口号当事实、从静态能力推演用户痛点或未来影响。

## 成稿机械检查

- 已写明模板 ID，且只有一个。
- 每个必填槽都有材料绑定；正文没有模板外句子。
- 开头承诺、数量、问题和结果均已在正文兑现。
- 每个解释后都有具体事实；相邻句段没有重复同一结论。
- 第一人称、亲测、时间、数字、引语、因果、比较和最高级都能回到当前材料。
- 结尾使用该模板规定的停止点；没有无来源升华、假想读者心理或无任务 CTA。
- Thread 没有中途换模板；长文每个章节都符合指定章节块，Newsletter 最多一个主要 CTA。
- 没有任何同形态模板满足必填事实时不跨形态回退，也不勉强成文；直接指出当前格式缺少的最小事实集合。
