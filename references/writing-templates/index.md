# 组件写作模板索引

这是普通写作唯一使用的结构真源。模板按实际职责分开保存，任何一篇成品都分别选择一个钩子、承接、正文推进、连接和结尾；文章与 Newsletter 还为每个章节选择章节块。目录不提供预先绑定的整篇路线，也不提供“推荐组合”。

## 目录

- `hooks/`：`H01`—`H23`，只决定第一击怎样进入内容。
- `continuations/`：`C01`—`C12`，只决定钩子后的第一步怎样落地。
- `bodies/`：`P01`—`P24`，只决定正文事实怎样推进。
- `bridges/`：`B01`—`B16`，只表达材料中真实存在的句段关系；没有关系时使用 `B01` 直接切换。
- `endings/`：`E01`—`E18`，只决定在哪里停笔。
- `sections/`：`S01`—`S09`，只用于文章或 Newsletter 的章节内部。

每个编号单独存放在同名 Markdown 文件中。普通成文完整读取本索引，再只打开候选组件文件；维护侧另有逐来源证据账本，不进入成文输入。

## 独立选模顺序

1. 根据用户要求的成品目的和当前材料，分别筛选 `H`、`C`、`P`、`B`、`E`；长文再筛选 `S`。每个组件只看自己的“适用条件”和“必须事实”，不能因为另一个组件合格就放宽条件。材料里存在某种句式素材，不等于用户本次要用这种进入方式。
2. 每类只选一个。连接允许选择 `B01`；长文可以让不同章节各选一个 `S`，但每个章节仍只能使用一个章节模板。
3. 用户明确规定某一部分时，只把这一部分记为 `USER-H`、`USER-C`、`USER-P`、`USER-B`、`USER-E` 或 `USER-S`，其它部分仍从对应目录独立选择。用户没有规定的内容不能从局部要求中推断。
4. 选择后逐个绑定必填槽。缺少必填事实就换同类组件；某一必需类别没有任何合格组件时不成文，只指出缺少的最小事实。
5. 组件可以自由组合，但不能自由补内容。组合后若出现承接重复钩子、正文重复承接、连接虚构关系或结尾另起新主张，重新选择造成重复的那个组件。
6. 一篇只保留一个主要对象或问题、一个正文推进方式和一个停止点。模板分开不等于把多个正文骨架拼在一起。

项目短内容还有一条硬限制：用户要的是“吸引人的项目短内容”、项目介绍或宣传短帖，而不是操作演示时，README 中的一条命令或自然语言示例不能让 `H23` 合格。此时先按各自条件判断材料能否填满 `H01` 的具体直接利益或 `H02` 的可见结果；两者都不合格时继续筛选其它钩子，不能退回 `H23`。`H03` 仍须同时具备可识别行动者、新近状态、具体动作和已发生结果。这个限制只筛钩子，不指定承接、正文、连接或结尾。

同一目的也不能让 `P01` 合格。项目介绍已经在钩子或承接给出主结果或利益，且材料还有二至四项不同的具体证据与至少一个条件或边界时，按 `P24` 自身条件判断它是否合格；不合格就继续筛选其它正文模板，不能退回 `P01` 重播命令、输出和自动步骤。这个限制只筛正文，不指定钩子、承接、连接或结尾。

## 组合次序

短帖与 Thread：

```text
H → C → P → B（0—2 次，按真实关系出现）→ E
```

文章与 Newsletter：

```text
H → C → P（全文推进）→ 每章一个 S → B（章节之间按真实关系出现）→ E
```

`B` 只在两个已写事实之间使用，不能单独制造内容。`S` 只规定章节内部，不能替代全文 `P`。Newsletter 的订阅、报名或链接动作只有材料中存在真实入口且用户需要时才可使用相应 `E`。

## 共同事实边界

- 第一人称、亲历、测试、时间、数字、引语、因果、比较、预测和最高级必须由当前材料直接支持。
- 钩子的疑问、数字、冲突、结果和信息缺口必须由后文实际兑现。
- 模板只提供句法和关系，不能提供本轮人物、痛点、情绪、体验、意义、读者心理或行动入口。
- 同一句不能同时承担两个组件的必填槽。解释句若没有机制、动作、数字、例子或限制支撑，就不写解释。
- 案例、钩子和覆盖账本只用于维护模板，不为本轮提供事实或措辞。

## 默认交付

完整成品之后始终附上实际使用的模板，不需要用户另问：

```text
使用模板：
钩子：Hxx 名称
承接：Cxx 名称
正文：Pxx 名称
连接：Bxx 名称（没有连接句也要写 B01 直接切换）
章节：Sxx 名称（非长文写“无”）
结尾：Exx 名称
```

用户直接规定的部分写对应 `USER-*`，并用不超过十个字说明。这里公开的是模板编号和名称，不公开槽位绑定、检查清单或隐藏推理。
