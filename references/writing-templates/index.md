# 组件写作模板索引

这是普通写作的独立组件目录。任何一篇成品都分别选择一个钩子、承接、正文推进、连接和结尾；文章与 Newsletter 还为每个章节选择章节块。组件决定每个部分承担什么职责，私人库中的完整真实例子帮助模型模仿对应部分的自然表达。目录不提供预先绑定的整篇路线，也不提供“推荐组合”。

## 目录

- `hooks/`：`H01`—`H23`，只决定第一击怎样进入内容。
- `continuations/`：`C01`—`C12`，只决定钩子后的第一步怎样落地。
- `bodies/`：`P01`—`P24`，只决定正文事实怎样推进。
- `bridges/`：`B01`—`B16`，只表达材料中真实存在的句段关系；没有关系时使用 `B01` 直接切换。
- `endings/`：`E01`—`E18`，只决定在哪里停笔。
- `sections/`：`S01`—`S09`，只用于文章或 Newsletter 的章节内部。

每个编号单独存放在同名 Markdown 文件中。普通成文完整读取本索引，再只打开候选组件文件；逐来源覆盖账本由取例工具读取，不直接进入模型的成文输入。

## 独立选模顺序

1. 根据用户要求的成品目的和当前材料，分别筛选 `H`、`C`、`P`、`B`、`E`；长文再筛选 `S`。每个组件只看自己的“适用条件”和“必须事实”，不能因为另一个组件合格就放宽条件。材料里存在某种句式素材，不等于用户本次要用这种进入方式。
2. 每类只选一个。连接允许选择 `B01`；长文可以让不同章节各选一个 `S`，但每个章节仍只能使用一个章节模板。
3. 用户明确规定某一部分时，只把这一部分记为 `USER-H`、`USER-C`、`USER-P`、`USER-B`、`USER-E` 或 `USER-S`，其它部分仍从对应目录独立选择。用户没有规定的内容不能从局部要求中推断。
4. 选择后逐个确认当前材料具备“必须事实”。缺少事实就换同类组件；某一必需类别没有任何合格组件时不成文，只指出缺少的最小事实。
5. 为选中的 `H`、`P`、`E` 和长文实际使用的 `S` 分别取得一份完整真实例子。例子只影响对应部分的表达，不提供本轮事实，也不绑定成推荐组合。
6. 组件可以自由组合，但不能自由补事实。组合后若出现承接重复钩子、正文重复承接、连接虚构关系或结尾另起新主张，重新选择造成重复的那个组件。
7. 一篇只保留一个主要对象或问题、一个正文推进方式和一个停止点。模板分开不等于把多个正文推进方式拼在一起。

项目介绍或宣传短帖优先用 `H01` 的具体利益、`H02` 的可见结果，或其它符合当前材料的介绍型钩子。`H23` 留给操作演示、教程和命令讲解；`H03` 留给同时具备行动者、新近状态、具体动作和已发生结果的内容。钩子选完后，其它组件仍各自判断。

项目介绍已经在钩子或承接写出主结果或利益，材料另有二至四项不同证据时，可以选择 `P24` 继续展开。`P01` 留给操作演示、教程、命令讲解和具体工作流说明。正文选完后，承接、连接和结尾仍各自判断。

## 组合次序

短帖与 Thread：

```text
H → C → P → B（0—2 次，按真实关系出现）→ E
```

文章与 Newsletter：

```text
H → C → P（全文推进）→ 每章一个 S → B（章节之间按真实关系出现）→ E
```

`B` 只在两个已写事实之间使用，不能单独制造内容。`S` 只规定章节内部，不能替代全文 `P`。Newsletter 的订阅、报名或链接动作只有材料中存在真实入口且用户需要时才可使用相应 `E`。

## 共同事实边界

- 第一人称、亲历、测试、时间、数字、引语、因果、比较、预测和最高级必须由当前材料直接支持。
- 钩子的疑问、数字、冲突、结果和信息缺口必须由后文实际兑现。
- 组件只提供职责、推进关系和停止位置，不能提供本轮人物、痛点、情绪、体验、意义、读者心理或行动入口。
- 组件文件不提供带方括号的成品句或其它填空格式。模型结合当前材料和对应的完整真实例子，自然决定具体句子；事实和观点仍只来自当前材料。
- 条件、限制、反方、未知、安装和兼容信息只有在用户关心，或确实会改变正文主张和读者行动时才写；它们不负责让内容显得完整。
- 解释句若没有机制、动作、数字或例子支撑，就不写解释。
- 模仿案例和钩子只影响所对应组件的表达，不为本轮提供事实或可复制句子；覆盖账本只用于取例和维护。

## 默认交付

完整成品之后始终附上实际使用的模板，不需要用户另问：

```text
使用模板：
钩子：Hxx 名称
承接：Cxx 名称
正文：Pxx 名称
连接：Bxx 名称（没有连接句也要写 B01 直接切换）
章节：Sxx 名称（非长文写“无”）
结尾：Exx 名称
```

用户直接规定的部分写对应 `USER-*`，并用不超过十个字说明。这里公开的是模板编号和名称，不公开模仿例子、检查过程或隐藏推理。
