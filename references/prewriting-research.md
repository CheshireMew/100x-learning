# 写作前素材发现与净化

用于所有新写、扩写和实质重组。这个阶段的任务是找到更多能够让内容具体、有现实感、有传播力的材料，再把真正适合公开成文的部分交给写作者；它不在动笔前逐项证明资料是否准确。只做错字、格式、等义压缩，或者用户明确只用给定材料时，不额外联网；信息来源受限不等于成品只能复述材料原句和原意，除非用户同时明确要求忠实摘要或不作推断。

用户明确要研究、判断或事实核查时，由上层进入独立研究路线。只要最终结果是写作，无论题材、篇幅和风险高低，都沿“发现材料 → 净化材料 → 围绕具体关系成文 → 核查成品”的顺序执行。

上层已经把输入区分为当前正文、必须保留的内容、为新稿提供事实与场景的材料，以及明确选择的创作参考。本阶段只处理已经被判定为材料的部分：即使它是一篇完整营销稿，也只提取本篇可能使用的动作、结果、演示、比较、反应和自然说法，不把原稿的段落顺序交给写作者。当前动作是改写、扩写、压缩或重组时，原正文继续由成文阶段按用户要求处理；本阶段只补充和净化新增材料，不用资料结构覆盖原正文。

交给写作者的材料同时保留两层信息：直接引语、数字、身份、事件和关键关系构成事实锚点；追问与回避、期待与落差、前后变化和可见结果构成可供成文的场景关系。写作者可以概括材料能够支持的关系，但不能把推断伪装成来源明确陈述的事实。字幕和访谈按完整互动恢复这些关系，不把每条时间片依次改写成正文。

## 搜索是为了增加可写内容

先快速打开用户给出的对象、页面或材料，避免认错主题，并看见最直观的动作、结果和入口。随后从官网、官方仓库、文档、Release、演示、媒体、KOL、创作者、真实用户、Issue、Discussion、论坛和社区讨论中寻找：

- 能一眼看懂的输入、动作和结果；
- 真实演示、使用瞬间、前后变化和意外画面；
- 人们怎样描述问题、收益、比较和替代选择；
- 比官方定位更自然、更容易复述的说法；
- 能够改变选材和读者关系的反应或争议；
- 当前内容真正需要的故事、例子、数字和必要解释。
- 项目主页、仓库、安装指南、原样候选命令，以及每个入口实际完成的动作和必要前置步骤；
- 用户明确要求提示词，或本篇的主要下一步本来就是把一个明确任务交给 AI 时，AI 能否直接完成该任务，以及形成一至三句提示词所需的目标、必要边界和完成依据。

官方来源和外部来源都是候选素材。官方材料常提供直接动作、演示、项目说法和入口；媒体、创作者和用户材料常提供现实场景、比较、反应与自然语言。写作前不建立“官方负责证明、外部负责润色”的等级，也不为了确认 README 的每一句话继续搜索。

根据对象使用中英文自然查询。GitHub 项目可以组合：

```text
项目名 + demo / review / tutorial / use case / tried / alternative
项目名 + 体验 / 实测 / 演示 / 教程 / 问题 / 替代 / 对比
项目名 + GitHub Issue / Discussion
项目名 + Reddit / Hacker News / X / YouTube / Bilibili
核心结果或痛点 + 项目名
```

查询只负责发现入口。打开真正有用的原文、帖子、视频说明或转录、讨论串和评论上下文；搜索摘要、转帖标题和自动摘要不代替原内容。来源身份不决定是否保留，信息增量才决定：新来源能够增加一个场景、演示、比较、反应、说法或传播入口时继续；开始重复时停止。没有固定来源数量，外部内容少时也不强行凑。

## 在写作前净化材料

搜索得到的是候选材料，不是写作者必须看完的资料包。交给写作的内容只保留：

- 本篇最值得讲的一项变化、判断或场景；
- 能把这项变化写具体的动作、结果、演示、数字和自然说法；
- 材料中可以支撑场景重构和作者判断的互动与上下文关系；
- 媒体、创作者或用户内容中真正改变讲法的相关上下文；
- 读者理解核心关系所需的少量机制；
- 用户明确要求必须写入或逐字保留的内容；
- 当前成品确实需要的利益、时间、必要条件和行动入口。

下面这些内容留在搜索记录和来源页面中，不进入创作上下文：

- 官方免责声明、责任声明和合规套话；
- “最终仍需自行判断”“结果不保证可用”等通用提醒；
- 与当前角度无关的额度消耗、人工审查、风险和限制；
- README 的完整功能清单、路线图、开发状态和边缘 Issue；
- 价格、许可证、平台、兼容性、API Key、硬件、版本和运行条件等只供备查的信息；只有省略会让本篇核心说法或主要行动明显失真，或用户正在评估这些问题时，才交给写作；
- 只准备在成稿后核对、但不准备写入正文的技术信息；
- 为了显得全面、平衡或稳妥而保留的无关事实。

剔除发生在材料进入创作上下文之前。不能一边标注“只供备查”，一边继续把原文、摘要或限制清单交给写作者。对应来源链接继续留在当前任务中，只有成稿实际使用相关主张时才重新打开核查。

命令按官方原文作为候选保留，同时记录它是否包含完整 HTTP(S) 地址、实际完成哪一步、是否依赖尚未完成的前置步骤，以及官方是否另有更适合普通读者的项目页或安装页。多步安装不自行压成单行，本阶段也不根据命令外形替正文选择最终入口。提示词不是固定素材：用户明确要求，或正文已经选定“把明确任务交给 AI”作为主要下一步时，才判断 AI 能否操作目标环境并完成核心动作，并提供任务目标、必要上下文、边界和验收依据；不能因为项目与 AI 有关或 AI 理论上能够代办就自动准备提示词。

## 选择传播关系

先用普通话想清三件事：读者最先应该看见什么变化；什么动作、结果或反应最容易让它变得具体；内容说到哪里已经足够。

从材料中确定一项普通读者能够理解并准确转述的具体关系，记录支持它的动作、结果、原话或比较，并说明它为什么与目标读者有关。找不到这三部分时继续寻找材料或收窄主张，不用抽象评价或预设句式补空白。数字、性能、热度、普遍共识和明确承诺如果最终进入正文，再在成稿后核查。

面向普通读者时，优先保留能直接感受到的变化，其次保留让变化具体的产物、演示或反馈。组件、工作流、数据结构、模型名、文件格式和完整步骤只有确实帮助理解或选择时才进入。价格、许可证、平台、兼容性和运行环境不会因为信息真实、部分读者可能关心或适合放在结尾就进入正文；只有省略会让核心说法或主要行动明显失真，或用户正在评估这些问题时才保留，不能在结尾合并成一组限制说明。

## 交给写作的内容

把净化后的材料作为自然上下文交给写作者，不预写固定开头，不整理成事实表、评分表或候选状态：

- 当前对象、读者、作者位置和写作目标；
- 本篇最值得讲的变化、场景或判断；
- 可以直接用于正文的动作、结果、演示、比较和说法；
- 必须保真的事实锚点，以及能够支撑场景、作者判断和读者价值的材料关系；
- 真正改变讲法的媒体、KOL、创作者或用户上下文；
- 用户必须保留的文字、格式和行动要求；
- 已核实的项目主页、仓库、安装指南和原样候选命令，以及各自完成范围与前置步骤；已经选定提示词作为主要下一步时所需的材料；
- 本次实际打开的外部来源链接，供成稿后按需核查和最终说明。

第一人称经历只在当前作者材料明确提供时进入写作输入。案例或外部来源中的接触动作、测试次数、使用时长、性能数字和亲历结果仍属于原作者，不能移植给当前作者；最终写入的相关事实由成稿核查处理。

内容型宣发仍需在成文前知道用户明确给出的成品数量、利益领取者、触发动作、有效时间和真实入口，因为它们决定要写什么，而不是为了提前证明它们是否真实。合作、审核、结算和发布者收入等内部信息不进入公开写作材料；用户同时要求核查时，作为独立结果处理。
