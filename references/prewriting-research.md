# 写作前材料发现与净化

用于在正式成文前补充真实材料并完成删除式净化，再把净化后的来源原文交给主文件组成唯一一份“写作准备材料”。

## 默认搜索

新写、扩写、改写和实质重组默认搜索外部资料。用户明确禁止联网、要求只使用给定材料，或只改错字、格式和等义措辞时不搜索，直接净化现有材料。

先打开用户给出的对象、页面或原始材料，确认主题和上下文。随后从官网、仓库、文档、演示、媒体、创作者、真实用户、Issue、Discussion、论坛和社区讨论中寻找能增加创作可能性的原文，例如具体动作、结果、场景、机制、比较、反应、实际步骤和自然说法。搜索结果只用于发现入口，实际使用前打开原文或完整上下文；新来源不再增加可写内容时停止，不按固定数量凑资料。

GitHub 项目可以查看演示、真实体验、替代方案、Issue、Discussion 和社区讨论。行动入口、安装步骤、报名时间、价格、兼容性或提示词只在当前成品确实需要时补充。搜索不负责预选角度、中心、主线、段落或结尾。

## 删除式净化

用户材料和搜索结果都作为候选材料。净化只删除不适合当前成品、重复或会误导创作的内容；其余内容继续保持来源原文、原有顺序、来源边界和必要上下文，不摘要、转述、重排、拼接、统一改写或合并成简报。

用户明确要求保留的内容继续保留。专业词、数字、日期、限制、原话和事实关系按来源保存；一个事实依靠前后条件、参与者、原因或结果才能成立时，把这段关系完整留下。不同来源保持分开，来源链接紧跟对应原文。

净化阶段不选择核心关系，不预设正文角度，也不根据一个预先选出的中心删除其它仍可能服务成品的材料。模型在正式写作时自行决定哪些信息进入正文。

通常可以删除与当前请求无关的官方套话、重复说明、完整路线图、边缘功能、内部过程、候选评分、检索记录和事实核查清单。价格、许可证、平台、兼容性、版本和运行条件是否保留，只看它们是否可能影响当前成品的理解或行动，不建立固定字段。

字幕、访谈和会议记录先恢复谁在回应什么、前后关系怎样变化，再保留相关连续原文；时间切片顺序不等于正文顺序。

## 交出净化后的材料

净化结束后，把仍保留的来源原文、来源边界、必要上下文和对应链接交给主流程。这里不加入写作建议、事实分类、中心句、段落任务或材料说明；主流程随后使用唯一的写作准备材料模板加入用户要求和通用写作注意。

主文件组成完整准备材料后第一次保留；完整案例和钩子读完后、正式写作指令出现前，再把完整准备材料原样放一次。最终回答只展示一次完整版本。
