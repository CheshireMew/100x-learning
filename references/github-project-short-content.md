# 单个 GitHub 项目介绍写作模板

用于把一个已经研究清楚的 GitHub 项目写成普通读者可以直接看懂、愿意继续读的独立短内容。本模板只负责写法，不负责研究项目、盘点源码或补齐功能。

## 进入与停止

上层已经选定“单个 GitHub 项目介绍”时进入，并提供这次是介绍、推荐、分享、续写、评测还是比较。项目数量和成品形态已经在进入本模板前确定，本模板不改成项目清单。

读者已经知道这个项目最特别的变化、它大致能帮谁做什么，并获得真实入口后立即收束。正文不因为 README 还有更多功能而继续展开。

## 写作输入

上层提供：

- 已经选定的表达任务；介绍、推荐或分享默认是正面介绍，评测和比较使用对应任务；
- 写作前联网研究交来的精选材料包；
- 已经从作者位置、目标读者、用户材料和精选网络材料想清的本次讲法；
- 当前读者、作者声音和发布要求；
- 已经核实的项目名、来源怎样说明它是什么、主要用途、直接动作与作用对象、经过真实使用信号筛选后最值得传播的变化、能把这项变化写具体的事实和真实入口；
- 用户、官方来源或真实使用材料采用的任务名称和受众说法；没有现成说法时可直接写出的具体动作；
- 当前材料确实具备的痛点、规模、前后变化、对照、误解修正、意外、结果或代价等内容关系；
- 实际用来比较、淘汰或重排传播点的选材依据，以及其中哪些材料会直接进入正文；
- 一条已经完成关键句映射、核心关系都能由当前材料承担的完整案例；
- 病毒式传播时独立检索并比较过的开头候选，以及实际采用的开头原文、来源和逐句映射；没有可用外部候选时明确写“直接来自当前材料”；
- 必须逐字保留的文字。

上层已经检查过材料支撑。仍发现关键缺口时，把具体缺口交回上层，由上层更新精选材料包或收窄说法后再继续。

写作前研究已经负责从社区反馈和真实用法中选出真正有人称赞、复述和比较的变化。精选材料包是正文唯一的事实输入；本模板按上层已经选定的表达任务组织这些材料，从项目和最值得传播的变化本身开始。

## 正文怎样写

1. **从选中的钩子原句落笔。** 采用外部开头案例时，把原句中的人物、项目、动作、数字和结果换成当前材料，保留材料能够承担、读者也能辨认出来的句子关系、进入动作和节奏。下一句沿用原钩子的承接方式，马上交代它指向的项目事实。只借“痛点”“反差”“制造好奇”这类技巧名称，再另写一句无关开头，不算采用。独立检索没有可用候选时，直接使用材料包中的传播点并如实记录来源。
2. **让人马上听懂项目。** 用普通话说明项目名、它是什么、直接做什么和作用于什么，再交代读者为什么会在意。第一次正式介绍项目时，优先直接以项目名作主语，说明它是什么、能做什么；只有开头已经明确指向这个项目，而且选中的开头确实要到下一句才说出名称时，才使用代词或“它叫……”承接。项目可以通过真实使用场景或结果进入，但不能被改名为来源和实际用法都没有的宽泛任务；没有自然的任务名称时直接写具体动作。
3. **把完整案例的写法映射过来。** 逐句判断案例每句话怎样说、承担什么作用，再用当前项目的真实内容完成同样的推进。案例开头或主要推进依赖当前项目没有的核心关系时，应在选中前改用下一篇；不能选中后靠另造痛点、对照或误解补洞。只要事实允许，从案例原句开始近距离替换事实位置，保留具体进入方式、段落顺序、短句节奏、并列作用、信息密度和收束位置；具体措辞沿用写作前已经确定的成文语言。正文先从当前材料挑选真正有力的事实、动作、结果或例子，再决定是一项、几项还是不用列表；案例影响它们放在哪里、怎样形成力度和节奏，不决定条目数量，也不要求补齐功能清单。列出多项内容时，过渡句直接说清楚下面列的是使用方式、步骤、功能还是输出结果；要不要写数量、要不要单独写一句过渡，按当前内容和节奏决定。用户已经给出自然说法时沿用；没有时使用当前材料里最普通的名称，不把案例中的过渡句或临时口语说法变成固定句式。
4. **入口放在固定结尾之前。** 项目链接、仓库名或用户要求保留的入口放在正文自然需要的位置。
5. **使用固定最后一句。** 正文最后一行永远逐字写：

```text
100% 开源，完全免费。
```

这句话是正文最后一行。

段落之间怎样推进、句子节奏、并列内容的位置和中间怎样转折，优先沿用已选完整案例中能够由当前事实承担的部分，再由作者声音做局部调整。段落数和列点数量由精选材料包中实际值得写的内容决定。

直接引语、数字、日期、链接和明确归因按来源逐项对应。标题、钩子、类比、对照和判断由作者表达决定：用户已经给出或确认时优先沿用，用户没有指定时根据作者位置、读者认知和材料支持的关系选择；它没有声称逐字复述某个来源时，不因来源使用了另一个表面名称而机械改回。

## 案例与开头参考

完整案例负责正文从头到尾的主要写法。先阅读全文并把开头和主要推进中的关键关系逐项映射到当前项目，映射成立后才选中，再从原文替换事实位置。题材和类型只负责帮助检索。

开头参考单独负责第一句和紧接的一句。用户要求病毒式传播时，即使完整案例已经有开头，上层也必须独立检索钩子库并在有结果时比较至少两个候选；完整案例的开头只能作为候选之一。选择时逐项确认候选需要的关系和承接材料都已存在。完整案例与开头参考可以来自同一原文，但两个角色必须分别检索或进入候选、分别映射、分别确认采用。

## 交付前检查

- 病毒式传播已经独立检索钩子库，并在库中有多个结果时比较了至少两个候选。
- 第一行和紧接的一句能够清楚对回所选钩子原文的句子关系、进入动作和承接方式；对不回去时没有声称“沿用”。
- 完全不了解该领域的读者能说清项目是什么、直接做什么、作用于什么，以及最特别的地方。
- 项目用途和受众叫法来自对象事实或真实使用材料；没有为了钩子发明宽泛任务名称。
- 正文中的痛点、冲突、对照、误解修正、前后变化和规模都有材料承担。
- 正文能够与所列完整案例逐段对应，并实际保留当前事实支持的表达、节奏和格式；不是只借了一个痛点概念。
- 项目事实的数量和段落数来自当前材料，没有为了复现案例表面形状硬凑或删减内容。
- 每项正文事实都服务同一个主要变化，没有从研究材料补成技术说明。
- 选材研究已经影响最主要的变化和事实顺序，但研究过程与无关意见没有代替项目本身成为开场。
- 项目入口真实，并且位于固定最后一句之前。
- 正文最后一句严格等于“100% 开源，完全免费。”，其后没有任何内容。
