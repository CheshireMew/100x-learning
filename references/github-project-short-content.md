# 单个 GitHub 项目介绍

用于在成文前保留单个 GitHub 项目介绍特有的事实边界。本文件只准备材料，文件正文、栏目和说明不进入成文输入。

写作准备材料应保留项目的官方定位、完整能力范围，以及实际有用的演示、动作、结果、场景、比较、用户反应和自然说法。项目主页、安装方式、运行条件、价格、许可证、平台或提示词只在用户要求或正文确实需要时加入。

项目身份由官方定位与真实能力共同支撑，不能用某个快速示例或单项能力重新定义整个项目。

不要把 README 机械压缩成功能摘要，也不要预先排除具体功能；一个功能确实最能帮助读者理解项目时可以成为主要内容。架构、工作流、文件格式和内部术语只有在能帮助理解或行动时才进入正文。

用户要的是吸引人的项目短内容、项目介绍或宣传短帖时，开头先找项目最强的具体直接利益或可见结果。README 里的命令和自然语言调用示例可以作为能力证据或正文材料，但用户没有要求操作演示、教程或命令讲解时，不能只因存在这类示例就选择 `H23 原始输入开场`。这条规则只限制钩子资格，不预选承接、正文、连接或结尾。

同类请求也不能选择 `P01 输入—处理—输出` 重播钩子已经说过的利益。材料另有二至四项不同的能力、数量、格式、范围或使用条件时，独立判断 `P24 结果证据展开` 是否合格；它不合格时继续筛选其它正文模板。命令示例可以证明某项能力，但不能同时充当钩子、正文主线和结果证据。

普通介绍可以保留一个有用入口；安装、运行或教程请求可以使用相应命令。准备完成后只把项目原始事实和必要上下文并入材料。草稿中的实时数据和行动条件回到对应来源核对。
