# 单个 GitHub 项目介绍

用于把一个 GitHub 项目写成普通读者能直接看懂、愿意停留和转述的独立短内容。本文件只负责成品身份，直接消费上层已经净化的写作材料，不重新搜索、核查项目或规定固定正文骨架。

## 写作输入

上层应当同时提供：

- 从官方仓库、文档、演示、媒体、KOL、创作者、真实用户或社区讨论中筛出的可写材料；
- 本篇决定读者为什么要认识或选择这个项目的核心关系、能够证明它的动作或结果，以及可供通用成文选择的项目主页、仓库、安装指南、原样候选命令与完成范围；
- 用户明确要求提示词，或本篇的主要下一步本来就是把明确任务交给 AI 时，形成一至三句可复制提示词所需的目标、必要边界和验收依据；
- 目标读者、作者位置和可用声音；
- 多个完整案例全文、多个独立钩子的原始开头与紧接内容，以及两类文件各自的路径。

写作输入已经去掉无关功能、边缘限制、官方免责声明和通用保守提醒。模型直接从留下的动作、结果、演示、比较和自然说法中选择讲法，不在本模板里重新建立官方事实底座。

## 找到真正值得传播的关系

不要把 README 压缩成一段介绍。先区分项目级价值与支撑它的功能细节：项目级价值说明读者采用它以后能完成什么重要任务、得到什么重要结果，或者获得什么原本缺少的选择与控制；功能细节负责让这项价值可信、可见。暂时拿掉某个细节后，读者仍然知道为什么要选择这个项目，它就不能只因容易演示或描述而占据第一屏。确定核心关系后，再找支持它的具体动作或结果，并说明它为什么与这类读者有关；缺少其中任何一项时继续找材料或收窄主张，暂不写开头。

## 正文怎样写

由上游已经选定的项目级关系决定开头和正文顺序，不固定成某种骨架，也不要求某篇案例承担某个位置。完整案例和独立钩子共同参与写作，但不能替项目材料提供主张，也不能把一个更好描述的支撑功能重新抬成主线。

面向普通读者时，前两句优先出现已经选定的项目级变化，以及它对读者的直接意义。读者如果只能复述一个支撑功能，或者还要把 MP4、时间线、工作流、组件或格式翻译成“为什么值得用”，说明开头没有说到项目价值，需要回到核心任务、结果、选择或控制。项目名和身份在读者需要识别时自然出现，可以融入场景、结果或入口，不固定单独成句。

多个完整案例与多个独立钩子原文可以共同影响成文。模型不必挑一个模仿，不登记逐篇采用状态，也不为证明借鉴而改变成稿。只有用户明确要求仿写或续写某篇时，才近距离对应它的句段职责。

案例或钩子中的第一人称属于原作者，不能改写成本次作者经历。当前作者明确提供的使用时长、测试结果、数字和感受如果最终承担可信度，由成稿核查决定是否修正。

只写服务于主要传播关系的内容。README 里的能力清单、架构、文件格式和内部术语只有在能让读者更理解、更相信或知道下一步时才进入。外部报道和用户讨论同样按作用取舍，不为了显示研究充分而堆进正文。

提示词不是项目介绍的固定部分。只有用户明确要求，或者本篇的主要下一步本来就是把一个明确任务交给具备目标环境操作能力的 AI，而且提示词比项目入口更直接地帮助读者完成任务时，才在价值和场景已经成立后给出一至三句可直接复制的提示词。只是让读者认识项目、产生兴趣或前往项目入口时不加；已经选定的提示词包含同一直接指令时不重复展示。

本模板不根据命令外形重选行动入口。普通项目介绍消费通用成文已经选定的项目页面；安装、运行或教程请求消费已经选定并说明用途的直接指令或安装指南。用户给出的格式和链接位置优先；行动入口交付后正文停止。

价格、许可证、平台、兼容性、免费范围、付费依赖、API Key、硬件、版本和运行条件默认留在研究材料中。只有省略会让本篇核心说法或主要行动明显失真，或者用户正在评估购买、兼容性、部署或价格时，才保留真正必要的一项；“信息真实”“部分读者可能关心”和“下载前也许有用”都不足以让它进入正文。已经用“Mac 应用”等日常说法交代对象时，不再追加更细的平台和版本条件，也不在项目入口附近或结尾合并成一组稳妥说明。成稿实际使用了精确许可证、价格、平台或运行条件时，再核查对应说法。不再使用固定结尾，也不把“仓库可以访问”自动写成“100% 开源，完全免费”。

## 交付前回读

- 完全不了解该领域的读者能够说清项目直接帮他做什么。
- 开头来自当前项目的核心结果、反应、比较或场景，能够说明为什么值得认识或选择它，不是换个项目名也成立的官方套话。
- 前两句是具体动作或结果，不是工作流、格式和内部机制的堆叠。
- 搜索材料中的官方套话、通用提醒、无关平台和边缘限制没有进入正文。
- 媒体、KOL、创作者和用户材料确实改变了选材或表达，没有只把 README 换一种说法。
- 多个相关完整案例与多个独立钩子原文已经共同进入写作上下文，没有唯一参考和采用证明。
- 相邻句子没有换一种说法重复项目身份、核心价值或结果。
- 行动入口符合本篇目的；普通项目介绍保留真实项目页面，安装或教程只使用通用成文已经选定的直接指令或安装指南，没有按命令外形重新选择。
- 提示词只在用户明确要求，或它本来就是本篇的主要下一步且比项目入口更有用时出现，没有因为 AI 可以代办而机械加入。
- 价格、许可证、平台、兼容性、付费和运行条件没有作为稳妥说明挤进结尾；确实保留时，它直接关系核心说法、主要行动或用户正在评估的问题。
- 成稿中会改变项目理解或读者行动的事实已经核查，每处表达近似都有材料支持并让关系更清楚。
