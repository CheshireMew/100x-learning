# 连续学习

用于围绕同一主题开始学习，或根据用户对上一轮的真实反应继续下一轮。它负责决定“现在最值得学什么、怎样讲才接得住”，不把主题自动展开成预先写好的长课程。

## 一、先找当前学习位置

新主题先确定用户想获得的结果、现在怎样理解或使用它，以及第一轮能产生什么实际帮助。资料已经足够时直接给出第一轮讲解、例子或小实践，不为了完整感先列出庞大课程表。

继续学习时，读取当前对话中最近一次有效讲解、实践结果和用户反馈。真正的反馈包括哪里没懂、觉得重复、与自己无关、已经会用、提出了反例，或带来了新的现实问题；模板问题、系统提示和 Agent 自己预设的反馈不算用户证据。

## 二、根据真实反馈改变下一轮

- 用户困惑时，降低抽象层级，回到具体对象、动作、因果关系和反例；不要只换一组同义词。
- 用户觉得无聊、重复或不相关时，换一个与其现实用途相连的切口，不按原顺序继续堆知识点。
- 用户开始应用时，转向案例、判断、比较或小实践，让新知识参与可观察结果。
- 用户已经掌握当前层级时，提高信息密度，进入更深机制、边界、争议或迁移条件。
- 反馈很少时，只推进一个与当前难度相邻的小台阶，并留出能够暴露理解状态的下一步。

每一轮只交付当前真正有用的一课或一次互动。结尾提供自然的反馈入口，例如请用户指出最模糊的关系、带来一个实际例子，或选择继续解释还是动手使用；不强制固定课数、固定篇幅和统一课堂模板。

## 三、把现实问题作为课程入口

用户带来异常、失败或判断难题时，先钉住预期、实际现象、断点和不能改变的条件，再选择刚好能解释或处理这个断点的知识。问题已经清楚时不重复提问；信息不足且会改变主要讲法时，只问那个关键缺口。

## 四、需要跨任务保存时

普通连续学习留在当前对话。只有用户明确要求保存、建立学习系列或以后接着学时，才读取 `private-knowledge-library.md` 与 `knowledge-base-workflow.md`，使用现有私人知识库：

- 系列目标、当前状态、已暴露缺口和下一步放在 `30-Projects` 的唯一项目真源。
- 已经稳定、可脱离单次课程复用的概念与机制合并进 `10-Knowledge` 的唯一主题。
- 用户确认要保留的课程成品或实践结果进入 `40-Outputs`；原始材料仍只在 `20-Sources` 保存一次。

同一事实不在课程记录、项目状态和知识文档中各维护一份。继续学习时先读唯一状态和最近的真实反馈，再更新原位置；不要预先写完尚未发生的后续课程。

## 五、完成标准

- 本轮内容对应用户当前的理解缺口或使用目标，而不是预设目录中的下一项。
- 讲法确实随真实反馈改变，用户能指出自己学会了什么、还卡在哪里或下一步怎样用。
- 没有反馈证据时只做小步推进，不虚构掌握程度。
- 未经用户明确要求不持久化；需要保存时只更新现有知识库的唯一真源。
