# 实践导向学习

用于把已经获得的知识转化为模拟、案例、工具、方案、判断或现实行动。实践服务用户目标，不是考试。

## 一、什么算实践

实践是使用知识产生可观察结果，包括：

- 用概念分析一个真实事件或案例。
- 建立纸面方案、情景模拟或回测。
- 比较多个选择并说明取舍。
- 制作以后能复用的表格、模型、代码或清单。
- 在安全环境执行一个流程并记录结果。
- 根据实践形成决策说明、教程、文章或复盘。

如果一个知识点暂时无法帮助观察、判断、设计或行动，把它标为背景并压缩，不堆积信息。

## 二、用户拥有实践目标

- 用户已经指定产物时，围绕该产物推进，不额外设置学习任务。
- 用户只说想了解时，先完成讲解。只有实践能明显帮助当前理解时，才简短提供一个可选方向。
- 用户暂时不想实践时，完成当前讲解并保留入口，不用答题或闯关阻塞交付。
- Agent 可以承担检索、计算、制表、编码和起草；用户决定参与程度。

## 三、按知识类型选择实践

| 知识类型 | 合适实践 | 可观察结果 |
| --- | --- | --- |
| 定义 | 用它划分真实案例或边界 | 哪些属于、哪些不属于 |
| 机制 | 改变输入做情景模拟 | 原因、过程和结果怎样变化 |
| 框架 | 应用到用户案例或方案 | 哪些维度被看见，哪些仍遗漏 |
| 程序 | 在安全环境执行一次 | 步骤、反馈、错误和完成产物 |
| 争议 | 比较不同立场下的选择 | 哪个前提改变了结论 |
| 历史经验 | 对照新的事件或环境 | 哪些机制可迁移，哪些只是时代背景 |

## 四、设计一次实践

正式设计实践时，至少考虑以下内容；简单实践不必把每项都展示成标题：

1. **目标产物**：最后得到表格、模型、方案、分析、决策说明还是文章。
2. **输入**：材料、数据、用户约束和必要假设。
3. **环境**：现实操作、沙盒、纸面模拟还是历史案例。
4. **步骤**：能直接执行的少量动作。
5. **观察指标**：怎样看到结果、差异、失败或意外。
6. **关键边界**：哪些假设或限制会实质改变结果，哪些动作暂不执行。
7. **沉淀方式**：结果如何变成可复用规则、工具或内容。

实践应尽量贴近用户真实用途。模拟只是降低风险的手段，不能把虚构结果写成真实经验。

## 五、低压力协作

- 用共同操作、演示和选择代替闭卷回答。
- 用户卡住时提供数据、脚手架、示例或 Agent 演示，不把卡住解释为学习失败。
- 提问用于获得必要约束或讨论取舍，不用于检查记忆。
- 每次只推进与当前产物有关的知识，不临时扩张成完整课程。
- 结果出现问题时回到对应机制补充，不要求用户从头重学。

## 六、高风险实践

涉及金融、医疗、法律、生产系统或不可逆外部动作时：

1. 先核实当前规则和关键事实。
2. 优先建立纸面方案、沙盒、模拟数据或情景分析。
3. 清楚区分教育示例、分析结果和针对个人的建议。
4. 未获得必要授权和用户约束前，不代替用户执行外部动作。
5. 只记录会改变结果或行动的关键假设、费用、限制和失败条件。

## 七、完成标准

实践完成不是用户通过考试，而是：

- 产生了用户认可的具体产物。
- 知识确实参与了观察、判断、设计或行动。
- 会改变判断的结果、假设和边界被记录。
- 用户可以决定停止、继续迭代或把过程转成文章与工具。
