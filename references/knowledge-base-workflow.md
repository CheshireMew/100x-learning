# 知识库工作流

用于读取和更新上层已经定位的 `<私人知识库>`。目录边界以 `<私人知识库>/Home.md` 为唯一规则；目录决定内容角色，frontmatter 只辅助检索和维护。

## 一、读取与写入边界

只有上层选择知识库读取或写入时进入。本文件负责检索、目录归属、唯一真源、写入和写后核对，不决定普通材料理解、主题研究或写作是否必须读取知识库。

进入后先读取 `<私人知识库>/Home.md`。该文件缺失时，把缺失状态交回上层，继续使用用户材料和外部资料；交付必须持久化时再询问初始化或接入位置。

满足以下任一条件时进入写入分支：

- 用户明确要求保存、整理、更新或继续已有内容。
- 用户要求的交付物本身是持久化文件。
- 当前适用的知识库或项目规则明确要求回写本次结果。

跨任务复用价值决定哪些内容值得写入，当前授权决定是否写入。只读分支直接完成当前回答。

## 二、用 `rg` 找到需要的文档

1. 读取 `<私人知识库>/Home.md`，确认当前目录边界。
2. 从任务中提取主题名、常见别名、近义表达、缩写和必要的中英文术语。只扩展会改变检索结果的词。
3. 先查 `10-Knowledge` 的文件名，再查正文：

```powershell
rg --files "<私人知识库>/10-Knowledge" | rg -i "关键词1|关键词2|English term"
rg -n -i -g "*.md" "关键词1|关键词2|English term" "<私人知识库>/10-Knowledge"
```

4. 优先打开标题、`topic` 或 `aliases` 直接命中的文档，其次是小标题和正文多次命中的文档。结合目录、开头的主题范围、正文范围、状态和更新时间判断相关性。
5. 从候选知识文档沿 Obsidian 链接读取直接相关的专题和来源。需要找反向引用时搜索短链接或完整路径：

```powershell
rg -l -F "[[笔记名]]" "<私人知识库>"
rg -l -F "[[10-Knowledge/目录/笔记名]]" "<私人知识库>"
```

6. 需要核对证据、恢复原始上下文或已有知识不足时，再读取已链接的 `20-Sources`，必要时对该目录全文搜索。
7. 任务涉及正在进行的工作、长期领域、最终成果或写作规则时，再进入相应的 `30-Projects`、`50-Areas`、`40-Outputs` 或 `60-Systems`。任务明确需要相关个人经历时读取个人日记。
8. 本地资料存在缺口、已经过时或需要当前事实时，扩大到外部搜索。

`rg` 负责文本匹配，Agent 生成少量合理的同义词和英文术语，并通过阅读候选内容判断语义相关性。当前知识库继续使用现有索引作为真源。

## 三、确定主题唯一真源

写入前再次搜索主题及别名，并比较候选文档的实际问题和范围：

- 处理同一个问题、机制或判断边界：更新现有文档。
- 只是现有主题的一个新证据、案例、限制或子问题：合并到现有文档的对应位置。
- 能独立回答另一个长期问题，且与现有文档边界不同：新建主题文档，并与上位或相邻主题建立链接。
- 多个专题需要共同入口：更新最接近的综合主题文档。

同一主题知识保持一个活动文档，历史变化由版本管理、项目记录和文档中的必要说明承担。

## 四、按内容角色落位

| 内容 | 位置 | 写入方式 |
| --- | --- | --- |
| 网页、书籍、论文、字幕和访谈等原始材料 | `20-Sources` | 保存出处、来源角色和必要上下文；本地材料或获得保留授权时写入完整原文 |
| 已消化的概念、机制、证据判断和可复用案例 | `10-Knowledge` | 合并成主题知识文档，链接来源 |
| 有目标和结束条件的文章系列、研究或实践 | `30-Projects` | 保存范围、状态、材料链接、缺口和下一步 |
| 已确认完成的文章或其他成果 | `40-Outputs` | 保存最终版本，并链接知识和项目 |
| 写作声音、模板和长期流程 | `60-Systems` | 维护长期规则，具体文章保存在对应项目或成果目录 |

暂时无法判断归属的材料进入 `00-Inbox`。归档使用 `90-Archive`，活动路径保持当前版本。

### 已确认或已发布的写作成果

用户明确要求保存确认稿或记录已发布内容时，正文进入 `40-Outputs/Writing` 的现有分类；同一作品只保留一个活动正文。为了让后续写作能够分别检索发布历史和合格声音证据，新增或实质更新的写作成果使用：

```yaml
---
type: writing-output
status: final
updated: YYYY-MM-DD
author: 作者名
source: user-confirmed
format: article
content_type: 内容类型
writing_origin: human-edited
voice_eligible: true
published_url: ""
---
```

`source` 按真实状态使用 `user-confirmed`、`published-article`、`published-post` 或 `published-thread`。`format` 使用上层已经选定的成品形态。已经发布时填写规范入口；用户只确认终稿但尚未发布时保留空值。`writing_origin` 按实际情况使用 `human`、`human-edited`、`ai-generated`、`curated`、`translated` 或 `unknown`。只有用户明确确认正文能代表自己的表达，而且来源是 `human` 或 `human-edited` 时，才填写 `voice_eligible: true`；发布账号、确认终稿和发布入口本身不提供声音资格。

`<私人知识库>/60-Systems/Writing/style-guide/voice.md` 继续是长期声音的唯一真源。`published-content-index.jsonl` 只索引确认稿和已发布正文的路径、形态、发布归属、写作来源、声音资格、日期与哈希，不复制正文。内容案例继续留在 `20-Sources/Social Posts/Content Cases`；被选为案例不能证明作者声音。案例中的社交原帖只有规范入口匹配 `writing-memory.json` 已验证的本人账号时，才以原帖全文进入发布历史；还必须另外具有可靠 `writing_origin` 和 `voice_eligible: true` 才能进入声音检索，缺少时按 `unknown` 和 `false` 处理。

## 五、来源、知识与关系

- 来源文档记录“这个来源实际提供了什么”，保留作者、时间、链接、版本、必要上下文和来源角色；综合结论进入主题知识文档。
- 主题知识文档记录“当前足够可靠的认识”，包括机制、证据判断、适用范围、冲突、开放问题和实践反馈。
- 技术字幕缺少板书、图表或公式时，来源文档记录缺失边界和材料能够确认的主线；主题知识文档保存可靠校正后的定义、公式和条件，并明确它们不是从残缺字幕逐字恢复的内容。
- 每项重要来源用链接放在它支撑、限制或反驳的主张旁边。
- 相关知识使用带说明的链接，写清关系类型、方向和范围；裸链接用于导航。
- 来源冲突会改变结论时保留双方、条件和当前判断。
- 项目、文章和系统链接主题知识，研究材料保留在知识真源。

## 六、按知识库约定解释和组织文档

`<私人知识库>/Home.md` 的文档约定是主题文档格式的唯一说明。

读取候选文档时，先用标题、`topic`、`aliases` 和开头的范围说明判断它是否回答当前问题，再读取相关章节、证据和边界。单独命中一段时，确认该段的主题对象、适用条件和来源关系。

写入时把聊天、搜索结果和来源材料重组成可复用认识。章节名称服从内容，并保留 Home 规定的主题范围、来源关系和重要边界；章节随实际内容创建。

如果用户在对话中纠正过解释层次、范围或表达方式，以用户最后确认有效的解释结构为当前真源，写入时使用该结构及仍然有效的内容。

抽象、技术或公式密集的主题在同一个知识真源中保留两个层次：先用现实问题、具体情境和普通语言建立可理解模型，再保存精确定义、核心公式、符号或尺寸、成立条件和必要关系。每项正式内容说明它对应可理解模型中的哪一部分。

两个层次在同一主题真源中分区承担不同作用。“普通人总结”“实际怎么用”“行动清单”等部分使用已解释的普通语言写判断、动作、条件和可观察结果；正式定义、公式和高阶关系进入后续正式层。用户要求把总结讲简单时重写该层次，用户明确缩小整个写入范围时按新范围处理。

对话中的追问和纠偏如果改变了概念定义的讲法、暴露了关键反例，或明确了模型与现实的边界，就属于本次稳定知识增量。写入前回看当前完整对话，合并用户最后确认有效的可理解结构、仍然成立的正式内容、关键反例、现实应用边界和开放问题。

同时保留来源角色：课程或原文实际提供了什么，标准定义和公式怎样校正，现实判断由哪些外部证据支持，哪些是为了帮助理解而构造的教学例子。用户追问决定主题文档需要回答什么，原始来源证据由来源本身提供。

### 完整材料的覆盖闭环

如果最初请求的范围是整节课、整篇文章或另一份完整材料，写入前根据材料分析阶段的核心知识单元做覆盖映射：

1. 先列出材料主线中的核心知识单元，再分别标明它应进入哪个现有主题、新主题或综合入口。
2. 多个核心单元共同回答一个上位问题时，综合主题文档负责呈现全局问题、单元关系和完整学习路径；某个单元已经形成足够独立且深入的认识时，可以建立或更新专题文档，由综合主题用一句有方向的关系说明连接它。
3. 来源文档负责忠实记录材料范围、结构和缺失边界；知识层覆盖由能够复用整课结构的综合主题或关系入口证明。
4. 写后逐项检查：每个核心知识单元已经在综合主题中得到最小解释，或能够从综合主题直接进入相应专题；被追问的专题同时保留用户确认有效的通俗层和正式层。

如果用户最初只要求沉淀一个概念或片段，就以该概念为覆盖单位。覆盖闭环服务当前授权范围内的主干。

## 七、体系化写回

正式修改前，先读取 `<私人知识库>/Home.md`，搜索主题名、别名和已有来源，确认本次是更新现有文件还是创建独立新主题。用户已经授权、目标路径符合 Home 的目录边界后再写入。

1. 新来源需要长期保留时，先写入或更新 `20-Sources`；网页研究通常保存出处、作用和必要上下文。本地来源需要哈希时，在写入计划前从实际文件计算一次，并把同一个计算结果复用于 `source_identity`、来源元数据和正文。
2. 把新结论、修正、关系、边界和开放问题合并进 `10-Knowledge` 的唯一主题文档。
3. 新关系会改变导航或上位模型时，更新相关综合主题文档，并用一句话说明关系。
4. 任务属于项目、文章或长期系统时，更新对应文件的状态和知识链接，主题正文保留在知识真源。
5. 更新 `updated` 日期，并确认活动目录中的主题真源唯一。
6. 新建或更新知识文档后重新读取文件，检查标题、主题范围、来源链接、必要边界和内部链接是否完整，确认用户实际能找到并使用。
7. 本地来源写入后重新计算实际文件哈希，并与来源记录中保存的值比较；两者一致后交付。
8. 保存确认稿、已发布内容或长期声音后，运行 `python scripts/writing_memory.py build-index` 和 `python scripts/writing_memory.py validate`，证明正式正文已经进入发布历史，写作来源和声音资格也能被下一次写作按用途读取。没有新的可靠声音证据或稳定声音变化时，不更新长期声音真源。
9. 告诉用户实际更新了哪些文件和认识；稳定增量存在时执行写入。

进入文章或实践前，检查当前用途需要的机制、证据、案例和限制是否已经可用。发现缺口就补对应知识，材料足够后停止。

`00-Inbox` 接收暂时无法判断归属的内容。已经确定归属的内容直接进入唯一正式位置。
