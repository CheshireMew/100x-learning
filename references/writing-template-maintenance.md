# 写作模板维护

只在用户明确要求新增、修改、审查或重新蒸馏写作模板时读取。普通写作不读取本文件；正式取例工具可以按覆盖账本列出当前组件的活动候选，并只读取模型按当前角度显式选择的一份完整案例或钩子。

## 语料角色

私人库中的完整案例和独立钩子既是模板研究语料，也是普通成文可用的模仿候选。维护时可以从案例索引和钩子索引打开活动正文，找出可跨题材复用的结构关系；原文、作者身份、题材事实、口头禅、CTA 和偶然措辞不进入组件规则。普通写作先看候选标题，每个表达职责最多显式读取一份与当前角度相关的完整例子，并且只能模仿该部分的节奏、取舍和推进；没有相关例子时不读取。索引标签只帮助分组，不能直接当模板。

一次蒸馏必须分别判断：

- 钩子怎样承诺后文；
- 钩子后第一句怎样说明对象、结果或问题；
- 正文怎样按事实、动作、机制、比较或时间推进；
- 句段和章节之间存在什么真实关系；
- 结尾停在结果、边界、行动还是首尾回扣；
- 哪些事实缺失时对应组件不能使用。

钩子、承接、正文推进、连接、结尾和长文章节必须分开蒸馏、分开存放。一个组件只承担一个职责，不把常见搭配固化成整篇路线，也不建立推荐套餐或兼容矩阵。运行时先从当前材料选择最强具体角度，再独立选择实际需要的组件；每个组件必须单独满足事实条件。没有独立承接或连接句段时不选 `C`、`B`，不能为了拼接而写身份句或过渡。

相同原文同时出现在案例库和钩子库时只算一份结构证据；返佣推广、高风险因果、损坏命令、实验文体和失败稿只能贡献确认可靠的局部句法或关系，不能贡献事实、承诺或默认语气。

## 当前蒸馏基线

2026-08-11 的迁移完整读取了 41 篇活动社交案例、29 篇活动文章案例和 131 个活动钩子。社交案例索引中的一条归档残留已经通过正式索引生成器清除；8 个钩子是现有社交案例的开头节选，计算证据权重时已去重。

这些语料支持了活动组件目录中分开存放的模板。逐来源覆盖账本记录 201 份活动来源实际支持了哪些组件；8 个与社交案例开头语义重复的钩子保留寻址但降权。来源被读到不等于已蒸馏，只有覆盖账本能把它指向具体组件或明确拒绝原因时才算处理完成。

单个组件不是某篇原文的改写。多个来源可以共同支持一个组件；只有单例支持但结构仍然清楚的组件必须在文件中保留严格准入条件。每个组件一个文件，稳定 ID 与文件名一致。

英文原文和翻译语料只贡献可以迁移的关系，不贡献英语语序。组件文件不再保存带方括号的成品句；自然中文由当前材料决定，确实相关的真实例子只帮助节奏和取舍，不能把 `This is...`、`What this shows is...`、`The answer is...` 一类英文承接逐词换成中文。

## 外部方法怎样使用

外部方法只用于校正组件边界，不直接成为新一套运行时框架：

- 倒金字塔支持事实更新先给最重要事实，但不适合所有叙事和观点内容。
- nut graf 支持钩子后尽快交代“这是什么、为什么值得继续读”，随后用证据兑现。
- 短写作依靠选择一个最强事实，而不是把全部材料压缩进短篇。
- 具体事实与解释要交替，避免连续抽象判断。
- AIDA 和 PAS 只描述说服阶段，不能作为普通写作模板。只有真实转化任务、明确读者研究和可核实问题存在时，才可把其中局部关系吸收进对应正文或结尾组件。
- CTA 只在真实下一步存在且当前任务需要时使用；逻辑结尾与 Newsletter 页脚分开。

维护时优先阅读原始方法说明：[Nielsen Norman Group 的网页短写原则](https://www.nngroup.com/articles/be-succinct-writing-for-the-web/)、[Purdue OWL 的文档组织说明](https://owl.purdue.edu/owl/graduate_writing/introduction_to_writing/documents/drafting-your-document/handouts/document-organization.pdf)、[Poynter 的 nut graf 说明](https://www.poynter.org/archive/2003/the-nut-graf-part-i/)、[Poynter 的短写作原则](https://www.poynter.org/reporting-editing/2009/25-non-random-things-about-writing-short/)。

## 变更合同

新增或修改模板时，一次提交必须同时完成：

1. 在对应子目录新增一个文件，写出稳定 ID、名称、适用形式或位置、适用条件、必须事实，以及该类别需要的写法、推进关系、展开方式或停止位置。不能加入带方括号的成品句、填空句或固定句式，也不能在一个文件里同时定义两种职责。
2. 更新活动组件索引的编号范围，并在逐来源覆盖账本中加入每个新来源，或调整受到影响的旧来源映射。
3. 至少用两个不同题材的真实材料试填；单例支持的组件必须写清单例来源和严格准入条件。
4. 检查“必须事实”能由当前材料判断，不能要求模型自行发明痛点、欲望、冲突、意义或 CTA。组件只说明职责和关系，具体中文由当前材料自然生成；模仿例子只有相关时才使用。
5. 在覆盖账本中如实记录新组件的活动来源；没有真实支持该写法的活动来源时明确写“无活动取例来源”，不能为了让工具有结果而硬映射。再检查它与其它组件组合时没有重复职责或虚构连接。普通写作组件不附带统一的风险清单、免责声明或必写限制。
6. 更新组件文件、覆盖账本、取例工具和运行合同测试，并让一个没有收到预期答案的全新代理完成真实写作验收。验收结果必须按默认交付格式列出实际使用的全部组件。

旧组件被替换时直接迁移所有调用点，不保留别名、整篇模板、固定组合或回退路线。原始案例和钩子继续保存在私人库，既用于以后蒸馏，也由正式取例工具按单个组件列为候选；只有模型确认与当前角度相关时才进入普通写作。旧文件需要退出时移入 `archive/`，不删除。
