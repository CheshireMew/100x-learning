# 独立钩子库

用于在写作前定位用户已经明确保存的钩子原文，也用于用户明确要求时新增或更新钩子。它不读取完整案例，也不从案例开头生成钩子。

## 运行边界

钩子库位于：

```text
<私人知识库>/20-Sources/Hook Library/
```

`开头钩子索引.md` 先按开头手法、再按原始内容形式定位文件。主题标签不能作为钩子索引，因为主题说明“内容在讲什么”，不能说明“这个开头怎样抓住读者”。内容形式只说明原文来自哪里和大致篇幅，不限制文章、短帖或 Thread 互相借鉴。每个钩子文件只包含：

- 稳定的 `hook_id`；
- 内容形式；
- 用户指定的连续开头与紧接内容；
- 可核对来源。

开头手法只体现在目录和索引分组中，例如问题钩子、痛点钩子、结果钩子、反常识钩子、故事钩子、信息缺口钩子或对象亮相钩子；分类保持在能直接帮助选择开头的稳定层级，不把每种措辞再拆成细碎类型。钩子文件内不写技巧解释、公式、效果、证据、评分或筛选理由。目录使用 `<内容形式>/<开头手法>/<文件>`，不按题材拆分。

## 写作读取

写作时先打开 `<私人知识库>/20-Sources/Hook Library/开头钩子索引.md`，根据当前内容希望怎样自然带出后文，定位少量真正准备阅读全文并用于本次写作的钩子。当前成品对篇幅或连续结构有特殊要求时可以优先查看同形态来源，但 `writing_format` 只帮助定位。可以同时读取多份钩子和多份完整案例，让模型自由综合它们的开头作用、节奏和表达；当前作品的事实、立场、经历和结果仍由对象材料提供。本次实际使用的钩子在最终“本次创作参考”中列出。

没有合适钩子时沿当前材料继续写，不从完整案例临时抽取开头，也不为满足数量创建新钩子。

批量整理时先筛选再进入活动库。浏览量、转化率等数据存在时可以帮助比较，但数据缺失本身不是淘汰理由；仍要直接判断开头是否完整、具体、有张力，紧接内容是否兑现开头。相似钩子只保留更好的代表，未入选原文放入可回查归档。比较过程使用的指标和判断不写入活动钩子或索引。

## 创建和更新

只有用户明确要求把一段独立材料保存为钩子时才进入写入。输入文件本身必须包含需要保存的连续开头与紧接内容；案例文件路径不能代替输入：

```powershell
python scripts/hook_library.py add-hook --input "钩子原文.md" --title "钩子标题" --hook-id "stable-hook-id" --writing-format "短帖" --technique "结果钩子" --source "来源链接或本地来源"
python scripts/hook_library.py build-index
python scripts/hook_library.py validate
```

更新已有钩子时直接修改唯一钩子文件并重建索引。没有用户明确写入要求时，普通写作只读。

## 通过标准

- 钩子脚本、目录、数据类型和索引不读取案例库。
- 钩子原文与来源真实存在，文档开头只记录稳定 id 和内容形式。
- 索引先按开头手法分组，内容形式只标明来源；不按主题标签分组，也不显示筛选指标和分析。
- 活动钩子只有连续原文、来源和寻址字段。
- 写作可以同时读取案例与钩子，但两边没有相互引用或自动身份转换。
