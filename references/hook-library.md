# 独立钩子库

用于在写作前定位用户已经明确保存的钩子原文，也用于用户明确要求时新增或更新钩子。它不读取完整案例，也不从案例开头生成钩子。

## 运行边界

钩子库位于：

```text
<私人知识库>/20-Sources/Hook Library/
```

`开头钩子索引.md` 只按成品形态和使用语境定位文件。每个钩子文件只包含：

- 稳定的 `hook_id`；
- 成品形态和使用语境；
- 用户指定的连续开头与紧接内容；
- 可核对来源。

除上述内容外，钩子文件不增加写作注释。目录只按成品形态组织。

## 写作读取

写作时先打开 `<私人知识库>/20-Sources/Hook Library/开头钩子索引.md`，按成品形态和当前语境找到真正相关的文件，再读取实际原文。可以同时打开多份钩子和多份完整案例；钩子只提供真实开头材料，不替当前内容决定事实、立场或结构。

没有合适钩子时沿当前材料继续写，不从完整案例临时抽取开头，也不为满足数量创建新钩子。

## 创建和更新

只有用户明确要求把一段独立材料保存为钩子时才进入写入。输入文件本身必须包含需要保存的连续开头与紧接内容；案例文件路径不能代替输入：

```powershell
python scripts/hook_library.py add-hook --input "钩子原文.md" --title "钩子标题" --hook-id "stable-hook-id" --writing-format "短帖" --context "项目介绍" --source "来源链接或本地来源"
python scripts/hook_library.py build-index
python scripts/hook_library.py validate
```

更新已有钩子时直接修改唯一钩子文件并重建索引。没有用户明确写入要求时，普通写作只读。

## 通过标准

- 钩子脚本、目录、数据类型和索引不读取案例库。
- 钩子原文与来源真实存在，元数据只有寻址字段。
- 活动钩子只有连续原文、来源和寻址字段。
- 写作可以同时读取案例与钩子，但两边没有相互引用或自动身份转换。
