# 独立钩子库

用于在写作前定位用户已经明确保存的钩子原文，也用于用户明确要求时新增或更新钩子。它不读取完整案例，也不从案例开头生成钩子。

## 运行边界

钩子库位于：

```text
<私人知识库>/20-Sources/Hook Library/
```

`开头钩子索引.md` 先按开头手法、再按原始内容形式定位文件。主题标签不能作为钩子索引，因为主题说明“内容在讲什么”，不能说明“这个开头怎样抓住读者”。内容形式只用于定位和理解大致篇幅，文章、短帖或 Thread 均可互相借鉴。每个钩子文件只包含：

- 稳定的 `hook_id`；
- 内容形式；
- 用户指定的连续开头与紧接内容。

开头手法只体现在目录和索引分组中，例如问题钩子、痛点钩子、结果钩子、反常识钩子、故事钩子、信息缺口钩子或对象亮相钩子；分类保持在能直接帮助选择开头的稳定层级，不把每种措辞再拆成细碎类型。钩子文件内不写技巧解释、公式、效果、证据、评分或筛选理由。目录使用 `<内容形式>/<开头手法>/<文件>`，不按题材拆分。

## 写作读取

写作时先打开 `<私人知识库>/20-Sources/Hook Library/开头钩子索引.md`，根据当前内容希望怎样自然带出后文，定位多份准备阅读全文并用于本次写作的钩子。当前成品对篇幅或连续结构有特殊要求时可以优先查看同形态来源，但 `writing_format` 只帮助定位。多份钩子要提供不同的开头作用和表达距离，例如直接说出对象与变化、进入场景、提出真实问题、展示结果或留下必要信息。对象或变化本身已经清楚有力时，第一句直接进入主题就是完整开头；同题材候选都依赖大数字、悬念、反常识宣告或夸张判断时，继续跨题材寻找能够自然连接后文的原文。

钩子被保存，只说明这段连续原文可以帮助观察开头怎样接住后文，不表示它的夸张程度、语气和表面句式适合当前成品。阅读全文后保留实际有用的开头作用，用当前对象自己的事实和说话身份完成表达；多份原文共享的宣传腔、概念判断或悬念口吻不因重复出现而获得更多影响力。当前作品的事实、立场、经历和结果仍由对象材料提供。本次读入成文上下文的钩子在最终“本次创作参考”中列出。

索引不存在、校验失败、钩子库为空，或按开头作用浏览索引并搜索正文后仍没有返回可读原文时，把准确状态交回主流程并停止成文，直接说明用户需要修复或补充的私人库状态。不从完整案例临时抽取开头，不为满足数量创建新钩子，也不授权写作者跳过钩子输入继续成文。

批量整理时先筛选再进入活动库。浏览量、转化率等数据存在时可以帮助比较，但数据缺失本身不是淘汰理由；仍要直接判断开头是否完整、具体、有张力，紧接内容是否兑现开头。相似钩子只保留更好的代表，未入选原文放入可回查归档。比较过程使用的指标和判断不写入活动钩子或索引。

## 创建和更新

只有用户明确要求把一段独立材料保存为钩子时才进入写入。输入文件本身必须包含需要保存的连续开头与紧接内容；案例文件路径不能代替输入：

```powershell
python scripts/hook_library.py add-hook --input "钩子原文.md" --title "钩子标题" --hook-id "stable-hook-id" --writing-format "短帖" --technique "结果钩子"
python scripts/hook_library.py build-index
python scripts/hook_library.py validate
```

更新已有钩子时直接修改唯一钩子文件并重建索引。没有用户明确写入要求时，普通写作只读。

## 通过标准

- 钩子脚本、目录、数据类型和索引不读取案例库。
- 钩子原文真实存在，文档只记录原文、稳定 id 和内容形式，不保存来源。
- 索引先按开头手法分组，内容形式只用于定位；不按主题标签分组，也不显示筛选指标和分析。
- 活动钩子只有连续原文和寻址字段。
- 写作可以同时读取案例与钩子，但两边没有相互引用或自动身份转换。
