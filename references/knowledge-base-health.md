# 私人知识库健康检查

用于检查已经接入的私人知识库是否仍然可检索、可追溯、可复用。默认只读：先报告问题和证据，再由用户决定是否修复；健康检查本身不更新正文、索引或状态。

## 一、先证明检查的是当前知识库

先运行：

```powershell
python scripts/private_library.py show
python scripts/private_library_health.py
```

第一条命令确认当前根目录和写入方式，第二条命令从真实活动目录、链接与索引生成 JSON 报告。用户给出 `--library-root` 或 `--config` 时按该边界执行，不扫描其它资料目录。脚本只检查能从文件确定的结构事实：不可读文档、重复主题身份、失效或歧义链接、到期复核、没有来源入口的知识、尚未被后续任务使用的来源，以及内容案例和发布历史的索引偏差。

## 二、机器发现候选，Agent 判断知识问题

不要把脚本告警直接当作删除、合并或重写结论。按严重程度和用户当前用途打开实际文档、直接相关来源与链接上下文，再判断：

- 两份文档是否真的回答同一个问题，还是同名但范围不同。
- 来源没有被引用，是尚未消化、只承担存档作用，还是已经被另一入口覆盖。
- 没有显式来源的知识，是用户原创判断、旧迁移内容，还是证据链确实缺失。
- 到期内容是否受时间、版本、政策、价格、产品行为或新证据影响。
- 相邻主题之间是否存在冲突、重复结论、缺失上位入口或只靠裸链接连接的问题。
- 当前任务所需的方法、证据、例子和边界是否已经足够，还是库看起来很完整却不能支持实际任务。

复核结论必须引用实际文件路径和能够改变判断的具体内容。没有读过正文和来源时，只能称为“检查候选”，不能宣称知识已经过时、冲突或错误。

## 三、报告按用户结果排序

先给整体状态和最影响使用的少量问题，再说明：

1. 会阻断读取或造成错误合并的问题。
2. 会让结论失真、过时或失去来源的问题。
3. 尚未消化的来源、缺失关系和待补主题。
4. 仅影响维护便利、不影响当前使用的问题。

每项写清证据路径、为什么影响当前用途、建议动作和不处理的后果。脚本未发现结构问题时也要说明本次检查范围；不能把“零结构告警”说成“知识内容全部正确”。

## 四、修复需要单独授权

用户只要求检查、审计或报告时，在报告处停止。用户明确同意修复后，才沿知识库现有的正式文档和写入方式更新内容：同一主题合并进一个活动文档，来源保留一次，关系写清方向和范围，索引从真实正文重建。不要自动删除原文；需要退出活动范围的内容移入知识库既有归档位置，并说明移动前后路径。

修复后重新运行健康检查，并用至少一个真实任务读取刚修改的知识与来源。只有结构告警消失、后续任务能找到并正确使用结果时，才能说相应问题已经解决。
