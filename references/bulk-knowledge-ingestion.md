# 大批量知识接入

用于审计大量本地文章、笔记、字幕、网页归档或其它材料，并把它们逐批接入已经建立的私人知识库。目标是让后续任务能够找到并使用这些材料，不是把文件换一套目录再复制一遍。

## 一、先审计，不直接全量搬运

使用主流程已经定位好的私人知识库及其现有规则。先明确用户授权的来源范围、排除路径、文件所有权、材料作用、重复或版本关系，以及接入后真正要支持的用途，例如解释主题、继续学习、写作、做判断或形成项目材料。

规模由当前材料、上下文、工具和失败成本决定，不用固定文件数或字数定义“大批量”。未经明确写入授权，只交付审计结果和接入设计；不修改原始归档，也不复制整个目录。

## 二、沿用现有知识边界

- 原始材料只在 `20-Sources` 保存一次，保留来源身份、必要元数据和可追溯入口。
- 稳定概念、机制、结论和边界合并进 `10-Knowledge` 的唯一主题。
- 正在推进的整理任务、未决问题和批次状态进入 `30-Projects`。
- 用户确认保留的课程、文章或其它成品进入 `40-Outputs`。
- 完整内容案例和钩子只在材料确实承担相应创作作用时，交给主流程已经选择的案例或钩子保存流程。

不要另建一套平行的“知识原子”类型、第二索引或副本库。分类标签只帮助检索，不能取代材料本身、正式知识文档或项目状态记录。

## 三、先做有代表性的样本批次

从不同格式、年代、主题、质量和重复关系中选一个足以暴露规则问题的小批次，数量由差异决定。样本必须走完整过程：识别来源与版本、去重、确定材料作用、写入或更新唯一位置、重建必要索引，再由一个真实的后续任务从知识库重新读取。

样本验收不能停在“文件存在”或“索引能搜到”。至少用接入后的内容完成一个用户真正需要的结果，例如解释一个问题、续写一轮课程、生成有来源的主题骨架、支持一次判断，或形成一段基于真实材料的草稿。这个任务必须读取刚写入的来源和正式知识文档，不能由测试手写等价内容冒充。

## 四、规则稳定后再逐批扩大

只有来源身份、版本与重复处理、分类边界、更新策略和实际使用结果都稳定时，才扩大到其余材料。按可回查的批次处理，每批记录覆盖范围、跳过原因、冲突和实际更新位置；出现新格式、新冲突或后续任务无法使用时，暂停扩大，先修改规则并重新验证样本。

已有内容默认更新现有正式文件，不覆盖用户未合并的修改。私人库配置了 Marktree 时，通过现有集成完成正文与索引写入，让桌面端、Agent 和可选 Git 读取同一文件；不要绕开它制造另一条写入方式。

## 五、完成状态必须说准确

交付时明确区分：只完成审计、样本已通过、部分批次已接入，或授权范围已经全量接入。报告实际覆盖范围、未处理内容、冲突和后续任务的验证结果；不能因为索引建立成功就宣称整批知识已经可用。
