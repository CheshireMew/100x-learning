# 网页优先的视觉媒体制作

用于实际制作代码生成的静态图、动态图表、数据故事、概念卡、示意动画、GIF 或无实拍画面的视频。目标是先得到一个能够直接预览和修改的网页，再从同一网页导出各类媒体，避免内容、布局、样式和动画在多个脚本中各自演化。

## 一、先判断网页是不是正确的制作真源

先按最终画面怎样产生来分类：

- **代码生成视觉**：图表、图解、概念卡、数据变化、示意插画、界面演示和排版动画由 HTML、CSS、SVG、Canvas 或 JavaScript 产生。默认以网页作为唯一视觉真源。
- **原始素材剪辑**：主体是讲课、访谈、实拍、屏幕录制或已有视频素材。使用视频编辑时间线作为真源；网页只在确实需要时生成标题、字幕版式、图表或动画覆盖层。
- **混合视频**：旁白、实拍或录屏与代码生成画面共同出现。网页负责可编程视觉，视频项目负责声音、素材剪辑和最终装配；不要在视频项目里重新手工绘制网页已经负责的画面。

用户只要求选材、文案、分镜或制作建议时，不创建网页。只有用户明确要求视觉样稿、可编辑原型或媒体成品时才进入本流程。

## 二、网页是真源，不是临时预览壳

代码生成视觉默认交付单文件 HTML；只有共享组件、多个本地素材或构建工具确实能降低修改成本时才使用小型网页项目。网页至少要有一个固定逻辑尺寸的媒体画布，预览控制放在画布外，导出时可以隐藏。

同一信息只保留一个可编辑位置：

1. **内容与数据**：标题、正文、标签、数值、来源和状态数据集中保存，不散落复制到多段绘图代码。
2. **视觉变量**：颜色、字体、字号、线宽、圆角、阴影、间距和背景使用 CSS 变量或等价主题配置。
3. **布局**：对象位置、分组、层级和画布安全区由 HTML/CSS/SVG 结构负责，不为不同导出格式重写一套坐标。
4. **时间线**：元素出现、移动、计数、变形和停留由一个主时钟控制；播放、暂停、重置和定位到指定时间使用同一套状态更新逻辑。
5. **输出设置**：目标比例、像素尺寸、时长、帧率、循环和背景方式集中配置，布局开始前确定会改变构图的设置。

静态图、GIF、视频封面和无声动画都只是网页真源的派生结果。用户反馈内容、颜色、位置或节奏时，修改网页并重新导出；不直接在导出的位图、GIF 帧或视频画面上建立第二套正式版本。

## 三、从内容关系设计网页

网页不会自动把内容变好。先沿 `references/content-distribution.md` 确认主文案、视觉任务、信息结构和参考层，再决定用什么网页元素表达：

- 数值随时间变化时，使用坐标、条形、面积、计数器或对象尺度变化。
- 静态差异使用并列、叠加、矩阵或分组，不因为最终会动就改写成步骤。
- 空间关系使用示意图或可定位对象。
- 真正存在方向、交互或流程时才使用连线、路径和节点。
- 叙事确实需要多个场景时可以在同一网页中组织场景，但每次切换都要承接同一问题；GIF 仍优先使用持续可见的上下文锚点。

组件和模板只提供可修改的结构、控件和基础样式，不替内容选择图表类型、审美风格或叙事顺序。外部模板若带固定手写、科技、霓虹、PPT 或流程图语言，只在用户明确选择该风格或结构时使用。

## 四、用网页完成样稿和确认

样稿都在同一个网页真源中完成：

- **风格样稿**：网页只放少量代表元素，检查字体、线条、颜色、纹理、图标、密度和留白。
- **构图样稿**：网页放入完整内容骨架，检查层级、位置、容量和持续可见的上下文；可同时导出一张截图方便查看，但截图不是编辑真源。
- **动效样稿**：在已确认构图中实现一个代表性变化，并提供播放、暂停、重置和定位能力，检查运动是否真的解释了关系。

在真实浏览器和目标画布尺寸查看网页。字体、图标和本地素材必须实际加载；不能只读源码猜测效果。样稿未确认时停在网页和对应预览，不提前批量导出媒体。

## 五、让动画可以稳定导出

用于导出的动画必须能够从已知初始状态重复播放。依赖鼠标经过、滚动位置、随机数或不可控加载时间的效果，要么改成主时间线控制，要么固定输入并记录初始化条件。

网页至少提供以下能力或等价接口：

- 等待字体和必要素材加载完成后再标记为可捕获。
- 从零开始播放，并能暂停、重置和定位到指定时间。
- 捕获模式隐藏按钮、调试信息、鼠标指针和画布外元素。
- 在相同时间点产生相同的内容、位置、样式和数值状态。
- 循环动画的结束状态能够自然回到开始状态；非循环视频有明确的收束帧和停留时间。

CSS 动画、SVG 动画、Canvas 和 JavaScript 都可以使用，但不能让同一状态同时由多个互不知情的计时器控制。需要随机粒子或噪声时固定随机种子，避免每次导出都改变主体构图。

## 六、从同一网页派生媒体

先使用网页已经提供的导出能力；没有内置导出时，再选择能够捕获同一画布和时间线的浏览器截图、逐帧捕获或录制方式。导出工具只负责读取网页状态和编码，不重新实现视觉内容。

- **静态图**：在指定时间或静态状态捕获目标画布，按目标像素尺寸导出 PNG、WebP 或其它所需格式。
- **GIF**：按固定帧率采样一个短而完整的循环；优先减少无意义帧和大面积随机变化，控制可读性和文件大小。
- **视频**：从同一时间线导出无声 WebM、MP4 或帧序列。旁白、音乐、实拍和字幕需要后期装配时，网页导出的画面仍是视觉真源，后期项目不重画其内容。

如果当前环境只能可靠导出某些格式，保留网页真源并说明能够实际完成的导出；不能为了声称交付 GIF 或视频而另写一套不一致的绘图程序。

## 七、检查真实用户链路

交付前依次检查：

1. **网页源头**：文件可以打开，内容、数据、样式、布局和时间线能够从各自唯一位置修改。
2. **浏览器预览**：目标尺寸下没有文字乱码、字体替换、重叠、裁切、溢出、错误层级或控件进入捕获画布。
3. **关键状态**：开始、核心转折、结束和循环衔接都符合已确认文案与视觉任务。
4. **导出结果**：尺寸、比例、帧率、时长、背景、循环、清晰度和文件大小符合目标；动效在导出后仍真实存在。
5. **一致性**：导出媒体与网页在相同时间点表达同一内容，没有丢失字体、颜色、图标、滤镜、蒙版或关键状态。
6. **可修改性**：随机修改一个用户可见字段或视觉变量并重新预览时，相关画面由网页统一更新，不需要同步修改派生媒体或另一套渲染脚本。

技术检查通过不代表审美成立。仍要把网页样稿与用户确认的参考层逐项比较，并让用户在最早未确认的层面确认后再继续。

## 八、复用外部模板和代码

先核对许可证和必要署名。可以复用单文件组织、组件系统、CSS 变量、预览控制、导出菜单、画布上限和错误检查等通用机制；不能把来源项目的固定主题、内容类别、节点结构、布局、文案或动画效果升级为默认方案。

直接复制了受许可证约束的实质代码或资源时，在目标项目保留相应版权和许可证说明。只提炼操作机制时，不把来源项目路径设为运行依赖，也不把示例输出、失败记录或仓库专属字段保存进本 Skill。

## 九、停止条件

- 用户只要网页样稿时：网页可以打开、当前样稿层已经可见并完成对应检查后停止，不自动导出 GIF 或视频。
- 用户要静态图、GIF 或视频时：网页真源确认、指定媒体从该网页导出并通过一致性检查后停止。
- 用户只要修改时：修改网页真源并更新用户点名的派生格式后停止，不扩张成其它比例、平台版本或完整发布方案。
