# 值得分享的内容识别

<!-- 旧字段化交接包流程，已退出活动 Skill。 -->

用于从用户提供的视频、字幕、书籍、文章、课程、访谈或其它材料中，识别离开原材料后仍适合普通受众理解、受益和继续讨论的内容。默认交付分享候选与内容真源交接包；具体选择图文卡片、GIF、视频、音频或播客以及实际媒体制作由 `visual-multimedia` 负责。

## 一、先区分学习重点与分享候选

学习重点回答“理解这份材料最重要的是什么”；分享候选回答“哪段内容离开原材料后，普通人仍愿意看、能够看懂并得到东西”。两者分别服务理解和传播：

- 依赖大量先修知识的专业主干优先进入学习讲解，经过独立可懂处理后再作为分享候选。
- 故事、例子、反直觉判断或简洁表达可能有传播价值，仍要检查它是否忠实承载材料原意。
- 单句有冲击力时继续检查独立完整性；缺少关键条件、因果理由或转折时，扩大片段边界或降低推荐顺序。

先按 `references/material-analysis.md` 完成全局扫描、材料一致性判断和真实定位，再从完整语境中筛选。全局扫描用于跨整份材料比较候选，交付保持在分享候选范围。

## 二、受众、来源与授权

用户没有另行说明时，默认受众是没有相关专业背景的普通人。受众背景、分享目的或来源版本会实质改变候选时先从上下文确认；仍缺少一个会改变大部分结果的条件时再询问。

候选可以来自当前附件、本次对话已经读过的完整材料，或用户明确指定的既有来源。已有全局扫描且来源版本没有变化时可以复用；候选原文、时间、章节和页码仍回到原始材料核对，聊天转述、知识笔记和先前结论只帮助定位。

本流程默认读取材料、筛选与排序候选、补充最少必要语境、说明普通受众价值、记录来源和现有素材。短内容成文、媒体制作、文章起草、运营排期、上传和发布分别由对应请求触发。

## 三、建立完整候选

候选保留使它成立的最小完整单元，包括必要的理由、条件或转折。

### 视频、音频与字幕

1. 使用真实时间信息确定开始和结束，至少包含理解核心判断所需的提问、例子、理由或收束。
2. 开头依赖前文但一句语境可以补足时保留；需要长篇专业背景时降低优先级。
3. 字幕没有真实时间戳时使用章节、分集标题或片段编号。只拿到转写稿时明确候选来自文本定位，实际剪切边界需要回到原媒体核对。
4. 用户点名原始版本或具体平台时，交付对应媒体入口；字幕、讲义和转载页继续作为分析来源。

### 书籍、文章与其它文字材料

1. 使用真实章节、页码、小节或段落位置；缺失时写明当前只能定位到哪里。
2. 精彩段落优先概括完整意思。已经读取准确原文且短引文本身承担选择价值时再逐字引用。
3. 一句话依赖前后论证时同时说明必要语境，或扩大到能够独立成立的段落。
4. 长材料先建立目录和主题地图，再跨章节比较候选。

## 四、判断是否值得分享

对候选依次检查：

1. **独立可懂**：普通受众依靠候选本身和最多一句简短前置语境，就能理解谁在说什么、为什么重要。
2. **实际价值**：带来新的理解、可用判断、现实启发、情绪共鸣或值得继续讨论的问题。
3. **停留理由**：候选本身具有故事、反差、具体例子、清晰机制、强表达或可演示变化。
4. **语境完整**：保留关键条件、转折和结论，假设、事实与适用范围各自清楚。
5. **来源可靠**：原文和位置能够核对。高影响、实时或容易误导的主张未核实时标为分享前需要核查。
6. **使用可行**：已有素材、引语长度和许可状态足以支持后续表达；转载或公开使用在获得相应授权后进行。

强候选通常同时满足独立可懂、实际价值和语境完整；吸引力用于排序。相近候选保留表达最完整或最有代表性的一项，并保持候选主题和表达优势的适度差异。

## 五、整理内容真源交接包

每个进入后续制作的候选必须提供：

- **核心主张**：普通受众最终应当理解的一句话。
- **普通受众价值**：它解决什么理解、判断或现实问题。
- **必要语境**：离开原材料仍能正确理解所需的最少背景。
- **支撑材料**：理由、事实、数字、例子、演示或原声中哪些部分使主张成立。
- **来源位置**：真实时间范围、章节、页码、小节、链接或片段编号。
- **事实与版权状态**：已经核实、需要核查、可以概括、可以短引，或素材使用仍待确认。
- **可用素材**：已有原视频、音频、录屏、图片、图表、字幕、板书或其它制作资源。

每个准备进入成文的候选另外提供作者输入：

- **作者判断**：用户确认的判断、取舍依据、评价方向和主张边界，以及它来自哪份用户指令、确认稿或已发布内容。
- **作者声音**：当前用户原话、有效正文、确认稿、已发布内容或维护中的声音档案路径，以及一至五项本轮可观察的词汇、句长、节奏、重复、判断力度、幽默或完成度。用户明确保留的称呼、原句和结尾一并交接。

同一来源准备派生多个文字或媒体成品，或者候选属于连续系列时，交接包再增加一组来源关系：

- **来源标识（`source_id`）**：能够稳定回到来源记录的路径、链接或项目内标识。
- **来源版本（`source_version`）**：当前使用的发布日期、修订号、文件哈希或其它可核对版本。
- **内容单元标识（`content_unit_id`）**：该候选在当前来源中的稳定标识，使多个下游项目能够引用同一个内容单元。

普通单次候选沿用基础交接字段。系列来源关系只负责追溯，不预先决定媒体载体、项目目录或成品数量。

交接包说明内容怎样成立和现有素材是什么。字段名用于交接和追溯；下游成文读取字段中的含义，按目标读者重新组织正文，不把交接标签写进帖子或文章。用户随后要求通用单条短内容时读取 `references/content-writing.md`，由当前 Agent 直接成文；要求指定平台、多条差异化内容、当前发布规则或资源 CTA 时，读取 `references/social-content-distribution.md`，把交接包转换为唯一 `distribution_plan` 并通过结构校验，再由当前 Agent 成文；要求媒体方案或制作时将交接包交给 `visual-multimedia` 选择载体；要求文章或 Newsletter 时进入 `references/article-from-practice.md`。

## 六、默认交付

第一段直接说明这份材料是否存在足够强的分享候选，以及最值得优先处理的是哪类主题。随后按推荐顺序列出候选，每项至少包含：

- 位置。
- 完整意思。
- 普通受众为什么值得看。
- 候选本身的停留理由。
- 必要语境。
- 支撑材料。
- 来源、事实与版权状态。
- 可用素材。

确实影响选择时补充“分享前需要核查”“实际素材需回到原媒体确认”或“现有素材不足”。媒体形式、主文案、分镜、制作方案、平台版本和发布建议由后续请求触发。

## 七、停止条件

- 已完成足以跨整份材料比较候选的全局扫描。
- 强候选完成去重、排序和真实定位。
- 每个候选的完整意思、普通受众价值、停留理由和必要语境已经清楚。
- 每个推荐候选都有完整内容真源交接包。
- 作者判断、声音来源、当前声音信号和明确保留的表达选择已经记录；系列派生任务能够回到确定的来源版本和内容单元。
- 核查状态、定位状态和素材权利状态已经标明。

达到后立即交付。通用短内容成文、平台内容组合、具体媒体选择、媒体文案、样稿、音视频处理、文章、排期和发布分别由后续请求触发。
