# 从研究与实践到文章

<!-- 旧写作合同、Harness 与默认知识库落盘流程，已退出活动 Skill。 -->

用于把研究、实践或真实经历变成内容路线、文章、修改意见或作者声音分析，结构随当前材料和写作目标确定。

## 一、先确定写作动作与授权范围

先区分用户这次要什么：

- **声音分析**：比较叙事、结构、视角、节奏、用词、幽默和信息密度。
- **内容路线或大纲**：选择材料并安排推进顺序，交付可继续写作的结构。
- **起草**：按约定写局部或全文。
- **修改**：处理用户指定的结构、节奏、声音、内容或表达问题。
- **内容审计**：判断核心主张、经历、逻辑、结构和读者行动是否成立，默认报告实质问题。
- **研究或事实核查**：查资料、评估来源、验证主张或整理引用。

这些动作分别按当前授权进入，用户同时要求多项时组合执行。内容审计的容错、分级和停止条件统一读取 `content-audit.md`。

每次跟进先把用户当前动词识别为动作变化或对现有动作的补充，再合并进活动写作合同。“观察改稿差异”比较文本；“继续改这篇”沿用已有草稿、材料和所有未被撤回的写作要求，只执行当前点名的修改。用户明确更换对象、立场、交付形态或授权时，再更新对应部分。

用户输入 `文章模式：<主题>`，或明确说“写文章”并要求“大纲和具体参考内容”时，默认交付一个 Markdown 文件，其中包含可执行的写作大纲和能继续修改的参考正文。用户进一步要求“完整草稿”或“可直接发布”时，才把参考正文提升为完整终稿。

用户选择把某个分享候选发展为长文或 Newsletter，并明确要求制作时，把它视为本流程中的内容路线、起草或修改任务，复用候选的原始位置、完整语境和受众价值，并按用户指定的平台形态决定文章长度。

复杂写作任务开始前，用 Harness 的任务契约记录 `writing.action`、`writing.scope`、`writing.research_requested`、作者样稿是否可用、叙事骨架和经历材料状态。准备内容路线、文章结构、正文或修改稿时，同时读取 `content-writing.md`、本文件和 `content-case-retrieval.md`，按当前写作任务、内容类型、主题和所需结构取得完整文章案例。随后用 `validate-writing` 校验内容真源、当前作者声音、两份模板、同类型完整案例、当前全部要求和带出处的经历节点；通过后进入成文。

当前动作包含文章正文、Newsletter 正文、可直接使用的参考正文或对这些文字的改写时，同时读取 `content-writing.md`。本文件负责确定内容真源、文章承诺、推进线、作者观点取向和声音约束；当前 Agent 直接完成实际成文与后续文字修订。

## 二、按任务选择输入

- 声音分析：读取用户指定的样稿、对照稿和写作声音档案。
- 个人经历型文章：检索当前输入、已有文章项目、最终成果、文章归档索引及索引指向的实际正文，再读取经过作者身份与状态验证的用户经历材料、当前有效用户样稿和写作声音档案。用户要求研究或文章以研究为主时使用主题知识。
- 研究解释型文章：按 `knowledge-base-workflow.md` 找到主题知识文档及相关来源，为已授权的缺口补研究。
- 修改：先读原稿和用户点名的问题；研究或核查由用户要求触发。

长期声音规则的唯一真源是 `System Knowledge/60-Systems/Writing/style-guide/voice.md`。该文件已经吸收外部案例中可迁移的表达机制；具体用户样稿仍单独验证作者身份与状态。样稿分为：

- **当前用户原文**：用户在本轮直接提供或明确指向的本人文字。
- **外部参考原文**：能回到公开账号或原始出版物的已发布文字，只提供事实、结构和可迁移表达机制。
- **用户确认稿**：用户明确认可为自己的当前版本。
- **已发布文章**：能够追溯到用户发布页面或已核验归档原文。
- **用户未确认草稿**：可以继续修改，用户本轮明确指定时用于当前声音判断。
- **Agent 草稿**：作为待修改文本、前后对照或反感样本。

同一文章存在多个版本时，先建立版本关系，再使用用户当前指定或确认程度最高的版本。“最新”指当前有效用户版本。优先级是：

```text
用户当前明确指令 → 当前有效用户样稿 → 写作声音档案 → 通用写作原则
```

声音分析或成文前，`author_voice.sources` 为每项作者材料记录 `reference`、`authorship` 和 `verification`。用户本轮原话、确认稿或发布稿分别使用 `current_user_input`、`user_confirmed` 或 `published`；声音档案标记为 `system_profile / maintained_profile`。每次成文至少带入一项用户来源，再用一至五项 `signals` 指出本轮真正要沿用的声音特征。外部参考内容作为完整案例展示结构与表达，不作为用户声音来源。

## 三、从样稿形成可执行的声音约束

写作前从当前有效用户样稿和写作声音档案确定可执行的声音结构：

1. 主要视角是“我”、第二人称还是旁观解释。
2. 文章由真实时间线、问题递进还是研究解释推动。
3. 开头从真实事件、读者问题还是反常结论进入。
4. 段落长短、标题密度以及列表和表格的使用程度。
5. 图片、截图和数据是承载细节、提供证据还是制造节奏。
6. 幽默来自自嘲、反差、夸张还是冷静判断。
7. 结尾是直接结束、说出当前判断还是引出下一次尝试。
8. 作者怎样自然完成强调、转折、判断和收束，哪些当前句子没有沿用这些真实选择。

声音约束要能决定文章怎样组织，包括视角、推进、段落、素材、幽默和结尾。

作者在当前主题上已经确认的判断、优先讲什么、采用什么评价依据和主张边界进入 `shareable_point`、`writing_job.core_information` 与 `content_truth`。同一批已验证用户材料同时形成 `author_voice`，决定怎样组织和表达。用户更新判断时重建核心信息；只调整措辞、节奏或版式时更新声音信号和当前要求。

### 参考内容按授权层使用

用户提供一篇参考内容时，先区分他要借的是信息结构、作者声音、平台包装还是其中的事实和观点。用户没有点名时，分析完成当前写作动作需要的层。

需要借鉴结构时，拆解读者问题、开头承诺、推进顺序、材料进入位置、转折、结论和 CTA 各自完成什么，再用当前材料重建。需要延续声音时，以用户当前指令、当前有效用户样稿和写作声音档案为真源。

参考内容缺少用户的核心判断、真实经历、关键证据或希望读者采取的行动，且这些信息会改变大部分正文时，只询问一个最关键缺口。第一人称经历或立场来自经过验证的作者材料。默认交付一个最符合当前材料的结构或草稿，多个版本由用户要求触发。

平台表现用于证明某个入口、表达或包装曾经获得注意；结构适用性和观点质量使用当前读者、材料与独立证据判断。主动寻找高表现参考内容属于外部研究，由用户授权触发。

用户同时给出 Agent 原稿和自己的改稿时，按下列维度比较实际差异：读者身份是否更具体，现实冲突是否更早出现，作者是否亲自作出选择，判断是否更明确，新信息出现得是否更快，小标题是功能名还是记忆点，产品、数字、截图和加粗是否承担了真实信息。只把用户明确改动且会影响下次组织或表达的部分提炼为规则。

## 四、个人文章先还原真实经历主线

个人经历型文章动笔前，按下面顺序查找已有经历材料：

1. 当前消息、附件和用户明确指向的页面。
2. 当前文章项目和同主题旧稿，用于定位版本关系和作者状态。
3. `40-Outputs/Writing` 中带有用户确认或发布来源的成果。
4. `20-Sources/Articles` 的作者文章索引，以及索引指向的实际 Markdown 原文。
5. 相关主题知识文档中已经标明来源的作者实践。

归档索引负责导航；提取经历节点和作者措辞前读取实际正文。搜索时围绕主题对象、真实问题、具体动作、阻力、结果和作者判断使用多个检索词。Harness 的 `existing_materials` 记录检索状态，实际读取位置直接进入 `author_voice.sources` 或 `experience_events[].source`。检索完成后再判断经历缺口。

完成检索后，从经过验证的用户材料中整理：

```text
真实触发 → 已有尝试 → 具体阻力或失败 → 新选择 → 当前结果 → 作者判断
```

这条主线是正文生产者。已有文章能提供足够节点时，直接说明将使用哪段经历。检索后仍缺少会改变文章主体的节点时，只询问那个关键缺口；第一人称经历、动机、感受和结果来自用户当前输入、确认稿或已发布文章。材料仍然不足时，缩小文章范围，并继续使用当前用户文字所能支持的声音强度。

个人感可以来自已经发生的故事，也可以来自用户明确认可的选择型第一人称，例如“我会保留一部分流动资金”“我更愿意选这个方案”。选择型表达保持在意向与取舍层面。

## 五、确定文章承诺和推进线

写作前明确：这篇文章实际讲哪件事，读完后读者会知道什么，当前材料能支撑作者说到哪里。

- **个人经历型**：通常按实际发生顺序推进。每个问题促成下一步选择，知识只回答过程中自然出现的问题。
- **研究解释型**：围绕一个持续推进的问题，使用来源与转折、问题递进、常识冲突或案例发现等主线。
- **混合型**：真实经历是骨架，研究材料只补经历中的解释缺口。

文章结构由真实经历主线或研究问题决定，内容围绕读者实际会遇到的问题推进。

回应或反驳他人文章时，把参考文章作为待检验的主张。批判指出具体承诺的失效位置、遗漏条件及其对读者的影响。文章承诺提供解决方法时，使用用户已经确认的实践、选择或反馈给出替代机制：读者从什么现实问题开始，做哪个足够小的动作，依靠什么外部条件或反馈继续修正，以及怎样判断变化真的发生。材料只支持批判时，缩小文章承诺或询问关键缺口。

文章被用户指定为后续媒体制作的内容真源时，先让文章自身完整兑现承诺，再把核心主张、必要语境、支撑材料、来源边界和可用素材交给 `visual-multimedia`。同时交接当前作者判断、`author_voice.sources`、`signals` 与明确保留的表达选择；一篇文章将派生多个媒体成品时，再交接来源标识、来源版本和内容单元标识。下游媒体根据具体载体重新表达；新的事实、实践结果或作者判断进入文章真源，平台反馈用于调整入口、表达和受众匹配。

文章属于已有系列时，把上一篇已经讲清的内容当作前提，用足以连接新问题的最小回顾开场。先写出本篇新增的困难、产品、选择或结论，再决定旧知识需要回顾多少。

## 六、内容路线匹配交付粒度

用户要内容路线时，每个部分说明：

- 此时发生了什么或读者正在问什么。
- 要使用哪段真实经历、事实、机制、截图、数据或案例。
- 它为什么导致下一部分。
- 用户已授权研究时，此处是否真的需要证据。
- 哪些细节由图片、表格或清单承担，正文负责补充什么。

内容路线具体到能够继续写；用户要全文时直接完成全文。

## 七、研究与事实按授权范围进入

用户明确要求研究、引用或事实核查时：

- 核查会改变文章核心判断、读者行动或明确承诺的内容。
- 来源和数据放在读者需要它的位置。
- 口语、夸张和个人判断在保持事实含义时保留。
- 术语差异、例外和说明按它们对正文结论的实际影响选择。

用户当前授权是声音或文本分析时，把样稿中的说法作为文本材料处理；事实核查由相应授权触发。

研究写作按读者价值组织公开信息：

1. 先给出当前材料能支持的明确答案、方案或判断。
2. 判断一项条件是否会改变读者的结论、资产选择、操作步骤或预期结果。
3. 改变主体方案的信息直接进入方案；改变单个操作的信息放在对应步骤旁边；其它已核实内容继续留在内容真源。
4. 作者的口语、夸张和鲜明判断继续承担声音作用；会改变读者行动依据的事实在原位置保持准确。
5. 证据支撑文章的正面主张。

用户明确要求风险、合规、资格、适用性或事实审计，或这些内容本身就是文章的核心问题时，让它们承担相应独立章节。

## 八、可执行策略文章要核对真实操作链

文章要让读者照着完成配置、实验、工作流或决策时，动笔前把完整读者链路走一遍：

```text
起始资产或输入
→ 交易对、兑换或准备
→ 购买、申购或执行
→ 持有、锁定和观察
→ 赎回、再平衡或下一次使用
→ 读者最终看到的结果
```

每一段保留会影响下一步的币种、账户、交易对、费用、锁定期、赎回时间、额度、时点和观察值。文章中的资金、产品状态和再平衡时点保持前后一致，并走到读者最终可用结果。

## 九、起草和修改

修改已有文本前，先判断问题发生在哪一层：任务和主张、结构与素材顺序、真实材料、作者声音、句子与版面、事实边界，还是交付形态。选择能解决根因的最低充分改动：局部清理、段落重排、结构重组或重写。

用户提供前后版本时，比较他删掉、补上、降级和重排的内容，并判断这些变化修正了什么。用户明确修改的地方是当前任务的高信号边界；长期声音规则由重复证据或明确确认形成。当前确认版本是继续修改的真源；除非用户明确要求找回，后续不得恢复用户已经删除的总结、观点、例子和结构。

用户连续指出“太像 AI、太模板、结构不对、不是我要的”等同类问题时，先说明具体问题位置、根因、当前有效版本和建议修改范围，再按用户已有授权继续；缺失信息会改变主体时只询问这个缺口。

- 先依照真实经历主线或研究问题写骨架，再应用段落、标题、图片和幽默约束。
- 个人文章以第一人称实际行动为中心。
- 截图或表格已经包含详细方案时，正文说明选择、体验和用途。
- 保留作者的短句、停顿、明确判断和自然毛边。
- 只有当前用户原话可用时，从其中提取最可靠的词汇、句长和判断力度；高保真目标需要更多证据时再询问一份代表性样稿。

进入实际成文前，把文章承诺、推进线、真实经历或研究材料、来源边界、目标读者和交付格式合并为 `content-writing.md` 规定的写作输入。`writing_templates` 同时包含基础成文模板和本文件，`writing_examples` 包含同内容类型完整文章，`author_voice` 包含当前用户来源、声音信号和明确保留的表达选择。首次起草使用当前材料直接成文；修改已有正文时，以当前有效正文和本轮全部要求为边界，并继续让模板与完整案例进入同一个生产输入。

草稿完成后，再按声音约束比较叙事驱动力、主要视角、开头、段落与标题密度、图片作用、幽默机制和结尾。发现结构性偏差时，当前 Agent 依据仍然有效的写作输入直接修订。

## 十、保存文章过程与结果

需要持久化时，目录选择、唯一真源、知识合并和链接规则读取 `knowledge-base-workflow.md`。文章项目保存本次范围、真实经历材料、声音约束、知识链接和未完成问题；最终成果保存确认版本。

文章状态和保存目录必须一致：

| 内容状态 | 唯一活动位置 | `source` |
| --- | --- | --- |
| Agent 生成的大纲、参考正文或草稿 | `30-Projects/Content` 的文章项目 | `agent-draft` |
| 用户尚未确认的本人草稿 | `30-Projects/Content` 的文章项目 | `user-draft` |
| 用户明确确认的最终文章 | `40-Outputs/Writing/Articles` | `user-confirmed` |
| 已核验发布页面的作者文章 | `40-Outputs/Writing/Articles` | `published-article` |

`文章模式` 的默认交付是一个 Markdown 文件。已有文章项目或草稿时沿用项目路径；没有现成路径时，根据 `System Knowledge/Home.md` 在 `30-Projects/Content` 建立唯一文章项目，保存本次大纲和参考正文。写入 `40-Outputs/Writing` 前，`validate-write` 的操作声明 `writing_artifact.state=final`，`source` 使用 `user-confirmed` 或 `published-article`。

同一文章出现用户确认稿或已发布版本时，先确认它与现有草稿是同一作品，再让该版本成为唯一活动成果：更新或迁移正文到 `40-Outputs`，同步修改项目状态、链接和任何把它标为草稿的消费者。历史版本按用户授权移入 `90-Archive`。最终回答返回结果摘要和可点击文件链接。

确认后的长期声音变化更新写作声音档案，研究形成的稳定认识更新主题知识文档，每类规则保持一个真源。

## 十一、交付前检查

- 当前写作动作、研究范围和交付粒度与本轮授权一致。
- 本轮反馈已经与上一轮活动要求合并；正文仍满足所有未被撤回的对象、角度、核心信息、受众、声音、平台和交付要求。
- 询问个人经历缺口前，已经检索当前输入、项目、最终成果、文章归档索引及其实际正文。
- 第一人称经历、动机、感受和结果来自用户当前输入、确认稿或已发布文章；外部案例没有被写成用户亲历。
- 样稿的作者身份与状态已经记录；结构来自当前有效用户样稿和本次叙事骨架。
- 段落、标题、图片、表格、幽默和结尾符合声音约束。
- 个人文章由经历推动，研究文章由问题和因果推动；正文先交付正面主张和可执行选择。
- 策略文章已经走通真实操作链，内容路线、正文和目录各自匹配用户要求。
- 正文及文字修订由当前 Agent 直接完成，并按文章承诺、推进线、内容真源和声音约束验收。
- 当前确认版本保持唯一真源，用户明确删除的内容按本节硬边界处理。
- 文章项目、最终成果、内容审计和媒体交接各自达到对应停止条件。
