# 学习过程与方法选择

用于围绕具体材料、主题或真实任务判断“现在卡在哪里、下一步用什么方法”。方法直接服务当前学习对象和用途，不把一次普通求助扩成完整学习工程。

## 普通请求先走这条路径

1. 先问清知识最后要帮助用户完成什么。
2. 根据当前表现判断用户已经知道多少，不做长期能力标签。
3. 找到最先阻碍结果的一个卡点。
4. 选择一个最合适的下一步，并用真实结果取得反馈。
5. 卡点解除或产物已经形成时停止；没有效果时再换方法。

后面的结构、记忆、检索练习、迁移、休息和其它方法都是按当前卡点选用的工具，不需要依次执行。

## 什么时候使用

满足以下任一情况时使用：

- 用户面对具体材料或任务，不知道怎样开始或继续。
- 用户能读懂文字，却无法建立结构、判断真假或实际使用。
- 同一种方法反复无效，需要定位问题出在哪个环节。
- 解释或实践方式必须根据材料性质和用户已有知识调整。

用户只要求日程或打卡表时进入相应计划流程；出现具体学习对象、用途或卡点时才进入本流程。

## 先看四件事

### 1. 用户最后要完成什么

先确定知识要帮助用户看懂材料、形成判断、通过考试、执行程序、制作工具、解决问题还是准备文章。方法是否有效，由这个结果判断。

把“学会”落实成可以观察的表现：

| 用户要达到的表现 | 怎样确认 |
| --- | --- |
| 识别 | 能在相似干扰项中辨认 |
| 回忆 | 经过目标时间后仍能在适当提示下调用 |
| 理解和解释 | 能说明关系、条件、推导和反例 |
| 执行程序 | 能在真实或模拟环境完成步骤和产物 |
| 选择策略 | 能在混合案例中选对方法并说明线索 |
| 迁移 | 能在没有练过的新案例中使用 |

同一任务可以需要多项表现，但当前只先处理最影响最终结果的一项。

### 2. 用户已经知道多少

- **陌生**：术语和关系都要建立，先给主干和完整例子。
- **部分熟悉**：已有零散知识，重点补关系、差异和缺口。
- **能够使用**：减少基础解释，直接进入原始资料、争议、变体和迁移。

只根据当前任务中看得见的表现调整帮助，不给用户固定阶段或长期标签。

### 3. 当前材料是什么性质

这项判断只帮助选方法，同一材料可以同时包含多种内容：

- 名称、日期、规则、符号等需要准确调用的事实；
- 带有立场、证据和适用条件的主张；
- 指导行动的步骤、判断点和反馈；
- 可以观察、比较或放进现实场景的具体材料；
- 机制、模型、公式、因果和概念关系。

只判断当前真正影响方法选择的部分，不为了分类把一份材料拆碎。

### 4. 现在卡在哪里

| 卡点 | 常见表现 | 当前要解决什么 |
| --- | --- | --- |
| 材料不足 | 来源缺失、噪音太多或材料不合适 | 得到足够且相关的输入 |
| 字面不懂 | 术语、句子、符号或上下文不清 | 准确理解材料在说什么 |
| 关系没建立 | 知识孤立，无法解释原因或差异 | 形成最小关系结构 |
| 判断失真 | 来源冲突、类比失真或结论过度 | 找到错误位置和适用边界 |
| 不会使用 | 会复述但不会判断、执行或制作 | 产生真实用途需要的结果 |
| 没有反馈 | 不知道结果是否可靠、能否迁移 | 用结果决定下一轮改进 |
| 难以行动 | 迟迟不能开始或很快中断 | 找到具体阻力并形成可执行起点 |

先处理最影响后续结果的一项。解决后再判断是否需要继续。

## 建立足够使用的理解

学习过程可以往返：材料不够就补材料，术语没懂就回到上下文，应用失败就检查步骤、机制、假设或环境。低风险的早期尝试能够暴露缺口时，可以先尝试，再带着问题学习。

解释陌生或复杂内容时：

1. 找出当前问题不可缺少的少量要素。
2. 说明它们之间最关键的关系。
3. 给一个能展示这种关系怎样运行的具体例子。
4. 用户跟上主线后，再加入证据、变体、反例和边界。

需要把零散内容组织起来时，先明确当前要表达哪种关系，再选择形式：层级用树，多个对象相互连接用图，同一维度比较用表格，事件或状态变化用时间线或流程。关系还没有证据时先标为待确认；来源冲突时保留各自条件，不用一种漂亮结构掩盖分歧。

## 根据卡点选择方法

比较或采用一种方法前，先看五件事：它处理什么、解决哪个卡点、需要什么前提、产生什么可观察结果，以及什么时候会失效或增加负担。

| 当前内容 | 优先方法 | 怎样看结果 |
| --- | --- | --- |
| 事实 | 按自然关系组织；低频细节保留可查询记录；确实需要随时调用时做检索练习 | 能在需要时准确找到或调用 |
| 主张 | 追溯来源，分开事实、推断和价值前提，寻找反方与适用条件 | 能说明证据、信任范围和改变判断的条件 |
| 程序 | 新手先看完整示例和关键判断点，再做有反馈的尝试；熟悉后减少提示并增加变体 | 能完成产物并定位步骤错误 |
| 具体材料 | 观察和比较多个实例，改变条件，找出真正决定结果的特征 | 能在新案例中识别相关特征 |
| 抽象关系 | 使用最小模型、因果链、具体实例、对比和迁移 | 能用关系解释新情境，而不只复述定义 |

方法很多时，不要同时叠加一整套新习惯。先记录当前做法和结果，选择一个主要改动或一组不能拆开的互补动作，说明在什么情况下使用、怎样看结果、观察多久以及什么时候停止。使用足够次数后，再决定保留、调整还是替换。

## 决定哪些要掌握，哪些可以随时查询

优先掌握需要立即反应、高频使用、构成其它理解基础、必须形成流畅动作，或查询失败会造成明显损失的内容。

精确但低频的数字和命令、经常变化的规则和版本、需要保留原文与来源的证据，以及已有稳定概念后能够快速找到的细节，优先保存在外部资料中。

通常内部保留概念、检索线索和判断标准，外部保存精确细节、来源和版本。结果看的是用户能否在真实时间内找到、判断并正确使用，而不是背下多少内容。

## 根据用户当前状态调整帮助

- 用户陌生时，先给主线、必要术语和完整示例，一次只增加少量关键关系；Agent 可以演示第一次检索、分析、计算或应用。
- 用户已有部分经验时，从现有理解出发补联系和边界，用比较、反例和变体代替重复基础定义。
- 用户已经能够使用时，减少解释，提供原始资料、冲突证据和复杂案例，重点检查迁移、边界和判断质量。

帮助程度随当前表现变化，不按固定阶段长期绑定用户。

## 用反馈找到下一步

概念、机制、程序或“读懂但不会用”的内容，可以让用户暂时离开材料，用口述、书写、图示、推导或操作重新解释。把“卡住了”进一步定位为术语、关系、条件、例证、调用或应用缺口，再回到材料定向补足，并用新案例、反例或实际产物重新检查。

反馈使用最低但充分的压力：可以核对事实、重做推导、用新案例检查机制、运行模拟或代码、比较方案与约束，或者直接看实际产物。只有内容将来需要独立调用，或者当前必须暴露理解缺口时，才优先安排检索练习。

检索练习可以开卷，也可以使用新案例、模拟和实际操作。用户选择闭卷时再使用闭卷。每次尝试后及时给可靠答案和纠正；需要保持时隔一段时间再调用，并逐步改变线索或使用情境。

## 学不下去时先判断是不是行动问题

- **迟迟不能开始**：检查任务是否含糊、准备是否繁琐、是否害怕失败或容易被环境打断；明确第一个具体动作，减少准备并降低第一次尝试的代价。
- **开始后难以持续**：检查内容与现实用途的关系、难度、反馈速度、单次长度和切换诱因；增加个人相关性、可见反馈和适度变化。
- **一直在做却没有结果**：回到材料性质、方法和反馈，重新选择有效动作。

兴趣、用途、反馈、环境和任务设计共同影响投入。本节只处理当前学习任务，不把一次行动困难解释成固定人格问题。

## 按目标安排练习、迁移与休息

新手建立基本概念或步骤时，先用完整示例、少量集中练习和及时反馈。需要延迟后仍能调用时再安排间隔练习；需要判断该用哪种策略时，掌握基本方法后再穿插相近问题；需要适应变化时逐步增加案例、参数和环境差异。

检查迁移时，同时准备表面不同但深层关系相同的正例，以及表面相似但机制不同的反例和边界案例。先提出候选规律，再用没有参与形成规律的新案例检查。失败时区分是没有想起、没有辨别、范围过宽、遗漏变量还是只记住偶然细节。

持续注意明显下降时，可以短暂休息后返回。解释、方案、证明或创意已经经过一轮专注处理，却反复卡在同一路径时，可以暂时进行低负荷活动，再回来检验新想法。缺少事实、术语未懂、基本步骤不会或没有反馈时，优先补输入和指导，不能用休息代替学习。

## 完成标准

满足以下条件即可停止当前层次：

- 当前卡点已经解除，或已经明确缺少什么外部条件。
- 用户需要的产物已经形成，知识确实参与了结果。
- 会改变结果的错误、假设和边界已经说明。
- 当前方法已经足以支持理解或行动，继续增加方法的收益低于负担。

如果方法没有产生预期结果，先重新判断卡点和材料性质，再选择替换、调整或补充方法。
