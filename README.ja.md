# 100x Learning

素材、初めて触れるテーマ、現実の問題を Agent に渡すと、今すぐ理解・判断・活用・共有できる成果が返ってきます。継続して取り組む場合は、実際のフィードバックをもとに次の学習、テーマ、コンテンツ改善も管理できます。

`100x-learning` は、オープンな [Agent Skills 仕様](https://agentskills.io/specification)に準拠した学習・コンテンツ Skill です。字幕、記事、リンク、テーマ、主張、プロジェクト、既存の下書き、公開後の反応を読み取り、ユーザーが本当に求める結果に合わせて、素材理解、調査、概念説明、実践、コンテンツレビュー、執筆、継続的なテーマ選定、知識の蓄積を選びます。独立したアプリではなく、特定の Agent ホストだけに依存しません。

冒頭の図は、この Skill の安定した入力と成果の関係を説明するものです。性能や「100倍」の効果を示すものではありません。

## 依頼できること

### 学習と調査

- **素材を理解する**：`このインタビューの流れを説明し、見返す価値が高い箇所も示してください。` → 内容の構造、重要な関係、要点、実際の位置。
- **学び方を選ぶ**：`X を学びたいのですが Y で詰まっています。どう進めればよいですか。` → 現在の目標とつまずきに合った学習経路と練習方法。
- **テーマを調査・検証する**：`X を調査し、私の目的には A と B のどちらが合うか比較してください。` → 問いに対応する情報源、判断、まだ分からない点。
- **概念を説明・応用する**：`実際の場面で X を説明し、それを使って Y を分析してください。` → 必要十分な説明、仕組み、例、実行可能な判断。

### 継続学習とコンテンツ

- **一つのテーマを継続して学ぶ**：`X を継続して学びます。今回は最も役立つ一課を終え、私の反応から次を決めてください。` → 今回使える学習成果と、実際のフィードバックに基づく次の一歩。
- **長期的なコンテンツ方向を保つ**：`私の目標と既存コンテンツから長期方針を作り、今週取り組むテーマを選んでください。` → コンテンツ方針、継続テーマの状態、根拠となる知識へのリンク。点数で数合わせはしません。
- **公開済みコンテンツを振り返る**：`最終稿、直近7日間の数値、コメントを使ってこの記事を振り返ってください。` → 観察事実、仮説、別の説明、次に試すことを分けたレビュー。

### レビュー、執筆、知識ライブラリ

- **既存原稿だけをレビューする**：`事実、構成、AIらしい表現だけを確認し、書き直さないでください。` → 問題、影響、修正の方向。許可がなければ編集前で停止。
- **公開できる文章を書く**：`この素材を一般読者向けの中国語 Thread にしてください。` → そのまま使える短文、Thread、GitHub プロジェクト紹介、記事。
- **公開期のコンテンツを設計する**：`このプロジェクトの公開期コンテンツを設計し、まず案を出してください。` → 通常のコンテンツ案。特典、期限、行動リンクは本文に必要な場合だけ確認。
- **個人知識ライブラリを使う**：`確認済みの結論を個人知識ライブラリに保存してください。` → 一意のライブラリルートを特定し、同じテーマの正本を更新。明示依頼がある場合だけ書き込み。

成果ごとに停止位置が違います。候補だけを求めた依頼を勝手に投稿文へ進めず、レビューだけの依頼で原稿を書き換えません。新しい告知依頼は、まず確認可能な案を返します。ファイル保存、メディア制作、公開もそれぞれ別の操作です。

## クイックスタート

互換ツールが読み取る Skills ディレクトリに、リポジトリ全体を配置します。プロジェクト単位の `.agents/skills/` に対応するツールでは、次のように導入できます。

```bash
git clone https://github.com/CheshireMew/100x-learning.git .agents/skills/100x-learning
```

ツールがユーザー単位または別の場所を使う場合は、最後の保存先をその Skills ディレクトリに置き換えてください。Agent Skills はオープンな形式ですが、検出先と明示的な呼び出し構文はホストごとに異なります。[公式クイックスタート](https://agentskills.io/skill-creation/quickstart)にはプロジェクト単位の例があります。

導入後は、欲しい成果をそのまま伝えます。

```text
この素材を読んでください。まず内容、主な流れ、重要な関係を忠実に説明し、
そのうえで、さらに掘り下げる価値が高い箇所を教えてください。
```

Skill 名の明示呼び出しに対応するホストでは `$100x-learning` も使えます。最初に得られるべき成果は、一般的な勉強法や内部処理の説明ではなく、素材そのものを明快に理解できる説明です。

## 一回の依頼から次のラウンドへ

単発の依頼に複雑な仕組みは要りません。素材が十分なら、説明、調査、判断、執筆を完了して停止します。継続学習、長期的なコンテンツ方向、継続テーマ管理、成果の保存を明示した場合だけ、個人知識ライブラリにタスクをまたぐ状態を残します。

継続作業では、まず今回の実際の入力と成果物を固定し、数値、コメント、実際の利用、またはユーザーの直接フィードバックを読み、次の一課、テーマ、実験を決めます。一度の公開結果は検証待ちの仮説であり、長期戦略、個人の文体、知識の結論を自動で書き換えません。

```text
$100x-learning を使って、このシリーズの継続テーマを管理してください。
確認済みのコンテンツ方針と既存テーマを読み、今週の次の候補を選んでください。
数合わせの採点はせず、一時的な依頼を長期戦略に変えないでください。
```

## タスクの処理方法

`SKILL.md` が唯一の入口です。ユーザーが欲しい最終結果で経路を選び、`references/` から対応する方法だけを読みます。素材理解、調査、執筆、継続テーマ選定、公開後レビューは別の流れです。調査は事実を明らかにし、執筆は選ばれた素材から自然な完成稿を作り、レビューは実際の成果物と反応から次の検証可能な改善を決めます。

執筆では、完成した参考事例、独立した書き出し、個人の文体も別々に管理します。事例と書き出しは保存先、スクリプト、型、索引が異なりますが、文章を作る際には両方を参考にできます。告知、募集、予告、公開期の文章も通常の執筆フローを使い、特典、期限、行動リンク、開示事項は実際の本文に必要なときだけ追加します。

すべてを執筆フローに通すことはありません。素材理解は説明で止まり、調査は情報源と不明点を残し、レビューは原稿を変更しません。一度きりのテーマ選定を継続プロジェクトにも変えません。知識ライブラリの初期化、ファイル保存、メディア制作、公開は、いずれも明示的な依頼が必要です。

## 個人知識ライブラリと公開リポジトリ

個人知識ライブラリは Skill ディレクトリの外に置かれ、公開リポジトリには含まれません。新しいライブラリを初期化するか、現在のディレクトリ契約を満たす既存の Markdown ライブラリを接続できます。

```text
$100x-learning を使って D:\Knowledge\100x-learning に個人知識ライブラリを作成してください。
$100x-learning を使って E:\Knowledge\Existing Library の既存ライブラリを接続してください。
```

内部で使う保守コマンドは次のとおりです。

```powershell
python scripts/private_library.py init --root "D:\Knowledge\100x-learning"
python scripts/private_library.py adopt --root "E:\Knowledge\Existing Library"
python scripts/private_library.py show
python scripts/private_library.py validate
```

選択されたルートは `~/.100x-learning/config.json` に記録されます。新規ライブラリは Skill のソースディレクトリ外に置く必要があります。`init` は中身のあるディレクトリを上書きせず、`adopt` は既存知識を移動・複製・書き換えずに 100x Learning の識別情報とローカルのルート参照だけを追加します。設定ファイルが保存するのはライブラリのバージョンとルートパスで、個人の本文ではありません。

接続後は、知識の正本、完成したコンテンツ事例、独立した書き出し、確認済みの文体、公開履歴、長期的なコンテンツ方針、継続テーマの状態を利用できます。ライブラリがなくても、現在の入力だけで素材理解、調査、執筆は動作します。

| 素材の役割 | 個人ライブラリ内の場所 | 処理結果 |
| --- | --- | --- |
| Web ページ、講座、字幕、インタビュー、投稿などの原資料 | `20-Sources` | 出典、役割、必要な文脈を保持。全文は必要かつ保存可能な場合だけ保存 |
| 消化済みの概念、仕組み、結論、適用範囲 | `10-Knowledge` | 同じテーマと別名を先に検索し、一つのテーマにつき一つの正本を更新 |
| 執筆参考として価値のある完成品 | 完成短文または記事事例のディレクトリ | 全文と確認可能な出典を保存し、索引へ追加 |
| ユーザーが明示的に選んだ元の書き出し | `20-Sources/Hook Library/<writing format>` | 連続した原文、直後の内容、出典、最小限の位置情報を別索引へ保存 |
| 確認済みの最終稿または公開済み作品 | `40-Outputs/Writing` | 最終本文を保存し、条件を満たす場合だけ公開履歴や文体検索へ反映 |

長期的なコンテンツ方向と個人の文体は別の正本を使います。継続テーマはシリーズごとの判断状態だけを保存します。公開後レビューは最終本文と実際の反応へリンクし、本文や指標データベースを複製しません。繰り返し得られた証拠、直接的な行動証拠、またはユーザーの確認がある認識だけが長期の正本に入ります。

公開リポジトリを clone しても個人資料は含まれず、特定の人の経験、立場、文体も引き継ぎません。リポジトリが提供するのは、ワークフロー、方法、初期化テンプレート、保守スクリプト、行動テストです。

## リポジトリ構成

```text
100x-learning/
├── SKILL.md                   # 全体ルーティング、行動境界、成果ルール
├── agents/openai.yaml         # OpenAI ホストでの表示と既定プロンプト
├── references/                # 学習、調査、執筆、知識ライブラリの方法
├── scripts/                   # 字幕、個人ライブラリ、事例、書き出し、執筆記憶のツール
├── assets/private-library/    # 個人ライブラリ初期化用の公開テンプレート
├── assets/readme/             # GitHub README の画像
├── tests/                     # ルーティング、能力保持、リソース境界のテスト
└── archive/                   # 廃止済み資料。現在の実行では読み込まない
```

現在の能力は `SKILL.md`、活動中の reference、スクリプト、公開アセット、メタデータ、テストで定義されます。`agents/openai.yaml` は一つのホストに表示を適合させるだけで、汎用 Agent Skill というプロジェクトの性質は変えません。`archive/` の旧経路や旧スクリプトは互換経路として残りません。

## 保守と検証

保守スクリプトは Python 標準ライブラリを使用します。全行動テストを実行するには次を使います。

```bash
python -m unittest discover -s tests -v
```

SRT、VTT、タイムスタンプ付きテキストを、実際の時間境界を残した Markdown に整形できます。

```bash
python scripts/normalize_subtitles.py path/to/input.srt > normalized.md
```

個人知識ライブラリを設定済みの場合は、コンテンツ事例と執筆記憶を再構築・検証できます。

```bash
python scripts/content_case_library.py build-index
python scripts/content_case_library.py validate
python scripts/writing_memory.py build-index
python scripts/writing_memory.py validate
```

テストは正式な生成側から利用側までを確認します。空のディレクトリからライブラリを初期化し、別プロセスで再検出します。実際の UTF-8 素材を正式な事例・書き出しコマンドで各正本に保存し、それぞれの索引を再構築して正式な入口から読みます。利用側で作った偽の索引を、生成結果の代わりにはしません。

## 対象範囲

この Skill は、素材理解、テーマ調査、概念説明、実践設計、コンテンツレビュー、短文、Thread、GitHub プロジェクト紹介、記事、確認済みの公開条件を含む文章を扱います。画像、GIF、動画、音声、Podcast の制作、一般翻訳、広告運用、セールスページ、メール施策、ブランド全体やマーケティング全体の戦略、実際の公開は別の能力です。

ファイルへの書き込み、メディア制作、アップロード、公開は互いに別の操作です。明示的な許可がなければ、成果は現在の応答またはローカル作業領域に留まります。
